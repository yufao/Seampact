## 本版变化

| 问题 | 当前行为 |
| --- | --- |
| 参数经过函数、构造器或对象属性后无法核对 | 在有限、唯一且未被覆盖的原调用链内追踪，核对完整参数、赋值和调用证据；支持原 LiteLLM `api_base` 和 OpenAI 请求字典 |
| 单条映射的证据被忽略 | 独立校验 `mapping.evidence`，省略时才使用依赖总证据；空或越界证据不回退 |
| 模型标识、缓存及附加权重混为一谈 | 分别记录模型、checkpoint、Hub／本地来源和缓存；动态候选保留分支及未知，不猜成固定文件路径 |
| 只构造对象，漏掉原来的权重加载 | 检查可见的构造后初始化；漏加载、设备或模式设置时给出原位置。已有合法初始化或完整 B-CALL 保留原序 |
| 原库可选依赖在当前入口启用后仍被跳过 | 当前入口实际引用时继续核对，提示与绑定检查一致 |
| 完整库中的展示、MOCK、训练评价混进能力目录 | 分析器记录用途及证据，语义仍待核对；修订台可人工勾选保留入口，填写理由、完整重检并安装 |
| 缺口提示抽象、分析结束像是已跑通 | 给分析器具体字段、源码范围和修复动作；界面区分候选缺项、证据不全、规则不支持、模型来源和初始化遗漏 |

人工移除只改变导出的入口，保留原源码和剩余入口必需的内部调用、依赖及共享边界。新模型候选或源码版本需要重新确认选择。

`COMPLETED` 表示分析流程结束，另以 `outcome` 区分仍需修正、等待平台支持／资源条件、静态通过未运行。检查反馈接入模型正常修正回合，不自动增加收费重试。W／H／R、原 owner、生命周期及 RL 规则保持既有范围。

## 验证与剩余缺口

完整本地测试 **183 项通过**，前端语法及内存组件核验通过；包含实际 B-CALL 原序调用、模拟模型按具体反馈修正，以及同名目标、参数覆盖、动态调用、字典改写／逃逸和不可达路径等拒绝反例。此次没有新付费分析、真实模型推理或服务器部署。

六来源在 73 个摘要一致文件上完整复放 26 条资源检查，另 8 条缺完整文件，未计作复放。在补全证据的诊断中，VPC3 服务地址／模型名、REX-RAG 外层 URL 和 RefChecker `api_base` 的相应映射通过。诊断用补证或映射不计作分析器自动发现成功。

仍未通用覆盖 MiniCheck 的 Hub 缓存执行绑定与配置分支、PIGuard main guard 中的动态 checkpoint 初始化、MADL 配置对象／factory 等结构。来源逐项结果及证据唯一维护于[共性缺口与验证第 7 节](分析器共性缺口与验证.md#7-本轮核心支持实现与回查2026-10-31)，后续状态查[当前实现](当前实现.md)。不能由辅助入口 READY 推断目标防护接通。

## 更新与重新分析

按[服务器部署](服务器部署.md)更新平台；该流程会拉取已提交代码并重新构建、启动。更新后核对 `/health` 的 `version` 为 `0.14.8`，重新加载前端页面。工具／worker 按[统一构建说明](镜像构建与依赖复用.md)核对当前核心身份，不沿用失效工件。

保留现有六个来源、资源配置和分析历史。在“Harness 接入”找到原库，点击“分析 Harness”，使用 API 预处理启动完整新分析。无需删除或重新添加来源；“恢复来源”沿用旧结果，“重新核对”只检查旧候选，两者都不能替代本轮完整重分析。最后确认入口用途、选择真实资源，再验证目标初始化、调用和原评价指标。

本版沿用 0.14.0 的按需驻留、混合任务和自动观测，机制说明保留在[0.14.0 记录](0.14_按需驻留与混合调度.md)。历史版本与实验数值保留原日期和分母，不随本次版本号改写。
