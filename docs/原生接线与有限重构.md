# 原生接入到底怎样工作

> 历史专项记录：下文状态和操作按原日期理解；当前实现见[当前实现](当前实现.md)，来源现状见[原生运行考察](../../ccfa-workfiles/experiments/harness-paper-design/native-feasibility.md)。

更新：2026-10-14，0.7.0。有限原生宿主范围为用户确认的 Python 3.11、显式生命周期及无 frame 观察。

## 不只是把接口名称聚合起来

API 给出实际源码位置、原函数／类方法、构造器／工厂前缀、初始化顺序、资源和内部边界。引擎检查这些声明能否对应真实源码及参数值来源，再建立输入／结果端口与调用绑定。执行时使用原 callable、原对象和原返回关系。

生成代码来自有限规则模板：调用外层的门控、SDK 注册前接线、原构造前缀的绑定、调用点代理和循环体提取。原算法仍然执行，模型提交的是源位置和绑定说明。

## Unit、owner 和 controller

| 概念 | 直白含义 |
|---|---|
| Unit | 能力池中一个具备实际参数接口的可调用入口 |
| owner | 持有原模型、会话、工具、状态和初始化结果的对象／运行宿主 |
| controller | 原 Harness 内决定分支、迭代、下一步和结果汇合的控制逻辑 |
| 内部边界 | 原 controller 到达时进入调度的调用发生，不必是对外独立能力 |

一个 Harness 可以产生多个 Unit，内部一个方法还可以有多个门控位置。同一次原请求中已经共用的对象保持真实引用；B-CALL 按原请求的创建发生构造，尚未实现跨入口驻留共享。入口必须能绑定所需初始化和输入，内部步骤在原 controller 到达时才进入调度。

## W、H、R 实际做什么

| 操作 | 实际代码行为 | 原型范围 |
|---|---|---|
| W：包装 | 保存原 callable，在调用外层等待许可，再调用原实现，保持返回／异常路径 | 有真实源码、签名和 owner 的同步／异步 callable |
| H：原生接线 | 在原生工具列表交给 SDK 前安装代理，使实际原流程经过门控 | 引擎能定位并支持的注册锚点；未知 SDK wiring 明确缺失 |
| R-INPLACE：原位调用 | 仅替换原 Call 的 callee 交接，外围原 frame、分支、循环和异常结构保留 | 同单元普通函数／声明的 `self.method`；同步调用或直接 await 已知 async |
| R-EXTRACT：有限提取 | 将指定循环体变成原 owner 上的受控方法，原循环仍按原序逐项调用 | 顶层类的 async 实例方法中顶层 `for`，直线赋值／调用体 |

有限提取不接受逃出区域的 `break`／`continue`／`return`、嵌套控制流或词法作用域、跨轮标量回写、局部变量向后存活、反射等结构。R-INPLACE 可以保留外围控制语句，因为它只改一个原调用点；动态目标、生成器、先创建 awaitable 后等待、装饰／继承分派等未覆盖形式仍明确缺失。

原 callee、实参和解包按原语言顺序求值一次，代理在实参求值后等待许可。原 timeout 的起点、时限和作用域保持；处在其区间内的新增排队计入时限，许可后不重置时钟。引擎核对整单元 AST 的逆向结构，状态稳定、效果、引用存活和新增超时结果另行记录，结构核对不签发完整行为等价结论。

同一方法“整体 W”与“内部 R”是替代粒度，不能重复门控为同一个同时激活方案。父 controller 若等待内部受控调用，不占住内部调用需要的执行槽。

## 与数据、配置和模型有关的情况

B-CALL 支持原顶层同步函数中的直线构造前缀。`binding_program` 回指原 scope、原请求语句、任务参数和实际局部对象；宿主执行冻结前缀，保存原构造器／工厂返回值，再调用原入口。前缀中的检查和效果保留原顺序，不能跳过或按配置 hash 合并两次原构造。

目录中的文本配置和源码可以成为分析证据；模型权重、数据集、图像等二进制保持为资源引用。初始化和函数参数按原 Harness 接口绑定这些实际路径。原目录、Notebook 其他单元和数据不由模型改写为另一套内容。

真实 Model／Context 对象可通过受支持的原构造程序或同一方案前项结果进入后续调用。来源不能确定、构造形式不支持、缺文件／依赖时显示 `MISSING`。业务输入保留为任务参数；固定值需要原默认值、原调用字面值或用户配置依据。

Notebook 接入使用受支持的定义、导入和字面值，不自动执行整本中的顶层样例调用。需要未绑定的非字面值全局对象时，仍然报缺失。

## 怎样进入实际对话

只有可绑定的原生入口加入对话工具目录。API 在对话时按实际参数接口提出方案，上层 RL 选择完整方案；进入原生入口后，原 controller 决定实际哪些内部边界发生，下层 RL 决定这些已使能调用何时获准开始。

同一方案后项使用 `$result` 取得前项原返回值，可传结果本体或内建容器投影。原生对象保持本地引用，不能通过 JSON 或文字重建；前项只在成功出口使能后继。当前机械检查覆盖来源类型、参数与控制结构，业务语义和完整 EXPORT／COMPOSE 证明仍未完成。

当前平台以一个进程／容器承载原生对象。尚未实现合法并行、远程派发及跨入口驻留共享粒度。K8S 部署单位还需围绕 owner 的状态和生命周期建立对应规则；目前不会根据 Unit 数量生成 Pod。
