# 四源自动发现实验

`tools/run_discovery.py` 用真实模型接口启动已有 `AnalysisJobs`，从四份冻结源码请求自动提出拆分候选。输入只有注册源码、入口、同一观察契约和引擎的通用准则；不传入 MMCT／CRAG 探针中手选的边界、答案或已生成补丁。

脚本依次处理 MMCT、CRAG、ABC、DiSP。DeepSeek 模型能力元数据先由已有 Profiles／Transport 读取一次，再供四轮分析共用。保留已配置模型及供应商默认推理设置，按提供方最大输出能力发送；不设置调用次数、轮数、费用或上下文截断上限。API Agent 可以分页读源码、扩展注册根内的源码、读取 AST 事实、核验和修正候选，最后结构化提交。每个源失败后仍处理下一个源；不自动重试或重放付费请求。分页及状态轮询不是上下文或分析预算。

仅当该次分析完成且提交的所有边界均通过有限引擎的构建检查时，脚本构建原候选为 `BUILT_DRAFT`。脚本不筛掉失败边界来制造通过结果，也不手动修改模型答案。构建不运行原 Harness、安装原依赖或签发原序／组合／并行／远程／生产许可。提交完成但不可构建的候选、工具错误或模型／传输失败同样保存。

## 执行入口

在 core 目录设置 `PYTHONPATH=src`，使用：

```text
python -B tools/run_discovery.py --home <私有工作目录> --sources <四源sources.json> --legacy-config <现有DeepSeek配置目录> --output <公开摘要目录> --provider deepseek
```

`--legacy-config` 只由现有 Profiles 读取并迁移当前用户的受保护配置；脚本不解密、读取、打印或拼装 Key。Linux 可以由原 Profiles 使用环境凭据，不传该参数。私有 home 应使用独立目录，避免与正在运行的平台页面共用数据库；Windows 受保护凭据须由拥有它的实际桌面用户运行。

私有 home 与公开 output 必须分别设置，不能相互包含。私有 home 保存数据库、完整模型／工具消息、冻结快照和生成包。公开 output 仅保存结果摘要：当前 `discovery-result.json`，以及 `run-<id>/summary.json` 和每源记录。公开记录包含版本、修订、请求／分析编号、初始及最终源码版本、轮数、用量、能力元数据、候选、独立报告及摘要；不复制完整 messages、配置或凭据。自由文本按常见凭据形式和本地私有路径脱敏；原始候选和报告仍保留在私有数据库中。

新实验在首次元数据／API 请求前记录 `reproducibility`：9 个引擎源文件的 SHA256、实际使用的 `RULES` 文本摘要、runner 文件摘要、Python 版本和 CLI 源注册文件摘要。记录不包含这些文件的绝对路径。运行期间应保持这些程序和注册文件固定；该记录是启动时身份，不能用来补写或冒充先前实验的程序身份。每个 `run-<id>` 独立保存；新工具检查不会改动已有基线结果。

`candidate_sha256` 与 `report_sha256` 是私有原提交的规范 JSON 摘要；`public_record_sha256` 对应公开脱敏记录在添加该摘要字段前的规范 JSON。若脱敏修改了自由文本，公开候选不能直接当作原候选的字节副本。生成包摘要核对私有 home 下的实际 ZIP；公开摘要不自动复制该包。

单次 Ctrl+C 请求停止后续轮次，并等待当前付费请求结果落盘，然后停止后续源。脚本没有付费重试或恢复开关；再次运行表示明确启动新的实验，旧消息保留在数据库。提供方能力元数据不可读取时记录全局失败，不用未知能力设置继续付费分析。

## 验证与结论范围

```text
python -B tools/run_discovery.py --self-check
```

该检查不读取配置、不调用 API：核验四源顺序与同一观察契约、失败源后继续、不可构建候选不构建、73 轮的既有结果可正常收录、包摘要一致，以及公开记录没有完整消息或配置标记。它验证实验驱动器的记录与分流机制，不能代替真实自动发现结果。

真实 API 结果应检查模型实际读取了哪些源码、是否扩展源范围、提交了哪些能力、独立引擎接受／拒绝了什么，以及后续原生核验的覆盖。自动发现成功、静态可构建、原序行为通过、并行通过和部署通过是不同结果。当前工具只执行前两项，其他项均保留未准入状态。
