# 手动启动与演示

更新：2026-10-13。当前版本0.5.0。本文说明如何启动工作台、完成一次任务和用于组会演示；当前业务任务宿主是CRAG，四源分析入口均已接入。

## 1. 先选启动方式

| 场景 | 方式 | 浏览器地址 |
|---|---|---|
| Windows本机看界面、做组会演示 | 项目Python环境直接启动 | `http://127.0.0.1:8880` |
| 共享Linux服务器常驻运行 | Git更新＋一个Docker服务 | SSH转发后 `http://127.0.0.1:8875` |

这两种方式运行同一套平台。当前平台包括来源管理、API分析、包生成、任务宿主、调度账本和页面；启动工作台不会自动启动四个来源的全部业务，也不会启动训练或RL。KIND是此前K8S部署的环境，当前DEMO不依赖它。

## 2. Windows：从Git新建项目环境

在PowerShell中执行；若已在项目目录，跳过clone和cd。已经存在的虚拟环境也不必重复创建。

```powershell
git clone git@github.com:yufao/Seampact.git
Set-Location Seampact
python -B tools/fetch_sources.py
python -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r docs/requirements-sdk-crag.txt
& '.\.venv\Scripts\python.exe' -m pip install -e .
& '.\.venv\Scripts\python.exe' -B -m seampact serve --home var/platform --sources sources.json --port 8880
```

保持终端打开，浏览器访问 http://127.0.0.1:8880 。前台服务用Ctrl+C停止。首次安装只在项目环境里进行；已有环境直接执行最后一行。

来源下载只取固定修订的选定工件，已核对的文件会复用。新环境中没有能力包时，按第4节先做分析与构建。已有真实API产物可以按[任务DEMO](任务DEMO.md)放入私有目录，并在启动命令加`--artifacts artifacts`。

## 3. Linux服务器：Git与Docker

服务器操作由用户在SSH终端执行。下面是首次部署；若已经有`Seampact`或`seampact-demo-runtime`，使用[Docker指南](Docker部署.md)的更新步骤，不重复clone或prepare。

```bash
cd "$HOME"
git clone git@github.com:yufao/Seampact.git
cd Seampact
python3 -I -B tools/fetch_sources.py
python3 -I -B deploy/prepare_workspace.py "$PWD" "$HOME/seampact-demo-runtime" --port 8875
python3 -I -B deploy/write_secret.py "$HOME/seampact-demo-runtime/secrets" deepseek
sudo systemctl start docker
sudo docker compose --env-file "$HOME/seampact-demo-runtime/compose.env" -f deploy/compose.yaml up -d --build control
sudo docker compose --env-file "$HOME/seampact-demo-runtime/compose.env" -f deploy/compose.yaml logs --tail 12 control
```

密钥助手会隐藏输入，密钥不放进Git或命令文本。管理员已允许启动系统Docker；只对本项目执行compose命令。首次镜像构建需要联网下载基础镜像和SDK依赖，不下载模型权重，也不使用GPU。

在SSH客户端建立本地端口转发：**本地127.0.0.1:8875 → 服务器127.0.0.1:8875**。打开日志里的“本次登录”链接。若本地8875已被占用，可以把转发的本地端口设为其他空闲端口，但页面请求的端口需要与启动服务的公开端口设置一致；最直接的是先统一使用8875。

服务器Git认证未配置时，先完成该服务器的GitHub认证；此问题不需要重新探测GPU、CUDA或全局Python环境。Linux网页中Key输入禁用，型号和接口地址仍在页面设置。

停止本项目：

```bash
sudo docker compose --env-file "$HOME/seampact-demo-runtime/compose.env" -f deploy/compose.yaml stop control
```

这条命令保留项目运行目录。更新用`git pull --ff-only`、`fetch_sources.py`和`up -d --build control`，完整操作见[Docker部署](Docker部署.md)。

## 4. 页面里实际怎么操作

先到“模型接口”。选择DeepSeek，确认接口地址、实际模型ID和Key状态，点击“保存接口”，再点击“发现模型能力”。Windows可以在页面填写Key；Linux需先按上文配置秘密文件。GLM未配置时可以先不使用。最大输出优先从提供方元数据发现，费用、调用次数和分析轮次没有应用上限，分析保留完整历史。

**先看一次任务：** 选择CRAG，进入“运行DEMO”。如果已有API能力包，选择“已提供的CRAG API适配草案”；如果只有新生成包，选择对应包。选择“真实模型”，输入问题和资料，再点击“运行工作流”。资料之间用一个空行分隔。

可直接使用下面的演示输入：

问题：

```text
用三点说明：原Harness、拆分引擎和调度器分别负责什么？
```

资料：

```text
原Harness保留其算法、原生对象、会话状态和控制流程。原controller决定下一步分支与调用何时使能。

拆分引擎接收API Agent提出的源码边界，核对固定来源、支持规则和接线，生成adapter与有限局部重构产物。它不会重新生成整个业务算法。

当前调度器给已经使能的原生调用发放启动许可，采用FIFO。结果返回原controller。并行、跨来源组合和两层RL是后续实现。
```

查看右侧答案、被激活能力、模型调用用量和执行轨迹。SDK无效果StartEvent分支单独标记，不把它解释为一次有用业务处理。完成后的执行槽应退休；任务失败则查看该运行的错误，先处理原因，不连续重放付费任务。

**再看自动拆分：** 回到“自动分析与适配”，输入接入目标，点击“准备来源并开始分析”。Agent会读取固定工件、调用检查工具并提交候选；完成后点击“生成适配草案”。支持的CRAG包可在运行区选择。只想查看来源时使用“仅准备来源”，它不启动模型分析。

自动分析会实际调用API，可能比问答耗时更长。组会中可以展示已保存的分析记录，再运行一次短问答；这样能讲清楚分析期和执行期分别在做什么。若检查拒绝某个候选，页面会显示原因；构建成功本身也不代表任意宿主都能运行它。

## 5. 建议的组会演示顺序

1. 展示四源卡片，说明它们分别代表工具会话、文档工作流、政策配置和离线模型作业。
2. 展示一份CRAG分析记录与生成包，指出API提议和引擎检查的分工。
3. 运行上面的真实问答，展示答案与能力激活；解释“包里的边界”与“这次实际调用”的区别。
4. 打开轨迹，说明原controller继续分支、Coordinator发启动许可、原算法执行。
5. 回到[组会报告](组会报告.md)，说明当前FIFO范围及后续MMCT、组合／并行与两层RL。

受控预览适合离线讲解调用流程，页面明确标记为不调用模型；实际模型回答使用“真实模型”。已有API分析、包联调和真实任务各有记录，不把它们拼成一轮未执行过的新实验。
