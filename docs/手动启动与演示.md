# 手动启动与使用

更新：2026-10-16，SeamPact 0.9.0。普通对话留在首页；配置接受真实仓库URL／目录，自动分析形成能力池和运行组。新增三学习器、教师反馈与研究运行配置，操作见本文末节。远端部署的完整过程和命令先读[服务器部署](服务器部署.md)，Docker网络与依赖读[Docker部署](Docker部署.md)，K8S读[运行组与K8S](运行组与K8S部署.md)。

## 1. 本机原生启动

在自己的Seampact仓库根目录执行。核心无第三方Python依赖，URL接入需Git。普通界面可用Python3.11以上；有限构造／原位宿主与worker的已确认范围是Python3.11，不能因为界面在3.13启动就扩大执行范围。

Linux有Python3.11时：

```bash
python3.11 --version
PYTHONPATH=src python3.11 -B -m seampact serve --home var/prototype --host 127.0.0.1 --port 8880
```

有现成3.11虚拟环境则激活该环境后先用 `python --version` 确认版本。需要新的专属环境且3.11已安装时，先执行：

```bash
test ! -e .venv
```

仅在上一条成功、目录不存在时创建：

```bash
python3.11 -m venv .venv
. .venv/bin/activate
PYTHONPATH=src python -B -m seampact serve --home var/prototype --host 127.0.0.1 --port 8880
```

已有`.venv`时跳过创建；先看其版本，3.11环境才用于本文原生能力，不覆盖已有环境。系统只有3.13或缺venv组件时使用Docker路线或返回实际报错，不替换系统Python。

Windows PowerShell在仓库根目录，使用已有3.11环境，一条命令启动：

```powershell
.\start.cmd
```

脚本优先使用项目已有的 `.venv-agentdojo` 环境，没有该目录时使用当前环境的 `python`，自动切换到仓库目录并设置源码路径；不需要 `py` launcher，也不创建或覆盖虚拟环境。默认地址是 http://127.0.0.1:8880，按 Ctrl+C 停止。更换端口用 `.\start.cmd --port 8881`。

手动启动也可以直接使用当前环境的Python：

```powershell
python --version
$env:PYTHONPATH = 'src'
python -B -m seampact serve --home var/prototype --host 127.0.0.1 --port 8880
```

上面的 `test ! -e .venv` 是Bash命令，不能在PowerShell中执行。PowerShell检查目录是否不存在应使用 `-not (Test-Path .venv)`；本机已有可用Python3.11时无需新建环境。

装有Python launcher且已登记3.11时，也可以使用：

```powershell
py -3.11 --version
$env:PYTHONPATH = 'src'
py -3.11 -B -m seampact serve --home var/prototype --host 127.0.0.1 --port 8880
```

没有launcher而已有Conda／venv时，先激活自己的3.11环境，使用python执行同样命令。不要为了本文修改全局Python路径。

打开http://127.0.0.1:8880，程序以前台运行，Ctrl+C结束。端口已占用时先辨认已有实例；换端口就在启动命令改为自己的空闲端口，不结束别人进程。服务器平台经SSH转发的网页默认是http://127.0.0.1:18880，不与电脑本机实例混用。

可选复用同系统中已有模型配置：

```bash
PYTHONPATH=src python3.11 -B -m seampact serve --home var/prototype --legacy-config var/demo/config --port 8880
```

只读取模型配置，不复用旧固定来源宿主。Windows密钥必须由原Windows用户解密；迁往Linux时在目标网页重填。

## 2. 配置模型与正常对话

点“配置”，分别保存“对话模型”和“分析模型”。两者可用不同接口／型号：

| 字段 | 填写 |
|---|---|
| 接口地址 | OpenAI兼容基础路径，程序追加 `/chat/completions`；不要填完整请求URL |
| DeepSeek | `https://api.deepseek.com`，型号用账号当前实际可用的ID |
| GLM | 国内通常为 `https://open.bigmodel.cn/api/paas/v4`，按实际账号接口填写 |
| 本地模型服务 | 对话和分析均可使用实际可达的兼容地址，如 `http://127.0.0.1:8000/v1` |
| API Key | 需要鉴权时填写密钥；同一地址下留空保留已有值；无鉴权服务明确选择“无鉴权” |
| 最大输出token | 可选，按模型实际输出能力；留空用可取得的能力或提供方默认设置 |

分析角色支持本地或远程 HTTP／HTTPS，并需要 Chat Completions 与工具调用能力。地址由平台后端访问，容器中的 `localhost` 指向平台容器自身。平台保留完整上下文，不设置应用费用、调用次数、分析轮次上限；提供方仍有自己的上下文和额度。密钥不发聊天，不放在Harness初始化配置中。

保存对话模型后可直接发送消息，无需先接入Harness。普通对话与原能力调用分别记录，不会伪造未调用的工具。

## 3. 从地址自动分析到能力池

配置中填仓库URL或本地目录。路径是**运行平台的机器**的路径；Docker内使用 `/harnesses/<项目>`，不填电脑路径。远端取得代码、私有源上传和挂载关系见服务器指南。

可填写修订、已知原生入口、资源JSON数组及非敏感初始化配置。例如实际有这些资源时：

```json
[
  {"path": "/harnesses/my-harness/config.json", "kind": "config"},
  {"path": "/harnesses/my-harness/data", "kind": "data"}
]
```

资源是已有物料的位置，不是预设拆分答案。入口定位完整Harness；API仍读取整个目录并自行探索。业务输入留给每次任务，固定参数须来自原默认值、原调用字面值或真实用户配置，不填样例值使任务接口变空。

点“接入 Harness”，再点这个来源的“分析”。后台使用实际分析API列结构、读源码、查构造／导入，提出入口、W／H／有限R边界和runtime_groups，接收引擎反馈并修正。同版本再分析沿用完整历史，不是全新独立分析会话。

| 状态 | 含义 |
|---|---|
| ANALYZED | API提交候选、引擎形成结果，不表示原算法已经运行 |
| READY／SOURCE_BOUND | 声明范围内静态源码与绑定准备，不是完整证明或已初始化 |
| BOUND | 对应原生绑定／初始化已在实际调用中执行 |
| MISSING | 缺依赖、参数、资源、初始化或接线，查看具体原因 |
| LOCAL_ONLY | 远程条件未覆盖，保留原本地执行；与本地能否READY分别判断 |
| REMOTE_CHECKED | 当前有限远程规则已核对，仍需实际启动、登记运行进程 |
| UNRESOLVED | 业务／组合语义条件仍未完全建立，不等于执行结果是假数据 |

只有实际可调用入口提供给对话模型；真实调用才加载原算法和原对象。核心镜像没有所有Harness依赖，缺库／模型时不能由API编造替代值。

## 4. 对话调用与运行观察

在首页说明实际任务、输入和所需结果。对话模型根据能力池提交完整方案，上层Q从合法候选中选择；下层安排原controller已使能且owner／资源条件允许的调用。当前方案步骤按声明顺序执行。

后项可以通过 `{"$result":{"step":"前项id","path":["字典键",0]}}` 接前项真实成功结果。省略path表示本体，仅投影内建dict／list／tuple，不读取对象属性。异常、非成功退出或实际参数不符会停止后继。原对象边留在原进程，不通过文字或JSON重建。

独立详情页都在**当前标签页**导航，可用浏览器后退；不会自动打开一批新标签。导航后任务仍在后端运行，可去“任务详情”查看。当前首页对话消息保存在页面内，返回／刷新后不会自动恢复完整对话气泡；不要把后台任务历史与前端对话记忆混为一谈。

| 页面 | 看什么 |
|---|---|
| 来源与分析 | 分析历史、候选、源码版本、完整检查报告，按来源筛选 |
| 能力池 | 实际输入／结果端口、绑定状态、初始化、缺口 |
| 运行组与部署 | 原生归属、组成员、远程条件和位置，导出包／登记进程 |
| 任务详情 | 实际回复、方案、结果／控制边、Unit调用与总时延 |
| 调度器 | 激活／等待、合法候选数、Q更新和调用收尾 |

展开、焦点和滚动在同页轮询时保留。候选数只有1时，Q更新不说明有择优收益。调用正常返回也不等于最终答案质量已经证明。

## 5. 摘除、重新接入与重启

来源卡片／配置列表可“摘除来源”：当前Units退出能力池，停止后续分析／调用；已经进入执行的原调用允许收尾，源码和历史保留。它不删除资源、不强杀模型，也不自动调用未知原close。

“取消本次分析”独立停止平台等待和后续处理，保留来源、已保存进度与已有能力；服务端已接收的模型请求可能继续执行。“删除来源记录”取消相关分析并移除来源及其能力池入口，同时删除平台克隆到本地的仓库，以及登记在这些仓库路径下的权重。放在独立目录的权重、你填写的原本地目录、冻结快照和已有任务依据保留。仍在执行的调用或研究占用须先结束。

“重新接入”复用最后完成的分析，创建新安装身份，不再次调用模型；原调用尚未收尾时须先等它结束。远程组恢复后导出新包，旧实例不能冒充新绑定。当前没有按Unit挑选剔除功能。

平台重启保留已保存的分析与任务，但不会恢复原会话或前端消息。**主平台重启后worker也需要重启再登记新session。** 网络响应缺失不会自动重放；原结果未决时不能直接换实例。

## 研究运行与冻结策略

在配置窗口的“调度学习与研究运行”中选择学习器、任务预算、种子和模式。首个真实开发配置保存在 `var/prototype/research/agentdojo/development_config.json`，可用“导入配置”加载；在本机也已保存为当前配置。教师标准、证据范围、分项尺度和权重可编辑，运行开始后冻结副本。教师可以独立配置，当前开发配置明确复用分析角色。

“能力池”里的 Unit 可以声明为业务可见／业务申请，或透明／平台触发。透明 Unit 不出现在业务模型工具列表，场景在真实事件上交给策略选择。场景还须提供原生重置、事件、候选、终止及结果判据；分析成功不会自动生成这些任务条件。

打开 `/inspect?view=scheduler` 查看时间与哈希标识、实际进度、分项覆盖、原始曲线和完整清单。选择多个运行可并列比较；UNKNOWN／N/A 单列，缺失不算零。运行按任务边界停止，三学习器顺序执行。结果位于 `var/prototype/policy/runs/<完整run_id>/`：清单 `manifest.json`、真实任务轨迹 `history.jsonl`、曲线 `curves.jsonl` 和实际更新后的策略 `policy.pt`。名字与标签不作为身份。

已有真实参数更新并完成的策略可“激活”。回到对话页，默认仍是普通对话；选择保存的场景任务后执行该原任务，输入文字只作附言。策略在真实工具返回事件上选择原模块，在线不再调用反馈教师。普通对话不会被冒充成已接入场景。

重评仅用于旧执行条件与证据仍适用的判据变化，服务／环境版本未知时保留参数热启动与新交互；PPO 总是采集当期轨迹。已保存小预算开发运行用于研究开发，不代替独立多种子、跨来源或投稿主实验。
