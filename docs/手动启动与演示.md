# 手动启动与使用

更新：2026-10-13，0.6.0。当前页面是普通 AI 对话，Harness 从用户填写的地址接入。

## 在本机启动

在仓库根目录使用 Python 3.11 或以上。平台核心没有第三方 Python 依赖；URL 接入需要 Git；原 Harness 所需库需要安装在这个运行环境中。

Linux：

```bash
PYTHONPATH=src python -B -m seampact serve --home var/prototype --port 8880
```

Windows PowerShell：

```powershell
$env:PYTHONPATH = 'src'
python -B -m seampact serve --home var/prototype --port 8880
```

浏览器打开 http://127.0.0.1:8880。关闭运行终端中的程序使用 Ctrl+C。

现有私有模型配置可以通过 `--legacy-config` 复用，例如：

```bash
PYTHONPATH=src python -B -m seampact serve --home var/prototype --legacy-config var/demo/config --port 8880
```

这只读取已有接口配置，不复用旧的固定来源、能力包或任务宿主。Windows 保存的密钥需要在原 Windows 用户下使用；迁移到 Linux 后在页面重新填写密钥。

## 配置模型并对话

点击左侧“配置”，分别保存“对话模型”和“分析模型”。两者可以使用不同接口和型号。

| 配置项 | 填写方式 |
|---|---|
| 接口地址 | OpenAI 兼容基础地址；程序在其后追加 `/chat/completions`。本地常见形式为 `http://127.0.0.1:8000/v1` |
| 模型 ID | 填实际提供方或本地部署的模型 ID |
| API Key | 云端填写实际密钥；不要求密钥的本地对话接口可留空；保持地址不变时留空保留已有密钥 |
| 最大输出 token | 可选。填写实际模型支持的输出上限；留空采用可获取的模型能力或提供方默认值 |

分析接口使用云端 HTTPS。平台保留完整对话和分析工具上下文，不设置应用费用、调用次数或分析轮次上限；提供方本身的上下文和输出限制仍然存在。

保存对话模型后直接在首页发送消息。此时可以只有对话功能，不需要先接入任何 Harness。

## 接入 Harness

配置中填写仓库 URL 或本地目录。路径指运行平台的机器上的路径；Docker 内使用容器路径，例如 `/harnesses/my-harness`。

可选信息包括 Git 修订、已知原生入口和资源列表。资源填写 JSON 数组，例如：

```json
[
  {"path": "/harnesses/my-harness/config.json", "kind": "config"},
  {"path": "/harnesses/my-harness/data", "kind": "data"}
]
```

这些是用户已有的资源位置，不是预设拆分结果。模型／数据二进制保持为引用，不塞入分析上下文。

点击“接入 Harness”，来源出现在配置列表；再点击它的“分析”。后台开始真实调用分析模型：列目录、读源码、查入口／导入、提出候选并接收引擎反馈。分析完成后，打开“运行状态”查看分析结果和能力池。

`READY` 表示入口、签名和声明的绑定已静态检查，初始化尚未运行。`MISSING` 显示未满足的依赖、资源、参数或接线条件。只有 `READY` Unit 会提供给对话模型。对话选择调用后才真正加载原 Harness、创建原 owner 和运行入口，返回实际结果。

## 在观察面板看什么

对话任务会显示最终回复或基础报错、总时延、实际 Unit 调用及各调用的等待／执行状态。上层调度显示选中的完整方案；下层调度安排原控制流已经使能的调用。能力池和任务执行使用同一个原生运行时。

当前方案步骤按声明顺序运行。若后续步骤需要前一步的结果，对话模型先调用前一步，获得结果后在下一轮提交后续方案。没有可用 Unit 时系统正常回答，不生成虚构的调用记录。

服务器与 Docker 操作分别见[服务器部署](服务器部署.md)和[Docker 部署](Docker部署.md)。
