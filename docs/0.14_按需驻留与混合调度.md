# 0.14.0：按需驻留、混合任务与资源观测

更新：2026-10-29。目标是在同样的真实任务、模型与防护义务下比较资源和服务效率。版本号为 `0.14.0`；本页描述已实现接口及其覆盖范围，正式实验仍遵循[主协议第 15 节](../../ccfa-workfiles/experiments/harness-paper-design/plan.md#15-多来源防护效果保持与资源调度主实验2026-10-28)。

## 1. 能力池与同时驻留分开

`residency.py` 按冻结的 `task.unit_ids`（省略时为该任务路由的全部 Unit）推导运行组工作集。每个任务在进入原执行前占有完整必需工作集的逻辑容量，任务结束才归还，以免先持有一个模型再永远等待另一个模型。未获准回收的运行组始终作为保留需求计入；`fixed_resident` 对照保留全池需求。

例如，两类任务分别需要 6 个容量单位、设备预算为 8：有回收资格时，两类模型可以都在能力池中，任务轮换使用容量；不要求把 12 个单位同时装入。若单个任务确实同时依赖两个组，它的 12 个单位仍不满足 8 的约束。平台不能删去必需调用来放行。容量单位来自显式需求配置，不能把多卡显存简单相加冒充一个模型可使用的连续空间。

容量压力下，所有策略采用同一确定性释放规则：只选择已获准回收、无活动调用、无排队调用可用它且无未结束任务租约的实例；释放确认后才允许新的实际启动。`STARTING`、`DRAINING`、失联但未确认释放的实例仍占预算。任务仍持有 owner 时不会跨实例迁移，也不重放原调用。

`joint.capacity.resources` 声明预算，`demands` 为每个远程组声明每项需求；未知需求不能补零。远程放置由已有冻结目录提供。`initial_state: "warm"` 可以用 `warm_groups` 指定本窗口可容纳的暖态子集；省略时保持全组暖态的明确含义。所有比较臂使用相同初态。

## 2. 内部边界派发

`joint.dispatch_scope` 默认 `roots_and_boundaries`，也可冻结为 `roots` 做对照。前者除了选择根请求，还在已检查的原始内部边界真实使能后选择执行顺序。`boundary_slots` 默认等于 `capacity.call_slots`，独立限制同时获准的内部调用；原依赖、owner 顺序和 runtime 容量仍必须满足。年龄保护从实际使能起计算，只在当前合法集合内起作用。

边界必须来自既有检查器，平台不按代码行任意切割。已执行的调用不抢占，原根请求继续持有宿主直至返回。因此本版支持多个活动宿主之间的合法边界选择，不声称同一原生进程可在任意两行间换入另一个任务，更不声称可卸载一个仍被活动调用使用的模型。边界决策记录包含实际 call、semantic key、等待时长、候选数和规则／学习／年龄保护来源。

默认资源实验的 `functional_policy` 为 `required_only`，固定原功能义务；若需要研究功能选择，须另行显式配置并分开归因。学习器算法保持原实现；新增边界标志改变表示维度，因此共同表示升级为 `joint-features/2`，runtime 身份升级为 `runtime/4`。旧检查点与旧 worker 不能静默混用，按当前配置重新冻结运行、重检和生成执行包。

## 3. 多类任务共用一个窗口

`scene.routes` 是“路由名 → 普通场景配置”的映射。每条路由拥有自己的真实 adapter、已安装 `unit_ids`、资源／环境版本、训练 `criteria`、独立 `evaluation_criteria` 和指标适用声明；任务用 `route` 指定路径，可用 `task_class` 保存类别。未提供路由判据时使用运行的共同判据。所有 adapter 文件及依赖、任务文件和资源摘要一起冻结归档。

各条路由共用 `capability-features/2` 与同一个到达序列、容量和调度器。路由名、类别名仅作结果标识，不直接充当学习特征。场景桥只能调用该任务冻结子集中的已安装 Unit，不能自行构造来源对象；单场景也执行相同子集限制。任务输入、原评分适配仍须为真实来源准备，接口存在不表示四类原任务已接通。

结果中的 `route_metrics` 按路由、训练／独立评价分列。全部已到达任务都进分母：失败、未完成和缺反馈保留为未知，明确不适用另计。迟到完成的实际质量保留，并单列迟到完成数；它不算按时完成，也不补回已按时限结算的奖励。不同任务类别的同名分数不混成一个平均分。

服务指标给出到达、完成、失败、未完成、完成率、吞吐、平均／p95 响应时间和时延分母。时延统计只覆盖期限内完成任务，容量排队等待从冻结的实际到达时刻起计；窗口线程迟醒不会丢弃本已到达的任务。

## 4. 自动观测及成本口径

在现有研究运行配置 `joint` 中添加下列**配置片段**，其余必填项沿用现有 joint/1 配置。设备、进程和 cgroup 必须填写当前执行机上实际允许观测的对象，以下空列表没有自动选择全机资源的含义。

```json
{
  "dispatch_scope": "roots_and_boundaries",
  "boundary_slots": 2,
  "observation": {
    "interval_s": 0.5,
    "gpu_uuids": [],
    "process_ids": [],
    "include_current_process": true,
    "cgroup_paths": []
  }
}
```

这个片段测量当前平台进程 CPU／RSS，未声明 GPU 或 worker。实际模型进程用显式 PID 或在采样进程可见的 cgroup 路径选择；远端机器仍须在执行机使用[独立采样入口](运行组远端操作.md#7-实验资源观测)，不能把平台本地读数当远端模型成本。正式各臂冻结相同观测范围。未配置 observation 时返回 `NOT_CONFIGURED`，不生成假读数。

窗口自动从准备前开始，收尾后结束；失败也保留已经采到的历史。`phases` 记录 preparation、workload、release、resources_released（或 release_unconfirmed）、evaluation_tail 的单调时间与 UTC，原始样本记录采样开始时的阶段。评价可能与任务运行重叠；阶段标志不构成设备能耗的独占分摊。总量覆盖整个观测范围，不能直接称“纯在线推理能耗”。

| 量 | 实际含义 |
|---|---|
| 进程 CPU 秒、RSS 时间积分和采样峰值 | 按同一进程身份的有效相邻样本计算；PID 被复用或采样失败不跨空洞积分 |
| cgroup v2 CPU 秒、memory.current 积分和采样峰值 | 显式选定容器／进程组范围；与 PID 读数重叠时不相加 |
| GPU 显存积分、采样峰值、利用率、功率积分 | 仅所选 GPU UUID；功率积分是整卡能耗估计，始终保留共享归因未核实标记 |
| task-seconds、instance-seconds | 原调度反馈中的时间／实例占用代理，继续与物理观测分列；不充当 GPU 秒或账单 |
| API 与评价成本 | 使用已有真实请求／token 账本，按每条任务实际判据和教师角色计费；未报告项保持未知 |
| 租赁账单 | 仍由实际租赁记录提供，不由显存或进程计数推算 |

所有积分随指标报告有效覆盖；超过 2.5 倍采样间隔的空洞不积分，缺值不补零。原始观测和摘要写入现有私有 runtime 目录，研究历史保存摘要及索引。前端窗口详情显示服务指标、设备／进程观测、覆盖率和逐路由原始分项。

## 5. 生命周期覆盖与更新后操作

`lifecycle.py` 新增有限的冻结源码证据生成：同步 Python owner、原始值构造状态、只读请求、可穷尽的本地导入与可达调用。证据绑定源码摘要和构造绑定，worker 重建核对；状态写入、未知副作用、析构／后台活动和未获摘要的外部框架仍是 `UNKNOWN`。

**本版未建立通用 Torch／Transformers 模型生命周期摘要。** 模型名、`.eval()`、候选中的“可回收”标志都不能授予权限。这样的模型仍可按既有方式原生执行；它们的自动复制／空闲回收资格不会因版本更新而自动开放。若不可回收组的合计需求超出当前容量，系统明确拒绝该驻留配置；实际方案要按已确认的运行组／服务放置、可用资源及原 owner 生命周期安排，不能把该拒绝写成已解决的重模型换入换出。

更新平台后按统一流程重检来源和重新生成过期工件，确认每组实际生命周期报告；冻结任务路由、完整工作集、容量、共同初态及观测对象；然后直接在实际部署中做同输入的 B0／平台配对并收集开发数据。软件检查只验证这些实现路径，不新增模拟研究实验，也不替代完整 10–15 来源与四场景的正式清单。

## 6. 已验证与尚待验证

本版核验包含实际本地 Unit 安装、同窗口双路由执行、实际 Coordinator 内部边界派发、容量与 owner 租约、失败／时限分母，以及当前 Windows 进程 CPU／RSS 采样。生命周期有限子集检查包含两个独立真实子进程的原 owner 执行和退出。它们是核心实现的回归检查，不作为重模型扩缩容或防护质量证据。

2026-10-29 本地完整检查 **109 项通过**，前端 JavaScript 语法核验与差异空白检查通过。运行级汇总检查覆盖两个实际窗口、逐路由已知／未知分母及结果持久化。

尚未取得：真实重模型池的自动回收覆盖、Linux cgroup／GPU 现场观测、B0–B3 同设备配对、四场景混合训练及 D 粒度收益。本次未租用算力、调用付费模型或发布远端部署。完成这些实跑后才能报告防护效果保持、节省幅度或 RL 优于规则策略。
