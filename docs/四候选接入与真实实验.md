## 2026-10-24，0.12.0 论文问答接续与手动运行

本轮消费当前目录中 REX 的原检索入口及 PaperGraph 的交互适配 CLI 整体核验入口，使用已有 `SceneSession` 接续任务，不在场景桥中构造原客户端或产生内部细入口。一次本地必要核验完成“检索→业务模型更新回答→原主张核验→再次更新回答”，约 74 秒，核验返回 4 条结果。PaperGraph 来源新增一个本地 CLI 文件，原算法文件不变，作为外部 Agent 个例源码适配单独归因，不计作无辅助自动接入。

任务从 PaperGraph 现有 12 篇论文材料各选择一条紧凑、纯文本的已发布问答。原初答来自公开轨迹，9／3 论文划分沿用之前本地工作负载。五条可选路径与教师量表由本项目设置，不是 PaperGraph 原完整多轮评测；材料此前已用于工程探索，不作为全新未见的最终测试集。原问题目标和评价参考只用于终止后的评价，不进入策略观测或业务提示。

| 实际记录 | 结果与解释 |

此批结果与下文旧检索实验分开，不构成本轮 RL 优势、两库顺序优势或 joint/1 生命周期收益。版本与继续运行入口见[0.12.0 更新说明](0.12_本地接入与实验接续.md)。

## 真实任务与固定配置

从原 PaperGraphBench 的 12 篇论文、97 个 macro 问题和实际 KC 原文证据整理出 1,027 个唯一证据文档。在线语料只包含论文标题、原文证据和来源身份，排除 `must_include`、`forbidden_claims`、目标 KC、标准答案及 judge 结果。12 份清理后的论文事实 KC 库另存，供后续原核验器绑定。

任务是**按问题交付论文证据**，不是完整论文问答。每篇论文为一个 episode，按原问题次序交付当前已有证据；策略决定检索或继续，已得到的文档保留供后续问题使用。模块指标为实际检索的目标证据召回；系统指标为每次交付时已有证据的目标召回，先在论文内平均再按论文平均。独立参考来自原目标 KC 到原文证据的映射，不等于人工穷尽相关性标注，也不等于官方答案得分。

按论文分组，9 篇／73 问用于开发与训练，3 篇／24 问冻结评价；固定语料可以包含保留论文的可读原文，保留问题及目标映射不进入策略。当前低成本观测不编码论文名、任务 ID 或目标证据 ID。语料来自原任务集，不声称未被来源模型见过。

所有策略共用候选、mask、资源和 FIFO。任务允许不额外检索，不取消任何原流程必需工作。目标为 `论文内平均证据召回 − 0.02 × 本篇检索次数`，对应固定配置 `module_calls` 尺度 16、权重 0.32；γ=1，局部诊断权重 0。成本偏好按实际调用次数定义，真实时延独立报告。

简单策略在当前查询 token 被已有证据覆盖的比例低于阈值时检索；阈值只用开发材料在 0.3／0.5／0.7／0.9 中比较，冻结为 0.9。三学习器各用种子 11／23／37、90 篇任务 episode，即每个运行 730 次真实决策。其余参数以不可变 manifest 为准；Double DQN／SAC 各 87 次更新，PPO 各 120 次更新。冻结评价无探索、不更新参数、不调用教师。

## 拆分与调度分别得到什么证据

本次运行只能说明手写资源包装后的原 REX 检索组件实际进入共同场景、共享候选表示、三学习器和冻结运行；不能据此证明分析器完成了原始库接入。REX 原本就有检索接口，但原 Config 对象构造与常驻 owner 接线被人工补上了。原生与平台的同一首查询结果已保存，可核对真实返回，不能代替自动接入证据。

PaperGraph 的同步完整循环仍由原函数执行。分析器没有把“源码存在 extract／verify 函数”推导成按主张跳过的权限；细入口尚未形成绑定，原顺序全执行／部分新 TaskSpec 的真实粗细对照为 NOT_RUN。因此拆分收益和跨来源组合收益仍无结果，不能用本次 REX 调度训练补写。
