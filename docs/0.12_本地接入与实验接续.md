# 0.12.0 本地接入、交互修订与实验接续

本文保留该版本的功能起点与历史运行事实。当前版本为 **0.13.0**；当前依赖复用、服务器更新和已有来源继续接入的流程见[依赖镜像复用与统一构建](0.13_依赖镜像复用与统一构建.md)。

更新：2026-10-24。本版在既有四层架构中汇总近期接入、修订和展示改动，增加同一论文问答任务中的检索／核验接续。W／H／R、有限绑定准则及三种 RL 学习器沿用现有实现。

**2026-10-25 部署修正：** rootless 工具容器不再把宿主 Docker socket 的数字 GID 直接写入 `GroupAdd`，避免未映射附加组导致 runc 在入口程序启动前失败；普通 Docker 的 socket 组设置保留。现有克隆执行 `install` 前须手动快进更新源码，`install` 本身不拉取已有仓库。操作和失败安装处理见[服务器部署](服务器部署.md)。本地四项针对性构造核验通过，目标服务器的修复后启动尚待实际结果。

## 1. 本版功能

| 范围 | 当前行为 |
| --- | --- |
| 对话／分析／教师模型 | 支持本地或远程 HTTP／HTTPS OpenAI 兼容服务，可明确配置无鉴权；分析服务还须支持实际工具调用／结构化输出 |
| 来源与分析管理 | 独立取消分析、可恢复摘除、删除来源记录；删除平台管理的源码克隆时同步处理其内部权重登记，独立权重目录和用户原本地源码保留 |
| 历史会话 | 查询、搜索、打开、继续、删除和撤销删除；会话删除不等于删除底层任务执行证据 |
| 分析结果展示 | 先看分析结论、可用入口、缺口与下一步，再展开预处理、逐轮耗时和原始技术记录；同一来源的历史操作区分分析、绑定、修订与重新核对 |
| 资源绑定 | 区分服务连接、可配置权重与原固定文件；按实际受影响入口核对映射，允许为已通过映射的入口选择资源，其余入口继续显示缺口 |
| 配置字典 | 有限 `parameter_path` 支持原函数字典参数中的固定字符串键、单赋值别名及已覆盖词法读取；动态修改、跨函数传递等未覆盖形式继续保留 MISSING |
| 修订工作台 | 同源修复与源码更新分别冻结；编辑或模型修复后完整重检，再独立安装。保存实际介入者、原因、修改对象、共性跟踪及目标执行结果声明 |
| Windows 运行 | 启动脚本启用 UTF-8；浏览器断开轮询连接时停止写回，不再向同一断开的连接补写 500 响应 |
| 研究配置 | 固定参照的冻结评价可不选择父训练；学习器冻结评价、继续训练和条件重评仍要求相应父运行 |
| 论文问答接续 | `paperqa_scene.py` 消费已接入的检索和 CLI 核验 Unit，实际输出交给冻结业务模型更新回答，后继核验消费当前回答；每项能力最多调用一次 |

逐项配置见[分析结果与补齐接入](分析结果与补齐接入.md)、[资源配置操作](资源配置操作.md)和[修订工作台说明](0.11_分析修订与源码更新.md)。本版包含此前逐步落入代码的改动，历史分析仍保留其实际实现身份，不把旧记录重标为新版本成果。

## 2. 怎样判断一次接入是否完成

1. **分析结束**：模型已提交候选；不表示所有入口可执行。
2. **CHECKED**：当前完整候选已完成机械重检；仍需查看逐入口反馈，可能包含 MISSING。
3. **映射已核对**：服务／权重的原参数位置有源码依据；接下来才能选择资源。
4. **READY**：满足当前宿主可核对的绑定与环境条件；服务持续在线、模型格式兼容及真实任务结果仍需实际调用。
5. **原目标成功**：检查真实返回、CLI 返回码及目标输出；进程正常返回一个 `CompletedProcess` 不代表它的退出码是 0。
6. **任务完成与效果**：能力结果已参与后续业务处理，并取得独立评价。返回若干核验标签本身不是准确率或组合收益。

仅登记权重路径不会自动启动模型服务。原客户端对象、配置流或宿主规则缺失时，下载更多权重也不会使映射自动通过。

修订模型仍失败时，先读明确缺口。用户或外部 Agent 可按已授权的交互路径调整候选或适配源码；源码变化须选择“源码更新”重新冻结、完整核对和安装，并记录实际介入。个例成功与通用分析能力改善分别统计，不通过清空真实依赖或 unknowns 强行放行。

观察快照中的 `partial` 按“是否未成功完成”设置：COMPLETED 为 false，运行中、失败、中断或取消均为 true；`terminal` 表示分析是否已结束，因此失败时可以同时为 true。它们不代表业务任务成功。`importable:false`、`resumable_artifact:false` 表示快照不能作为候选导入或断点恢复；`excluded` 列出该观察导出省略的消息、源码、凭据、地址、机器路径和原始错误等类别。候选／源码身份导出与修订操作是不同入口。

## 3. 本轮真实运行状态

本节按 2026-10-24 已保存记录描述，服务器更新不会自动补跑这些任务。

- 已完成 AnesSuite 原评测入口的本地真实调用；没有因此完成其所有 CLI 或 SGLang 部署，也没有进行 AnesSuite 模型微调。
- REX 原检索与交互适配的 PaperGraph 原整体核验完成一题实际接续核对，约 74 秒，返回 4 条核验结果。该核对使用本地业务模型，在内存目录中验证，不是后续平台 RL 运行。
- 手动实验使用 PaperGraph 现有 12 篇论文材料，每篇选取一条已有纯文本问答，初答来自仓库公开轨迹。9／3 按论文划分沿用本地工作负载；五条路径由本项目设置，不是复现 PaperGraph 完整多轮原协议，也不是全新未见的最终测试集。
- 本轮平台共 11 个运行，3 个完成、8 个因本地核验连接被拒绝中断；19 次实际尝试中 11 次反馈可用、8 次被排除。Double DQN 有效交互为 6 次，PPO 与离散 SAC 为 0 次，三者更新次数均为 0。
- 完成的只检索单题在线耗时约 7.46 秒，证据召回率 66.7%；与不调用路径的教师评分同为 4／4，暂未显示该题质量增益。相同题目、回答和允许评价证据另出现 4 分／3 分波动，需复核教师一致性。

本轮平台运行的业务模型实际为 DeepSeek，核验器内部仍绑定本地 Qwen 与 BGE；不能与前述本地业务模型验证直接计算加速比例。不调用路径复用已有初答，其结束时间不包含从零生成初答。失败耗时保留为实际成本，不作为完整路径性能；未报的 token 或金额保持未知。

机器地址、路径、运行身份和原始材料继续保存在私有状态／实验目录。Linux／Docker／GPU／K8S 的本版部署仍待目标服务器实测，尚无本轮 RL 或跨库组合优势结论。历史结果见[四候选与真实实验](history/四候选接入与真实实验.md)。

## 4. 服务器更新与跨机器准备

服务器更新主入口仍是[服务器部署](服务器部署.md)。本节保留 0.12.0 的发布准备记录，当时 `pyproject.toml`、`seampact.__version__` 和新进程 `/health` 的版本均为 `0.12.0`；当前版本及更新步骤以服务器部署主文档为准。根目录旧 `release-manifest.json` 是 `0.5.0` 的历史工作区快照，不是本次发布清单或运行证明，不应仅改其中版本号冒充重新验证。

已由 `deploy.sh` 管理的部署，等任务和 worker 收尾后，在原部署工作区执行：

```bash
bash ./deploy.sh update
```

若此前未安装学习器依赖，本次使用 `bash ./deploy.sh update --extras rl`；原来已有则沿用。脚本只拉取远端已有的干净提交，本机尚未提交／上传的源码不会自动出现在服务器。自定义部署根目录、旧 Docker／Compose 接管和直接 Python 运行，分别按主部署文档操作，不混用管理入口。

更新与新机器迁移需要区分：

| 材料 | 更新／迁移时的处理 |
| --- | --- |
| 服务器已有持久状态 | 同机更新沿用原 `/data`，脚本停机备份后替换容器 |
| Windows 凭据 | DPAPI 绑定原 Windows 用户／机器，迁到 Linux 后通过前端重新录入；不复制密钥明文到仓库 |
| 服务地址 | 在平台实际网络中核对；容器 `127.0.0.1` 指向平台容器，不指向宿主或 Windows 电脑 |
| 权重、语料、索引 | 独立迁移到服务器持久目录，填写平台容器可见路径；不随平台代码 Git 更新传输 |
| 本地源码与个例适配 | 私有 `var/` 与 `.local-private/` 不进入 Git；例如交互适配的 CLI 文件须随对应来源目录单独迁移，再重新冻结核对 |
| 实验配置 | Windows 绝对路径、Unit 身份和父运行不可直接套用；按服务器现役目录／候选重新生成或编辑配置 |
| worker | 核对新平台与核心身份，必要时重新生成运行包、构建镜像并启动；不恢复旧进程的内存对象 |

平台升级不负责启动 Qwen、embedding 或原检索服务。先实际验证这些资源及一次原目标调用，再继续实验。

## 5. 更新后继续实验

1. 打开 `/health` 确认版本，刷新前端，核对来源、命名连接和持久目录。
2. 启动实际需要的模型／embedding／检索服务；在前端重新选择符合原接口后缀的连接并核对入口条件。
3. 将实验 Unit 设为平台事件调度，补齐单题只核验、两种组合方向和关键评价；保留旧失败记录。
4. 固定本轮业务模型与教师，先复核重复评价，再启动三学习器。确认有效交互、实际参数更新和策略工件，而不是只看已提交次数。
5. 使用本轮对应完成训练作为父运行做冻结评价；固定参照可不选父运行。开发与留出材料分别保存，不根据同一留出结果反复改题或调权重。

五条路径可用于检查能力调用和顺序，本版尚未证明哪条路径更优。完整实验记录继续通过现有平台保存，不另建实验平台。
