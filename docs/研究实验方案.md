### 0.0 接入预处理、绑定、拆分与调度的归因边界

2026-10-20 新增[服务与权重资源配置设计](模型服务与权重资源配置设计.md)，为用户提供真实连接、凭据和权重路径的前端入口。配置值仍属于资源输入，原依赖识别、参数映射与入口构建由平台完成。API 服务与本地模型加载分别保存身份和实际成功依据；配置绑定、资源准备及网络／加载开销进入接入和运行成本，不将新增资源配置功能单独当作拆分或 RL 收益。当前实现及逐平台真实证据以页首续记和[当前实现](当前实现.md)为准，Linux／跨机器实机仍 NOT_RUN。

**开发者与平台分析器的职责是实现约束。** 外部 Codex 可以核对原源码、整理资源／评价标准、实现通用工具与场景适配；原入口发现、构造绑定候选和有限拆分必须发生在平台分析链内。不得先为某来源写 `seampact_entry.py`、人工拼接内部步骤或提供切分答案，再把分析器对这些包装的处理称为本轮主链。标注“人工辅助”只限定历史证据，不构成继续绕过分析器的许可。确需采集人工参照时单独定义比较臂和输入，不能用它替代自动接入臂。

场景桥消费已由分析器生成并经规则核对的目录 Unit，只负责任务输入、事件、接续、证据引用和评价。它不能直接构造被接入来源的 owner、调用其内部函数或自行制造细入口。Benchmark 自身环境／评价器的必要调用属于任务适配，应与被调度能力区分。系统内由检查器／构建器按版本化规则生成的来源绑定是允许的，但须保存原源码与生成工件的区别。

接入遇到缺口时，先区分资源缺失、已有规则未实现和新增变换语义：资源缺失如实记录；已有规格内补通用分析器／检查器／构建器；涉及新的状态、生命周期、导出或跳过权限时先明确规格，拿不准的选择由用户确认。不能为获得 READY 数量而换成无关辅助入口，完整目标调用仍单独记录。

本节区分实现与研究比较。自动 API 预处理现已接入原分析器后端：独立提示词和工具循环自动提出入口及构造绑定候选，冻结工件后由新的拆分上下文实际消费；原库不需要人工先写包装。REX 与 PaperGraph 的真实自动链路已完成，分别为预处理／拆分 16／14 和 32／33 次响应，结果另存 `var/prototype/research/original-intake/api-preprocessing-results.json`。两者完整目标调用仍未兑现；这不表示新增常驻构造规则已实现，也没有运行本节全部对照。不增加平台架构层。

| 环节 | 输入与输出 | 需要保持的边界 |
|---|---|---|
| 自动预处理 | 固定原库、任务目标与资源清单 → 源码依据、原入口、配置／资源及构造适配候选 | 由分析 API 自动完成，可提出可执行绑定 IR，而非仅整理事实。当前生成代码沿用已支持 IR 的构建器；构造适配、代码规范化若超出现有范围，须补相应规则实例和独立核对，不引入手工逐库步骤。最终拆分边界和运行组由后续分析决定 |

既有[构造语义第 2—4 节](../../想法/21_拆分接入的构造语义与规则实例.md)已描述原构造／工厂、对象引用及模块／宿主／会话／请求作用域。当前代码只兑现了请求级同步直线前缀等有限形式。因此，继承／有效接收者解析、目标入口发现、构造图和生命周期绑定首先应核对现有规格并补充可执行规则实例，不能把缺实现统称为缺理论。改变对象共享、原控制顺序、独立导出或允许跳过范围时，才须另列相应语义与证明义务；已有规格中的规则也仍不等于完整可靠性证明已经完成。

每次交付保存原始提交和源码摘要、任务目标、用户提供信息、资源版本、各环节输入／输出摘要、执行器与实现版本、API 可提供的模型版本、完整提示词／工具往返、候选、规则及宿主版本、源映射、未决义务和实际消耗。已有冻结记录可复用，缺项明确补齐。保存候选以重放检查与构建；重新采样分析 API 的成功率另行报告，不把保存一次结果等同于云端生成过程完全确定。

当前工件为 `source-preparation-artifact/1`，包含 `source-preparation/1` 内容和 `source-preparation-report/1` 反馈；原源码、工件和生成适配候选分别保存。`POST /api/analyze` 默认 `preprocessing="api"`，`"none"` 保留直接分析对照，`"replay"` 加 `preprocessing_id` 复用冻结预处理并重新核对来源／配置／规则，后续拆分仍调用分析 API。`GET /api/preprocessing/<id>` 取得原始工件。预处理和拆分消息上下文分开，用量按环节记录，同时保留总体用量，不能相加重复计费。已有构造 lowering 负责从受支持 IR 自动生成适配程序；新链路没有开放任意生成 Python 直接冒充原源码执行。

归因比较分开回答以下问题：

- **预处理与规则覆盖：** 固定原库、目标功能、资源、模型配置和预算，分别比较无／有预处理、原／增强可执行规则。若规则依赖预处理产物，应报告联合效果及依赖，不能各自宣称独立收益。评价目标是完整目标功能的实际接入，不以辅助 READY 数代替；全部来源、失败和人工帮助保留在分母与成本中。
- **变换与拆分：** 对比原生完整流程、自动绑定的整体入口、合法细粒度全执行；固定原输入、初态、资源与控制选择，核对实际返回、异常、对象／状态、外部调用次序、漏调／重复及全执行成本。成对运行事实不替代规则的行为保持论证。
- **调度与粒度：** 冻结同一接入工件，在相同粒度内比较跳过可选干预、适用全开、简单策略与 RL；原必需工作始终保留。若主张细粒度使调度更有效，整体与细粒度应各有相应简单策略／RL，不能同时换资源、额外提供隐藏证据或改变任务义务。

成本分列预处理／分析、人工准备与修复、资源获取与初始化、训练交互／教师、梯度及冻结运行；同时保留总投入与单任务费用，冷／热启动分开，嵌套时延不重复相加，未知项不补零。四个当前候选已用于方法开发；后续新增规则若在其上形成，跨来源泛化结论还需未参与规则调节的来源或明确限定适用范围。

### 0.1 主张与证据对应

2026-10-23 新增维护研究范围：人工提示和候选编辑是允许的交互条件，分别记录自动发现、提示引导和人工结构修订，保留实际内容及投入；仍不以人工包装替代自动接入臂。源码迭代、同源码纠错、资源补齐及规则变化分别冻结新请求／候选和方法身份，不把维护成功回填为旧分析已正确。首次分析及失败尝试的成本继续保留。

维护问题附属于 RQ1 的接入投入与覆盖、RQ2 的逐操作依据；机制见[主设计第 3.4／14.3 节](../../想法/18_异构Harness拆分形式与RL调度设计.md#34-跨版本维护与失效驱动修复研究设计)。需要同时说明更新范围、完整候选的有效性、新能力发现范围、错误复用及有据操作的保留，不能仅按少发送 tokens 判断。完整重新分析、只复用文件／对话及按支撑维护应保持相同目标和可信规则；新辅助输入本身也是比较条件。结构复用不建立 RQ3 的收益可迁移，旧轨迹继续按原兼容规则处理。0.11.0 已实现[材料复用、局部模型修复及完整重检](0.11_分析修订与源码更新.md)的工程入口；本机零模型草稿操作仅核对工程链路，未产生维护效率、模型质量或逐义务复用的研究结果。

### 0.2 本轮选材与信息提炼

**原库自动接入与评价契约整理分别记录。** 入口、边界与有限绑定由平台分析器依据原库提出；研究人员不预写包装入口或切分答案。评价标准、原评分程序、提示词及所需证据可以由研究人员借助 Agent 核对，也接受开发方提供的说明；这不等于从任意源码自动恢复可靠奖励。整理时间、Agent 消耗及人工核对计入准备成本，判据的有效性仍需独立结果检验。

每项来源整理：固定源码版本及配置；原调用事件、参数、资源、状态和结果含义；原阈值／政策提示词／评分函数；独立判定需要的数据和证据；缺失信息。模块方提供技术前提和原评价语义，平台／任务方确定必须执行义务、允许取舍范围及共同成本目标。把原固定流程改为可选干预时，显式声明这一任务政策变化。

真实任务使用 `{id, request:{request_id,image,question,original_answer}, reference:{category,references}}`；`reference` 只供终局评分，原始回答已有成本可另放 `upstream_costs`，注明来源，不能假装在当前回合测得。程序评价可绑定 `native_quality`、`native_before_quality`、`native_correction_success`、`native_harm`、`native_changed` 和 `native_quality_gain`；OCR 另有 `native_ocr_soft_quality`、`native_ocr_before_soft_quality` 两项。训练器另外提供真实 `latency_ms/module_calls/module_duration_ms`。各项分别保存，纠错和误改的分母由评价汇总明确给出。

该桥首先可用原程序反馈。当前文字教师收到图像文件路径不会自动看到图像内容，因此还不能声称完成 VPC3 的视觉教师盲评。该臂需要实际视觉模型及图像证据接线；无法判断时保留 UNKNOWN，不能给教师隐藏参考答案后再把结果称作无标签评价。

### 0.4 最小充分实验及执行方式

**A．接入与行为对应。** 对选定完整任务固定仓库版本、原配置、资源、宿主和交付目标，比较第 4 节四臂。通用 Agent 与 SeamPact 使用同一模型和源码工具；“通用 Agent＋同检查器”获得同一检查器、构建器和实际反馈，差别限定为分析组织与规则引导。所有产物使用相同独立调用判定，人工边界不作为唯一答案。记录输入准备、模型等待、核验、修复及总历时；人工时间与 API 消耗分别报告。将失败／不支持／依赖不足保留在来源分母中。对受规则支持的变换，原生与适配输入及外部返回成对对齐，记录结果、调用与异常；生成式差异按观察契约处理。该组回答接入成本与行为对应，不能被仅保存 JSON 或 READY 条目替代。

**B．真实调度效果。** 先固定一项确有合法取舍的任务，使用相同模块、服务和数据划分比较跳过、始终执行、随机、已有适用阈值及三种现有学习器。阈值只能来自原设置或训练／验证集选择，不使用当前尚未调用的重模块结果；对重检测后才取得分数的策略，另算其实际成本。正常输入和困难／攻击输入分别报告，再按事先固定混合比例汇总。除训练回报，还报独立任务质量、误改／误阻断、必要干预漏失、原模块实际调用率、端到端时延及失败费用；安全攻击成功率仅在对应隐藏目标判据真实可执行时填写。VPC3 的正确性改善不改称攻击防御成功。

单次选择后结束的场景按上下文 bandit 问题描述：现有 PPO／DDQN／离散 SAC 可以运行，但不能把单步数据解释为多步 RL 优势。将强上下文 bandit 作为后续比较计划，复用相同观测与合法候选；本轮不擅自新增学习器实现。多决策实验必须来自模块改变后续信息、任务路径或资源后的真实接续，不能人为插入空步骤。

**C．判据与教师。** 先在固定的已执行轨迹上，分别保存原程序判据与教师判断。教师使用冻结标准和当次允许证据，不读取原程序终局标量、隐藏标签、保留测试参考答案或攻击身份；无法从证据判断时保留 UNKNOWN。分项报告错误接受／错误拒绝、可判定覆盖、未知及实际费用，并按动作与任务类型分层。程序反馈训练臂和教师反馈训练臂分开保存，保持同学习器、任务分布、动作空间、目标尺度和新环境交互预算；程序臂获得原生判据是其定义的一部分，不把它冒充教师盲评或评价上界。最终均用未参与训练的独立判据评价。原模块自身分数可作代理反馈，不能同时充当其干预正确性的唯一真值。

**D．能力池变化与经验复用。** 当真实任务中存在两个或更多来源的可执行调用机会时，固定旧池训练后增／删／替换来源，比较冻结、从头与同算法兼容热启动；来源可以在不同真实事件生效，不要求预先证明天然互补。比较互斥替换时才额外要求对应动作能承担同一任务职责。三臂面对相同新环境、反馈、保留集与新增交互预算；画性能—新交互量曲线，列新交互、旧训练和教师成本，另报原任务是否退化。普通热启动只支撑参数复用，条件重评仍须满足第 6.4 节的转移、动作和证据兼容条件。当前仅 VPC3 一次可选校准的桥已存在，跨源组合／模块留出仍为 NOT_RUN。

**E．有解释力的消融。** 固定主学习器后，围绕实际实现选择必要消融：共享候选特征／已有低成本观测、结构化教师与自由总分、从头与参数复用。每项仅改变一个研究因素，记录它改变的信息与成本。必要调用和原依赖保持是运行前提，不通过实际执行违规动作制造优势；若离线分析约束影响，限定在保存轨迹或沙箱并单列结果。无独立新增机制时不另造“改进 RL”名称。

A—C 构成当前最小完整证据；D 是经验适应主张所必需，但受真实兼容模块和资源限制，未完成时收窄论文主张。E 选择能解释主结果的必要因素，不要求全部学习器、反馈、来源与变化类型做笛卡尔积。比较先以 3 个固定并记录的独立种子取得有限方差估计，展示单次结果与均值／范围；3 个种子不构成显著性或稳定性的保证，正式规模根据可见方差、差异和费用确定。配置选择只用训练／验证集，冻结后再评价保留集。

### 0.5 数据隔离与记录

- 按原始问题、同一图像／文档、会话或攻击种子分组切分，改写、同源裁剪、重复问法和共享参考答案不得跨训练与保留评价分组。图像／文档文件路径或任务 ID 不作为泄漏标签输入。
- 预训练、原 gate 权重训练、调度器训练、教师校准和最终评价分别记录。核对 VPC3 gate 原训练来源，保留集不得与其已知训练样本重合；原权重训练来源未知时记录 UNKNOWN，并限定未见数据主张。
- 来源泛化按代码家族及底层模型依赖分组。已参与模型提示修正、接线或判据调试的来源不再称全未见来源；同源码换名称、阈值或外壳不算独立来源迁移。
- 评价所需参考答案、隐藏安全标签和专家后验输出可以进入允许的训练反馈，不能提前加入调度状态。原 gate 或原模块取得这些信息的方式保持原算法，并计入其成本。
- 每次运行冻结源码、数据分组、服务／模型可知版本、配置、教师提示、指标定义、种子与父工件，沿用时间加内容哈希身份。当前云模型精确修订不可知时保留 UNKNOWN，不编造兼容性证明。
- 第 11 节已有 80 次尝试／74 次完整反馈保留为开发链路数据，不填入本轮主实验表。新数据使用新运行身份，不覆盖历史记录，不把尚未运行的路线或材料检查写成训练收益。

### 0.6 两层评价、奖励与系统任务集

模块级分别评价功能完成、前置激活理由及真实对照增益；系统级评价完整 Agent 任务，不能用模块分数均值代替。教师采用统一结构模板加模块评价卡，按前置、执行后、实际配对与系统终局隔离证据；时延、token 和费用由程序采集。源码准则帮助组织反馈，不直接提供最优动作标签。

当前实现是 `sparse_terminal`：终局分项聚合后给最后一条转移写奖励。本次检索对照采用全局证据交付目标与实际调用数成本，保留模块诊断；局部辅助权重为 0。视觉教师实际字节传输和返回用量显式绑定已接线，真实视觉教师、逐 Unit 稠密奖励及内部用量全采集仍未完成。

系统级保留 AgentDojo 现有参照；优先考察 τ 系列文本知识任务、VisualWebArena 和 GAIA 的适用外部任务，WebArena、AppWorld、AgentBench 等按能力匹配扩展。各自使用固定版本的原结果判据，训练与独立最终评价分开。完整候选表、提示词、公式、配对／组合实验、Benchmark 来源及实现清单统一维护在[Harness 候选与两层评价方案](Harness候选与两层评价方案.md)，不在多份文档重复维护细节。

### 0.7 本轮补强：决策机会、共同表示与净收益

研究目标是让训练中积累的调用经验转化为在线廉价选择，不要求逐请求最优。三个证据支点是：拆分是否开放有用决策、调度是否有效购买信息及调用能力、变化后是否减少学习代价。四来源数量不是成功标准，已有完整入口也不自动构成拆分贡献。

详细规格集中维护于[候选与两层评价方案](Harness候选与两层评价方案.md)：PaperGraph 粗细边界、共同表示、真实决策机会、教师可靠性及适应／净收益分别记录。共同表示和检索两层评价已接线；本次九个程序反馈训练及冻结结果没有显示 RL 优势。PaperGraph 细入口、跨来源组合和教师可靠性仍为 NOT_RUN，详见[本次结果](四候选接入与真实实验.md)。

同类任务内是否存在可重复的条件收益差异，是训练问题而非选材承诺。单步材料比较同信息的简单策略／上下文学习，多步材料再研究信息改变后继选择；阈值和规则也允许同预算调整。扩池保留旧配置结果并使用独立评价材料，不能反复按最终成绩加模块直到 RL 获胜。全部尝试和成本保留，但还需处理缺反馈集中在特定动作或难任务的偏差，不能只报已判定样本。

### 统一 RL 实验中的环境与能力来源

首个可直接选用的预置使用 [AgentDojo](https://agentdojo.spylab.ai/) workspace 套件、benchmark v1.2.2，在工具结果事件上选择原 TransformersBasedPIDetector 干预，并同时记录任务效果与成本。它是首个预置，不是平台唯一允许的训练场景。任务／攻击子集、固定来源 SHA、原模型／配置及资源路径保存为运行配置，具体接线见[实施计划](../../想法/16_SeamPact平台改进实施计划_2026-10-09.md)。这里研究何时激活及如何调度，原防御算法不变；suite 版本和源码 SHA 分别记录。

AgentDojo 整体是任务与评价环境；被选定的 agent pipeline／防御组件源码才是分析器的接入输入。不能把整个环境包装为一个 Unit，就据此宣称完成异构内部拆分。AgentDojo 本身已有模块接口，因此它适合提供训练闭环；分析器异构性仍需由上表及其他真实来源支撑。

原检测器是历史初始候选，完整实现共用场景事件、Unit 契约、候选特征及评价资源。2026-10-19 已按用户指令清空旧当前池，历史 AgentDojo 记录保留；本轮三项人工包装来源也已摘除，干净原库已重新交给分析器，结果以实际记录为准。此前人工辅助检索使用程序反馈，教师提示词等待用户前端输入。能力池按实际适用事件和义务形成快照，不把不相关能力强行放入同一事件。

模块留出至少需要两个不同真实来源且有自然适用任务；更有力的配置是训练池含两个已见来源，另留出第三个来源。只具备一个检测器时可以报告该场景的链路结果，但模块迁移证据仍未取得，不把这些结果当作完整主张的替代。第二来源的原动作、资源、适用事件与证据必须核对；同一底层模型换包装／阈值不单独证明生成式行为异构。

本轮已核对以下具体原入口，作为接入与选材依据，尚未成为可运行实验池：

| 来源／原动作 | 所需事件及机制差异 | 作为实验材料的条件 |
|---|---|---|
| AgentDojo 原 TransformersBasedPIDetector | 工具结果交给原 Agent 之前；原本地分类模型及消息处理 | 原任务／攻击判据用于独立结果，原模型与环境需实际可用 |
| [NeMo ABC 原 self_check_output](https://github.com/NVIDIA-NeMo/Guardrails/blob/4512d081cb970be8a99ac2ccd1c6a39b1a81d352/nemoguardrails/library/self_check/output_check/actions.py) | 业务输出交付前；原文字政策、LLM 调用与允许／阻断结果，固定本地源码已核 | 绑定原模型、提示及解析；按原输出政策选任务与独立评价，不挪作工具结果注入检测 |
| [LLM Guard 原输出 Toxicity.scan](https://raw.githubusercontent.com/protectai/llm-guard/main/llm_guard/output_scanners/toxicity.py) | 业务输出交付前；原毒性分类器，可在毒性／辱骂维度与 NeMo 输出检查共同适用 | 尚需固定源码修订、模型资源及该维度的独立结果依据；不等同 NeMo 全部输出政策 |

NeMo 输出动作提供第二个已明确的异构来源入口；LLM Guard 输出扫描器是同输出事件的留出候选。两类事件分别报告，输出池实验只比较共同适用的维度。原 Guard 的 allow／block 记录实际干预，不作为它自身正确性的最终真值；输出评价材料未取得时，该项迁移仍列为未运行。把原固定调用改为策略可选需声明新任务政策，结构保持证明不覆盖这个政策变化。

另核对 [LLM Guard 的文档扫描用法](https://protectai.github.io/llm-guard/tutorials/notebooks/langchain_rag/)：其默认 PromptInjection 与 AgentDojo 原检测器使用同一底层模型。它可用于比较不同代码封装接入，但不作为行为独立检测机制留出的主要证据。当前仍缺第二个底层独立、同工具结果事件且原入口已核的干预，不能用改名或复制配置补齐。

场景中的三种对象分别记录：

| 对象 | 在本研究中的用途 |
|---|---|
| 原任务、工具及会话状态 | 环境交互与正常任务完成判定 |
| 原 pipeline／防御代码 | 分析器输入、候选 Unit 及执行开销；固定其算法与配置版本 |
| 攻击目标与终局判据 | 独立最终评价及单列程序反馈参照；论文教师主臂不读取终局标签，不作为决策前状态 |

由[攻击目标判据](https://github.com/ethz-spylab/agentdojo/blob/main/src/agentdojo/base_tasks.py)实际求得时，`security=True` 表示目标达成。[benchmark 源码](https://agentdojo.spylab.ai/api/benchmark/)的部分上下文超限／服务异常分支也强制置真，DoS 则用 `not utility`。保留原值及产生原因，区别原版计分与确认的目标达成；无攻击同名字段不能作安全标签。若当前目标的关键结果未知，保留该次交互及费用而不将其纳入要求完整终局回报的训练批次；最终评价仍报告完整分母及原版计分口径，不自动记作防御成功。

平台已确定的必需工作通过合法动作约束落实；允许按需激活的防御才进入策略取舍。原 pipeline 中原本无条件必需执行的防御，若被改为可跳过，应明确列为新策略的允许变化，不能同时声称它与原固定防御策略完全行为等价。0.9.0 已增加透明 Unit 角色与独立于业务模型申请的场景事件入口，业务工具视图排除透明项；具体义务和合法候选仍须由场景契约明确配置，不能仅凭“透明”身份推定为必需或可选。

正常任务与攻击任务分开汇总，再报告选定混合负载。训练状态仅包含当时真实可得的低成本信息；攻击身份、隐藏触发真值、最终任务结果、当前尚未执行的重检测输出不进入决策输入。已有轻量观测的获取费用计入成本。

### 其他 Harness 与任务场景的接入

Harness 是能力来源，场景是一次明确的任务环境与决策配置，两者不按名称一一对应。用户可以继续分析并安装其他 Harness，再从能力池选择兼容 Unit 组成任务配置；一个场景可以使用多个 Harness，同一 Harness 也可进入不同任务与评价条件。前端及通用训练接口不将 `workspace`、提示注入字段或特定检测器名称写成必填条件；AgentDojo 的这些字段留在其预置配置和有限接线中。

自动分析安装只说明得到某些可执行入口，不等于已具备可训练环境。训练配置另需明确：任务输入及初始状态／重置方法、真实决策触发、当时可得观测、候选及合法条件、必需工作、独立结果反馈、决策接续与任务结束关系。现有配置和端口能表达时直接挂接；原宿主的事件或状态无法在当前支持范围表达时，需要相应的有限桥接，或如实列为尚不支持，不承诺任意源码零适配。没有可变合法选择的来源仍可用于接入研究，不进入策略收益比较。

通用任务、质量和成本指标与安全扩展分开声明。各指标保存稳定指标键、语义及版本、单位、优劣方向、适用任务范围、聚合方式和分母；安全场景另绑定相应攻击条件与独立判据。没有安全判据的任务不显示攻击成功率为 0，而标明不适用或缺少判据；不同语义、单位或分母的同名指标不直接合并。具体配置和运行身份以[实施计划](../../想法/16_SeamPact平台改进实施计划_2026-10-09.md)为准。

## 4. RQ1：自动接入比较

分析输入统一为仓库修订、目标任务／原入口说明、所请求的操作、真实配置与资源位置、允许宿主及公共工具。比较前写清交付目标：例如保持原流程的整体接入、在原位提供可排期边界，或在允许条件下导出入口；方法之间接受相同目标，不拿整体包装的时间与完整内部拆分的时间直接比较。生成器从零探索，不读人工边界答案、已生成候选或最终判定。已经参与当前开发的四源用于开发，不作为未见来源证据；新增来源选定后封存，公开预训练可能见过这些仓库，论文需如实说明。

| 对照 | 定义 | 是否已具备 |
|---|---|---|
| 通用工具 Agent | 同一模型、源码工具、可生成形式；依据一般适配说明提出入口与代码，再接受共同独立执行判定 | 计划实现比较臂；未运行 |
| 通用工具 Agent＋同检查器 | 与完整方法同宿主、同源码事实、同 W／H／R、同构建器及精确反馈；使用普通反馈修正，不提供目标操作的专门分析组织 | 关键强对照，计划实现；不能只给它弱类型检查 |
| SeamPact 完整方法 | 当前操作规则、构造／状态／控制分析与具体缺口反馈的完整工具循环 | 当前实现；现有记录是开发运行 |
| 专家人工适配 | 根据相同交付目标分析原代码并改写接入，保留原算法，记录时间、改动和干预 | 计划采集；不是唯一正确分区 |

所有比较接受同一独立判定，不能用 SeamPact 的 READY 标签当真值。普通 Agent 提出的候选若不满足执行条件，记作未兑现，不在原服务上绕过必要限制。不要把自建参考臂称为 HarnessX 等原论文系统的复现；若后续添加现有系统基线，要先核实其公开实现与实际能力。

默认 API 额度、轮次与上下文继续不限。比较统一模型版本、工具、上下文保留、来源事实和人工停止规则，同时报告消耗。不能在不等预算下只比较成功率并把差异归因于规则；给出完成度—tokens／调用次数／时间的关系。若需要严格预算实验，作为单独研究条件商定，不修改平台默认配置。

先对每个选定来源／方法做 3 次独立新会话，用于看跨会话变化；后续论文数量按实际方差与目标差异补足，不把 3 次重复当稳定显著性的依据。重复中的缓存提供条件相同，候选记忆不跨方法共享。提供方未支持 seed 时明确记为不可控。

### 统计单位与指标

目标操作记为 `(source_revision, original_region, requested_operation, host_profile)`。多个候选描述同一源发生与操作只计一个；同一逻辑操作的粗／细替代版本不累加能力数。

- **任务兑现率**：成功执行预先指定任务的数量／全部指定任务数量。缺资源、未支持、分析失败、运行失败分别列出；另给资源齐备子集的条件成功率和分母。
- **有效边界率**：独立确认可执行且完成所请求操作的边界／生成边界。包装整个入口、内部原位调度和独立导出分别统计。
- **误开放**：系统声明某项操作可用，但独立判定其前提或实际行为不满足的比例；“未运行”不按运行成功处理。未决独立判定单列。
- **漏得能力**：专家已有可行依据、方法未获得的目标操作／专家可行操作。未支持的语言／宿主单列，不偷换分母。
- **自动化成本**：模型／工具调用、tokens、墙钟时间、候选修正、人工输入配置时间与人工修改代码时间。时间从取得共同输入计至首次获得有效产物；未成功者报告已消耗时间与未兑现原因。零人工边界不等于零人工资源准备。
- **方法准备与接入复用成本**：通用规则／工具开发和人工参考建立的投入单列；新来源的边际接入成本单列。给出对已接入来源数的累计成本及摊销关系，避免把框架准备成本隐去，或把一次性准备费用重复计入每次运行。

人工少量案例用于说明具体开发投入时，明确参与者经验、辅助工具和计时口径，报告为案例研究；没有足够人员与任务覆盖时，不外推为普遍的人效结论。可运行能力的数量不是越大越好，结合任务需要和实际支持的操作解释其价值。

报告来源宏平均和完整逐源表。来源内多个任务相关，不把所有调用当独立样本获得虚假的窄区间。需要区间时按来源／会话的层级配对重采样，并报告样本少时的不确定性。

## 5. RQ2：原行为保持与真实组合

形式化与经验观察分别回答两个问题。形式化对象是冻结源修订、观察契约、受支持宿主及规则前提下的变换：在对应外部响应与随机选择的耦合条件下，保留声明的可观察行为。实际来源上的成对观察回答实现是否覆盖这些规则及其前提；有限运行结果不能代替全称证明，规则的定理也不自动覆盖规则外的任意程序。证明义务以[20 数学规格](../../想法/20_形式化定义与证明义务.md)与[21 构造规则](../../想法/21_拆分接入的构造语义与规则实例.md)为准。

论文分别列明：规则及其前提、可观察行为与结论、对应构建形式、真实来源覆盖、未决前提。Agent 提出的候选由规则检查和构建机制提供依据；模型置信度、`READY` 或 `SOURCE_BOUND` 标签不替代证明。

每个已能运行的原流程先定义观察契约：返回值／异常、相关原状态、外部请求次序、文件写入及原超时范围。原入口和接入入口使用相同源修订、输入、模型、配置、初始状态与数据，由原实现作为保持参照。随机模型响应无法严格耦合时，先对原发生使用明确标记的响应记录观察结构保持，再用真实服务单独报告任务质量与费用；回放结果不算真实模型质量或时延收益。

覆盖三种有差异的路径：直接原入口；带实际构造器／工厂／共享对象的入口；包含 if／loop／try 的原位调用。用原 callable 的实际启动、原返回／异常和后续控制证据判断，生成的 adapter 或模型自己的“等价”说明不作判定。当前 `starts`、receipt 和退休记录可帮助观察，但它们由平台产生，正式论文还需要来源侧的独立依据。

组合使用事先写清的 TaskSpec：输入、需要哪些实际操作、输出与拒绝／失败要求、质量判据。先做源内数据处理→原评分／归约等真实链，再选择业务兼容的跨源任务；不能只因两个 schema 都是 string 就要求视觉校准器与数学评分器任意互接。原生对象边与 JSON 边分开，记录初始化、引用身份和效果。没有自然跨源任务时如实报告，不能用重复加前缀替代。

固定参考策略下的拆分保持，与新策略的调用选择分别陈述。RL 跳过允许取舍的防御、选择不同配置或构造不同任务方案时，需保持任务义务及各项操作前提，再由独立结果判据评价效果；不要求其轨迹等于某一个原固定 Harness。不同流程的组合满足共同 TaskSpec，也不等于与其中任一原流程具有完全相同的语义。

针对本轮已经观察到的固定样例输入缺口，检查不同真实任务输入能否到达原函数。针对状态与控制机制，选真实会话／对象共享、原分支不启用某调用、原异常停止后继等案例。每个案例改变一个相关前提，保留原算法；研究发生关系，不优化来源模型。

**主要指标**：满足观察契约的成对任务比例、漏／重复原发生、异常／后继偏差、实际数据边兑现比例、完整组合任务完成率。确定性结构观察与最终内容质量分栏。AST 可逆检查是变换依据，不等于任意程序的行为证明。

## 6. RQ3：有效调度与经验适应

### 6.0 一套完整实现与三项主实验

完整链路是“分析器接入原 Unit→任务事件及合法动态候选→共享候选表示的 RL→原模块执行与会话继续→文字标准教师反馈及实测成本→版本绑定的学习／适应”。AgentDojo 桥只转换任务事件、原对象和评价材料，学习器不包含其来源名称、`utility/security` 字段或检测器名称分支。同一代码和配置入口用于下列实验，不把专用调度器作为单独交付目标。

| 主实验 | 具体问题与安排 | 主要比较及证据 |
|---|---|---|
| 完整链路效果 | 固定来源池，在未参与调参的正常／攻击任务上冻结运行；主方法训练语义反馈来自教师 | 完整方法、适用固定策略、同学习器的程序反馈参照；独立任务／攻击结果、成本及教师覆盖 |
| 真实模块留出与池变化 | 按真实实现／来源家族划分已见池与未见模块，新增、摘除、替换分别运行；事件不同时另列条件 | 冻结策略的零新交互结果、同一预训练工件的有限适应、目标池从零训练；新交互—效果—总成本曲线 |
| 判据变化后的经验利用 | 执行环境和候选不变，改变有独立最终依据的结果标准；历史材料满足新证据要求 | 相同起点的直接热启动与条件重评适应，另列从零；固定一种支持 replay 的学习器，计入重评费用及新旧任务表现 |

分析器接入比较继续回答 RQ1／RQ2。三种学习器在开发条件下比较后确定主配置；教师自由总分／结构化反馈、程序反馈作为定向消融和强参照，不与所有来源、攻击、算法做全组合。判据重评研究在 Double DQN／离散 SAC 中按开发材料固定一种；PPO 保留正常的新 rollout 路径，不为统一表格改成消费历史重评数据。

#### 6.0.1 训练反馈与独立评价的信息边界

通用架构允许适用程序判据直接供学习使用。论文主方法另明确研究“接入方提供文字标准与可读证据、训练侧没有现成终局程序标签”的反馈条件：教师读取用户任务、授权范围、实际执行轨迹、最终结果及该标准声明的参考／状态材料，输出语义分项；成本仍由程序实测。AgentDojo 的官方终局 `utility/security`、攻击成败布尔值及其等价标签不作为教师输入，不通过抄写标签制造判断准确率。

官方程序结果在实验侧用于独立最终评价和教师误差分析；使用官方结果训练的同算法单列为程序反馈强参照。这个参照具有更明确的训练标签，不称为性能上界，也不据此声称已有廉价程序判据时一定应换成教师。教师各比较臂获得相同允许材料；实际环境状态或参考事实若允许训练教师事后读取，应固定清单并计入取证成本，它们不提前进入在线调度观测。

教师只有文字标准但看不到相关后果时仍应 UNKNOWN。隐蔽攻击或证据不足导致的低覆盖属于反馈可行性结果；需补足真实可读证据或缩小支持范围，不能偷偷改用官方标签填补完整方法。教师失效任务仍计入总交互和费用，独立评价按可获得的真实判据覆盖调用与跳过后的任务结果。教师反馈接口便于评价接入，但泛化还依赖表示和训练覆盖，教师不是泛化的必要或充分条件。

#### 6.0.2 留出单位与可复用材料

预先保存任务、攻击、来源家族和模块修订的开发／训练／独立评价清单。相同任务模板的近重复、同一攻击载荷变体及共享核心实现按组分配；共享模型底座或人工接线如实标记。主配置与超参数在开发材料确定，适应材料和最终效果材料分开；最终任务不用于教师提示词修改、模块特征设计或重评规则选择。

| 留出对象 | 能支持的结论 |
|---|---|
| 相同环境中的新任务／攻击组 | 所声明分布变化下的任务泛化；不等于新 Harness 接入 |
| 未参与预训练的真实模块／来源家族 | 候选能力增减后的复用与有限适应；模块按原适用事件参与 |
| 第二种真实任务／交互环境 | 跨环境适用性；AgentDojo 换 suite 本身只说明其内部任务迁移 |

同一环境里来自不同来源且适用同一事件的模块可直接研究候选池变化。若新模块只能作用于输出，而原模块作用于工具结果，分别报告事件变化、来源变化和接口补充，不能把二者当成同位置的可互换防御。至少两个真实来源可以做双向留出，但不能据此宣称多来源预训练后的广泛零样本能力；两个已见加一个未见的配置用于更直接检验这种假设。

前端为每次运行选定任务／池快照、反馈提供者和预训练工件，已有哈希与时间身份保留这些材料。新增模块的能力说明、支持事件及已知配置可以进入候选特征；未运行检测结果、该模块在最终评价任务上的成绩或未来成本不得预填为特征。新来源保持共同特征规格，确需改 schema 则创建新版本并重新核对工件兼容性。源池得到的参数、轨迹及评价资源保留，在兼容范围内按第 6.4 节继续使用。

### 6.1 决策问题与可比较条件

已有 functional/1 固定下层 FIFO，只训练上层透明安全干预选择；本轮 joint/1 增加合法就绪派发与水平扩缩等生命周期动作，共享候选评分和同一工作负载回报。共同候选约束先落实必需工作、依赖与原执行条件，学习器选择允许取舍的原防御或配置；普通业务模型主动申请能力的接口仍与透明安全触发分开。两层为职责划分；联合模式也不要求两套独立策略网络。FIFO、基于历史耗时的短作业优先＋共同年龄保护、学习派发分别比较；真实 deadline 存在时才考虑 EDF。详见[联合规格](部署前建设与调度动作方案.md#52-功能派发与生命周期联合模式本轮建设目标)。

先记录每次决策的合法候选数。安全策略取舍需确有至少两个合法选项；同一任务有多个完整可运行方案才评价上层方案选择；有多个已使能合法发生才评价下层排期。原控制分支尚未激活的调用不能为了制造动作空间提前使能。当前同源两步前缀只有一个动作，不进入收益表。

若每个任务只选择一次防御方案，且此选择不改变后续决策状态，可用上下文 bandit 建模及比较；若多次选择改变后续观测、控制路径、预算或等待，才据此采用多步 RL。终局奖励延迟本身不构成多步问题。最终以接入场景中的真实决策事件确定，而不为使用复杂算法人为增加决策步骤。

策略选择与结构准入分开。原依赖、owner、资源、必需工作和各项操作前提形成所有方法共享的合法动作约束。接入方结果判据描述任务与安全结果，用于反馈，不提供逐步理想动作标签。程序与教师共用结构化反馈，平台／任务方负责共同目标、任务义务与聚合。主实验采用第 6.0.1 节的教师语义反馈条件及实测成本，程序终局反馈单列参照；部署方已有适用判据时仍可通过同一接口直接使用，不要求每个模块手写精确奖励公式。

教师默认用于训练、有限后训练及适用的结果重评价，不要求冻结调度在线调用教师。它不修改必需工作或学习器更新代码，不自动生成执行任意奖励程序。准则、证据输入与输出定义、程序／教师配置和聚合方式在运行内冻结，修改后创建新运行及内容身份。共同反馈保留原分项、判定、证据和未知原因，不能仅保留单个教师总分。教师自报置信度不当作校准正确率，也不直接参与自动加权。UNKNOWN／评判失败涉及当前目标的关键分项时，该任务保留在交互预算、费用及最终指标分母中，但不进入要求完整终局回报的训练批次；NA 仅按任务适用契约排除，教师无权自行免除指标。

攻击风险、正常任务效果和成本分别记录。初版采用加权奖励，分项尺度、系数与风险参考均作为可编辑运行配置保存，不等待先找到最佳数值才实现训练，也不在方案中擅填数值。风险参考只用于结果筛选／标记，不参与本版学习器的约束优化；这不构成约束 RL 或逐请求安全保证。必需工作仍由执行约束保证，不能因奖励或风险参考而省略。新场景不沿用旧的“调用正常完成”作为安全成功。

### 6.2 基础方法与选型

| 比较臂 | 作用与条件 | 当前状态 |
|---|---|---|
| 适用且合法的可选干预全开 | 在不违反依赖、适用条件和互斥条件的范围内执行可选干预，提供该配置的效果与开销参照 | 0.9.0 已有 `all_applicable` 固定参照；新场景需绑定，互斥方案明确固定选择，不能声称同时全开 |
| 仅完成必需工作 | 保留全部必需工作，不额外激活允许取舍的干预，提供额外干预的增量参照 | 0.9.0 已有 `required_only` 固定参照，新场景需绑定；不是关闭既定安全义务 |
| 轻量信号阈值策略（条件适用） | 来源已有可用轻量信号时，在开发材料中确定阈值，并计入信号获取成本 | 条件性对照；无信号不虚构规则，不称为已实现的强规则 |
| 现有表格 Q（可选） | 旧实现作历史参照；接入相同观测、动作、任务与安全反馈、预算后才构成有效学习器比较 | 已实现旧目标；不要求每次主要实验都运行 |
| Double DQN | 使用共享候选表示，在当前／后继合法候选集合上进行离散价值选择与更新 | 0.9.0 已实现并接入共同训练接口；效果须由真实场景运行取得 |
| PPO | 使用相同观测和候选表示，对合法候选给出策略概率并按本算法收集轨迹与更新 | 0.9.0 已实现，消费当前策略的完整可用 rollout，不消费历史重评 replay |
| 离散 SAC | 使用相同观测和候选表示，对离散合法候选实施相应策略、价值及熵项更新 | 0.9.0 已实现，温度显式配置；不直接使用连续动作 SAC |
| 完整方法及机制消融 | 同一基础学习器接入可维护教师反馈、版本绑定与条件适应；改变一个研究因素比较 | 共同反馈与保守适应路径已实现；机制收益与消融结果仍须真实运行，不宣称已有新 RL 更新算法 |

共享候选评分是一种表示方式，与使用哪一种 RL 更新算法分别说明。Actor-Critic 是方法家族；PPO、SAC 的归属不能当作彼此独立的四类算法。动态候选比较既要核对选择时的动作集合，也要保留学习所需的后继合法集合。

多学习器是前端支持范围和开发配套，不再把“在一个检测器上选出最好算法”作为论文主要结果。未发生标准／来源变化时，完整方法与相同表示、反馈及训练条件的同一基础学习器可能是同一更新过程，应合并呈现，不重复命名制造方法差异。

当前代码没有独立可选的“规则策略学习器”。现有源码检查、必需工作、合法候选过滤和 owner／资源限制是所有方法共享的执行约束；FIFO 是功能模式的共同排期条件；联合模式显式比较排期策略，规则准入不能包装成某个基线的专有优势。上述固定策略无需训练，作用是回答“学习是否比简单选择产生额外价值”，不用于证明某个基础 RL 更新算法优于另一个。

历史 Q 参数保留为 `α=0.2, γ=0.9, ε=0.1`，奖励是成功 ±1 减去 `t/(1+t)`，其中 `t` 为秒（`duration_ms / 1000`）。它衡量旧调用／方案完成及其时延，不覆盖新的安全结果判据或最终任务质量。其原配置仅作历史实现事实保留；0.9.0 已实现的 functional/1 三学习器消费共同分项和显式目标配置，下层统一 FIFO，不以旧目标的表格 Q 结果冒充同目标算法比较。

先在开发任务中选择基础算法与超参数，再固定配置并在独立评价任务上比较。所提方法必须与未改进的同一基础算法比较，保持可观测信息、候选能力及合法约束、训练交互预算和资源条件一致；新增表示或预训练数据带来的费用单列。不能在最终评价集上选择基础算法、调整方法后，又将同一批结果用作独立优势证据。

训练与成本画像使用开发材料；独立评价冻结策略并取消训练探索，继续在线更新则作为另一研究条件报告新增交互与成本。0.9.0 前端和接口已加入三种学习器的从零训练、同算法继续训练与冻结运行，以及明确选择已有策略的原场景任务；冻结工件不自动改写任意自由对话的任务定义。独立种子安排统一按第 0.4 节：初始比较使用 3 个已记录种子，正式规模依据开发材料确定并在保留评价前冻结。实际运行数、episode 数和停止口径保存为运行配置，不将该数量当作显著性保证。

各学习器使用同一场景、任务／攻击集合、原模块、模型与判据修订、低成本观测、候选表示及合法动作空间，并给予同等环境交互预算；逐次运行重建独立任务／会话初始状态。比较运行逐个顺序执行，不让多个学习器并行改变同一环境；真实服务的运行顺序按研究条件安排并记录，不能将服务负载漂移当作算法收益。除环境交互数之外，分别报告梯度更新次数、PPO 轨迹收集、经验重放利用及其费用，允许算法按其正常数据条件运行，不强行规定完全相同的优化步数。

PPO 用当前策略所收集的轨迹及相应概率进行更新，旧 rollout 不直接作为新策略可无限重放的数据。Double DQN 与离散 SAC 可利用重放，但经验中的观测、当前及后继候选、所选动作、模块／配置／判据及目标含义必须与当前学习条件相容；发生变化时不能仅因 schema 相同就继续使用旧奖励。算法之间不互载权重；普通同算法继续训练与所提经验适应机制分别报告。

### 6.3 拆分与调度的整体联系

比较“保持整体封装接入＋对应最强可用调度”和“拆分接入＋受约束调度”，使用相同任务要求、原模块、模型、资源及结果判据，分别说明它们实际能够提供的合法决策入口。该比较允许动作空间不同，目的是测量拆分提供的决策机会；基础 RL 之间的算法比较则固定同一合法动作空间，两种比较不混用。

记录收益来自何处：省去允许取舍的调用、选择更合适的配置／方案、复用结果，或改善已使能调用的等待。与只改变基础 RL 的比较配合，区分表示／能力空间贡献与学习算法贡献。任务负载采用相同到达序列、内容与资源条件，涵盖空闲及请求排队、短长任务混合、正常与攻击任务。跨策略切换真实服务的执行顺序，以减小共享服务器负载漂移；来自其他用户的 GPU 占用记作环境协变量。当前托管配额为 1 的串行选择不等于源内并行。

每个细粒度例子必须附原入口、规则／导出依据、原与新动作、获准取舍来源、信息时点和接续覆盖。功能模式的下层 FIFO 与联合模式分别报告；内部多了交接点却没有真实竞争／选择时，不主张排期收益。PaperGraph 的逐主张调用仍为待核对的导出候选；原核验循环依然全部执行，新 TaskSpec 允许部分核验时才研究逐项取舍，并报告未核验和抽取遗漏。细入口全执行对照检查保真；共同新任务中的粗／细策略对照检查自由度价值，两者分别解释。

共同表示对照使用同一学习器：现有结构向量、能力语义卡与任务匹配、必要的冻结内容表示。候选数可变不等于能识别新能力；相同数值输入的候选在当前共享网络中不能凭名字得到不同分数。表示接线、真实来源留出和相关开销均须单独取得证据。

#### 6.3.1 首个贯穿实例与表示诊断

优先实例为 PaperGraph 原核验区域：抽取／筛选主张，按原序逐项检索＋核验，归约返回。比较同一区域的整体版本和获准细化全执行版本，保留全部原义务、owner、状态与异常；同次发生粗细互斥。分析器产生的交接、覆盖、冲突及输出可见性关系决定合法方式，当前队列、预算、已取得证据决定方式的价值。空闲时可能整体协调更省，有其他合法独立工作等待时可能细化穿插更好；锁／效果冲突仍阻塞时，后者不成立。详见[完整实例](Harness候选与两层评价方案.md#26-贯穿实例papergraph-同一区域的整体与细化执行)。

先冻结一个真实开发输入及原区域，取得获准粗细工件，再记录新增信息／机会、实际策略选择、最终独立质量与完整成本。原位许可不自动发布结果；入口选择不读取未来主张／verdict，不在执行中换粒度。现有场景配置不等于细化已可运行，机制实例仍为 PROPOSED。

代码核对确认当前逐候选评分；PPO 状态价值读取合法候选特征均值。新版表示已有结果类型和局部运行摘要，仍需检查共享状态／owner、完成后解锁、互斥覆盖与信息时点是否丢失。开发集寻找局部特征相似但关系与合理选择不同的真实状态对，分别诊断单候选评分、集合价值与历史；再决定关系表示、价值估计或求解器改进，协议见[第 6.6 节](Harness候选与两层评价方案.md#66-候选关系与价值估计的开发诊断2026-10-25)。

诊断顺序为：路线近似无差别先查选择价值；有差别而观测不可分先补信息；简单策略已很好先查长期需求；简单策略短视且 RL 学不好，再核实反馈并研究信用分配／求解器／样本效率。补高质量人工合法接线，固定接线比较策略、固定策略比较接线，区分自动边界缺口与利用不足。人工臂经同检查、投入另计、答案不提供给自动臂，不当理论上界，见[第 10.6.1 节](Harness候选与两层评价方案.md#1061-学习提升空间的诊断顺序与人工参照)。

### 6.4 经验复用与变化后适应

围绕主问题选择有真实执行依据的一种变化开始：接入一个新 Harness／模块、已有能力配置发生变化，或接入方修改结果判据。变化类型分开报告，不能将换任务、换模块和换奖励混成同一个“泛化”结果。新增／摘除来源的工程功能也不等于策略已经具有迁移能力。

判据变化须预先写明旧标准 C0、新标准 C1 的语义差异及各自冻结的独立最终评价依据。新要求超出原 utility／security 覆盖时，补充相应独立参考，不能以旧 oracle 或训练教师自身分数验证新要求。仅等义改写提示词属于教师稳定性研究；仅改变已保存完整分项的权重，可直接重新聚合，作为低成本参照，不把该收益归因于教师重评。重评价实验选择确实需要重新判断且历史证据充分的新语义标准。

模块留出使用第 6.0.2 节保存的真实源池和目标池；冻结零新交互结果单列，有限适应以新交互量为横轴。在同算法比较中，直接热启动与完整方法使用相同预训练工件、新任务／反馈和预算；从零使用相同目标任务预算并报告预训练投入差异。无可比较旧工件或事件／特征不兼容时，如实报告适配范围，不把重新设计观测和动作接口后的训练称为同一策略零样本迁移。

| 比较方法 | 起点 | 变化后使用的信息 |
|---|---|---|
| 从零训练 | 相同初始化分布下的新策略 | 相同数量的新环境交互 |
| 直接继续训练 | 原策略与原训练方法 | 相同新反馈与交互预算 |
| 最小适应机制 | 原策略；版本绑定、保守兼容筛选、有条件重评价后按原学习器继续训练 | 相同新反馈；兼容性依据、旧经验使用／重评价及教师和计算费用单列 |

本轮确定的最小机制采用保守复用范围：执行环境、模块及配置、观测／动作语义和候选范围仍适用，仅结果判据或聚合改变，且历史材料包含新准则需要的证据时，才重新评价已执行结果。Double DQN／离散 SAC 还需满足各自 replay 数据条件，PPO 重新采集当期 rollout，不将换分后的旧轨迹当作 on-policy。能力池、模块或环境改变及兼容性未知时，默认保留兼容参数作为起点、采集新经历，不自动复用旧转移。结构契约兼容不能推出防御收益相同；相同结果判据也不能保证替换模块后的行为相同。

因此，能力池或环境变化时，首版最小机制可能与直接参数热启动采用相同的数据路径，应如实报告而不预设额外收益。要辨认条件重评价的作用，应另选符合上述兼容条件的判据变化，并在支持相应 replay 的学习器上比较；PPO 的历史重评不作为该作用的训练证据。

这是已确定的实现机制及待评价的收益假设，尚无实验结果，不先命名为新 RL 算法或元学习。反馈提供方式与适应机制作为两个因素分别比较；不能把换用更强教师、更多交互或不同目标所造成的收益全部归因于经验处理。

报告变化前后的完整学习曲线、新交互量、旧与新任务上的效果、总费用与耗时。目标性能阈值若要用于“达到目标所需交互数”，在开发材料中预先确定并完整公开。历史轨迹只有保存了新判据所需事实时才能重新评价；保留旧分数、新分数及其判据身份。重评价不补出未执行动作的反事实，不替代新模块改变路径后的真实交互。仅在上文条件成立、数据处理与算法路径已实现后，比较保留旧分数、重新评价和不使用历史转移；旧分数与当前目标不相容时，保留为诊断参照，不视为有效同目标训练方法。

### 6.5 结果指标与结论范围

混合任务归一到 [0,1] 不代表每类一分等价。正式选型先冻结类别／到达占比、训练与评价权重、各类独立质量最低要求；采用非劣比较时预设参照与可接受下降界限。按共同费用预算比较各类质量，满足各类要求时比较费用／时延；稀有类别单列，整体回报不能抵消某类未达标。数值待开发依据，不由本次修订代填。这是评价与选型规则，未新增约束 RL，详见[分类协议](Harness候选与两层评价方案.md#1041-各任务类别的质量要求与选型规则)。

各类已到达、完成、执行失败、截止未完成分别报告，另列评价缺失／UNKNOWN、原因和覆盖率；评价缺失可与执行状态重叠。失败按原任务规则计分，不可判定语义结果不补零；教师训练分与独立质量始终分列。质量相当／非劣需预设界限及区间支持，没有达标配置时不报告等质量节省。

正常任务报告任务完成率、质量分数及不必要干预的影响；攻击任务报告攻击成功率与受攻击时的任务完成率。两类均报告端到端时延、模型／工具调用与费用、重模块激活频率及失败／未完成数量。任务质量包括防御对输入、工具返回、上下文、拒绝行为及后续控制的实际影响；“透明模块”仅表示业务模型不决定其激活，不意味着没有质量或成本影响。

上述安全指标仅适用于提供了对应条件及独立判据的场景。其他 Harness 使用其任务配置声明的质量和成本指标，并可增加有明确含义的领域扩展。前端按指标声明展示和比较，不依赖某个预置的固定字段；仅在语义、单位、适用范围及分母兼容时汇总，缺失、未知和不适用分别保留。

攻击评价单元按预先选定的用户任务、攻击目标、攻击方法及重复运行标识固定，并报告完整数量。正常任务失败、未启用可选防御、异常或未触达实际注入位置均不作为事后删除样本的理由。遵循固定原版计分时同时报告异常处理口径和数量；另报有真实目标判定的子集时明确其分母，并保留全量结果、未知及缺失原因。不能把未知直接当作攻击失败，也不能用只统计成功完成的任务来改善攻击成功率。

排期指标保留平均／p95 等待、同样负载下完成任务数、最长等待和各任务类别分布；小样本不报告 p99。成功任务时延之外必须给失败／未完成数量。总成本包含轻量观测、判据调用、训练交互和分析／接入摊销，并分解模型请求、初始化、许可等待和执行。奖励总分作为辅助指标，不能替代分别报告安全、任务效果和成本。

公开环境的真实调用可以支撑相应任务、模块和资源条件下的机制结论。低成本模拟／回放若用于探索策略，应说明与真实执行的校准来源和覆盖范围，结果单列；它不能替代真实安全效果、模型质量或大规模部署证据。有限跨进程已实现，通用远程、并行及 K8S 规模收益仍需对应运行依据。

### 6.6 前端操作与运行身份

扩展现有配置 dialog 与调度器观察页，选择学习器、从零／同算法继续／冻结模式、来源工件、任务预算、种子及目标配置；在页面启动运行、停止继续提交任务、将选定冻结工件用于普通对话。比较运行依次执行。修改配置只影响新运行，已开始任务的选择与反馈始终绑定原运行和学习器，不更换其在途策略或破坏原 owner 生命周期。

历史运行可选中并列展示任务配置中声明的分项指标、时延／费用、学习曲线、环境交互量及配置差异；训练探索结果与冻结运行结果分开标明。风险参考用于筛选或标记结果，不将页面标记解释为通过安全保证。运行使用 UTC 时间与内容哈希关联的不可变身份，配置、工件及续训父工件分别保留内容身份；名称仅作可编辑展示别名，不作主键或历史结果关联依据。精确生成规则与前端分类见[实施计划第 7.1、8.1 节](../../想法/16_SeamPact平台改进实施计划_2026-10-09.md)。继续训练生成新运行记录，不覆盖原比较结果；相同配置的重复运行保持独立，名称变化后仍能按原身份检索和并列比较。

页面沿用现有状态接口与刷新方式；配置、运行和工件摘要写入现有 Store，神经策略权重写入原型私有工件目录。神经 RL 为可选依赖，未安装时如实显示不可用并提供基础报错；不静默替换成另一学习器，不新增独立训练服务、自动大规模扫描或生产审计系统。

### 6.7 反馈方式的选型证据

该比较嵌入第 6.0 节完整方法，回答结构化文字准则能否在可用证据下提供可迁移维护的训练反馈。教师从首版进入同一实现，程序反馈是独立参照；不另建一个先纯程序训练、以后才接教师的专用系统。先在同一批已执行结果及共同标准下比较反馈质量，再固定学习器比较调度效果。已有程序判据的维度不要求教师一定更优，判断依据包含维护投入及新增教师费用。

| 反馈方式 | 定义与比较用途 |
|---|---|
| 原程序判据 | 作为独立最终依据，并另列程序反馈训练参照；后者获得明确终局标签，不作为性能上界 |
| 单一自由教师总分 | 提供相同任务标准和可得材料，由教师直接给整体评分；作为自由判断的对照，不减少其必要信息 |
| 模块准则的结构化教师反馈 | 同一教师读取可编辑完整准则，返回分项、状态及证据；使用平台共同聚合 |
| 所选程序／教师混合反馈 | 可计算项保持原程序，教师只补充有证据的语义项；无补充项时退化为程序反馈 |

三种教师相关方式使用相同教师型号／生成设置、共同任务目标、原结果与允许证据，显式记录各自实际提示词、调用量和 token／费用。自由总分臂也可输出无法判断，不以强迫其随意打分制造劣势。程序成本和教师预算分别报告；训练比较控制同一学习器、动作空间、环境交互量、任务／攻击样本与目标尺度。额外证据或更多教师调用若构成某一方法的一部分，列出其成本而不作为免费优势。

按研究因素选择必要比较，不要求四种反馈与全部学习器／来源交叉运行。主方法的结构化教师反馈与自由教师总分检验组织方式；程序反馈参照检验在可计算真值可用时的差距；混合提供者只在任务确有两类分项时运行。教师不会读取独立程序标签作答案，信息边界按第 6.0.1 节固定。

评价维度由任务适用契约确定，不因跳过某个可选模块而自动成为 NA。反馈材料应覆盖调用与跳过后的最终任务／安全结果；若某维度只有调用该模块才可获得依据，应明确记录未调用时的评价缺口，不能只给已调用模块评分或把该缺口解释为安全成功。

有 AgentDojo 等官方结果依据时，用其相应真值统计判断一致、错误接受、错误拒绝、未知率／可判定覆盖与费用；分项范围和分母固定，未知不能隐藏在一致率之外。覆盖曲线与错误比例同时呈现，教师自报置信度不代替这些测量。没有程序真值的语义项使用事先说明的独立参考依据，若只有代理指标，结论限定到代理评价范围，不强行凑出人工逐步动作标签。

将 UNKNOWN 保留在总分母中使缺失可见，但不会自动消除训练样本筛选或评价覆盖的选择偏差。按任务类别、威胁类别及调用／跳过选择分别报告可判定覆盖、未知和失败；覆盖不足时限定结论范围，不将已判定子集的效果外推到全部任务。

训练反馈与最终评价分别绑定。最终报告官方或独立结果、正常任务完成、安全结果、实测成本及关键反馈未知数量；不能只用训练教师分数证明方法效果。若需要维护投入证据，记录完成同一准则更新所需的人工编辑时间、配置变更和教师费用，采用同一交付目标，不把生成文字的速度等同于有效判据的获得。

本节评价的是反馈提供机制。能力池／判据变化后的经验适应仍按第 6.4 节比较，同一新目标下保持反馈方式和预算相同；修改任务目标本身时，明确区分新目标下的适应与旧目标性能保持，不把目标变容易当作方法收益。

## 7. 有针对性的机制消融

| 移除／替换 | 要回答的问题 | 保持相同的条件 |
|---|---|---|
| 用普通反馈替代具体缺口反馈 | 定位反馈是否降低修正与人工成本 | 模型、工具、生成支持范围、独立判定 |
| 固定整体 W，去掉原位／构造选择 | 可运行内部边界是否带来实际复用 | 原算法、任务、服务与执行器；明确是消融，不是最强基线 |
| 固定值核对缺失 | 业务输入接口是否被样例硬编码 | 仅比较候选判断与实际无害数据任务；不让不满足前提的候选污染外部服务 |
| 固定策略或适用的轻量阈值策略替换 RL；分别固定已有上下层选择 | 收益来自能力空间、简单选择还是学习 | 相同完整方案、合法动作、任务与服务；上下层确有选择时适用 |
| 所提方法替换为未改进的同一基础 RL | 系统相关改进是否提供独立收益 | 表示、信息、合法动作与交互预算；若表示本身是改进，单列该因素 |
| 去掉所提经验处理，直接继续训练 | 适应收益是否超过普通 warm start | 预训练起点、新反馈、变化类型与新交互预算 |
| 将结构化／混合反馈替换为单一自由教师总分 | 准则和结果组织是否改善反馈及调度 | 任务标准、可得证据、教师、学习器和环境预算；教师费用单列 |

最小经验适应机制已定为版本绑定、保守筛选、有条件重评价及继续训练；可做的具体消融随对应路径实际实现而定，不虚构已有结果或进一步算法改进。结构约束是执行前提；不通过开放违反必需工作或原依赖的动作来制造消融。完整 EXPORT／COMPOSE 证明、宿主支持扩展和联合搜索算法若后续改变，需要更新方法定义后设计对应比较。

## 10. 方法定位的公开依据

以下资料用于确定场景及比较对象，并非本平台已复现的结果。正式比较时记录实际使用的实现修订。

- [AgentDojo 文档](https://agentdojo.spylab.ai/)、[agent pipeline](https://agentdojo.spylab.ai/concepts/agent_pipeline/)及[任务判据](https://github.com/ethz-spylab/agentdojo/blob/main/src/agentdojo/base_tasks.py)：公开任务环境、组件接入和结果语义。
- [Double DQN](https://arxiv.org/abs/1509.06461)、[PPO](https://arxiv.org/abs/1707.06347)、[离散 SAC](https://arxiv.org/abs/1910.07207)：首版确定支持的基础方法；原 SAC 的连续动作实现不直接用于本研究候选集合。
- [Decima](https://web.mit.edu/decima/content/sigcomm-2019.pdf)：结构化任务和动态候选的学习调度参照；本研究不因使用共享候选评分而单独主张新颖性。
- [Reward Design with Language Models](https://arxiv.org/abs/2303.00001)：按文字目标让模型提供奖励已有研究；教师本身不作为本研究的新算法。
- [Text2Reward](https://arxiv.org/abs/2309.11489)、[Eureka](https://arxiv.org/abs/2310.12931)及[RLAR](https://arxiv.org/abs/2603.00724)：奖励程序生成、优化和多任务奖励工具组织的相关方法。本版采用维护准则和结构化结果反馈，不将这些方法的代码生成或自演化能力写成已实现。
- [PEARL](https://proceedings.mlr.press/v97/rakelly19a.html)：少量经验适应的已有研究；本研究由异构 Harness 变化中的具体复用机制及证据界定贡献，普通继续训练不自动成为元 RL。此处 PEARL 元 RL 论文与第 3 节同名来源仓库是不同对象。
