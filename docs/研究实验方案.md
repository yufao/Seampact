# SeamPact 研究实验方案

更新：2026-10-14。对象是自动分析拆分与调度机制。本文给出论文实验的研究设计；继续使用现有四层原型和原 Harness，不增加测试平台，也不改进这些来源的算法。计划数量不是已经取得的结果。

## 1. 当前事实与研究范围

0.7 已实现原生入口绑定、有限 B-CALL 构造前缀、W／H、R-INPLACE、有限循环提取、真实结果数据边与顺序控制边，以及两层表格 Q-learning。宿主范围为用户确认的 Python 3.11、本地单进程、显式生命周期和无栈观察依赖。

四个来源首次真实分析共 135 次模型请求；DiSP 利用完整原上下文再修正 2 次。一个真实对话任务调用原 `insert_token_at_start` 两次，通过 `$result` 传递第一项返回值，得到 `[B] [A] Observe the red bicycle.`。实际两次调用均单次启动、返回并退休。上层更新一次、下层更新两次；候选数均为 1。这是调用与数据边的运行事实，没有构成多粒度、非平凡内部拆分、跨源组合或 RL 收益证据。详见[实际运行记录](0.7_规则兑现与实际运行.md)。

现在可以开展自动接入与顺序执行研究。原位拆分、构造状态保持需要各自的真实调用记录。并行、远程、跨入口共享粒度切换尚未实现，相关性能主张暂不进入主结果。

## 2. 三个研究问题

| 问题 | 要区分的机制 | 直接证据 |
|---|---|---|
| RQ1：能否自动获得有用的可运行能力？ | 模型读源码、提出边界，规则约束构造、值来源和宿主，反馈修正候选 | 全新分析会话产生的实际产物、真实任务完成、缺口、修正次数与人工成本 |
| RQ2：拆分后是否保持声明范围的原行为，能否正确组合？ | 原对象／状态／控制保留，原返回值传递，成功出口决定后继 | 原生与接入版成对观察；独立 TaskSpec 下的组合完成；异常与副作用关系 |
| RQ3：有真实选择时，两层学习是否改善调度？ | 上层选满足同一任务的完整方案，下层选已使能且资源允许的发生 | 相同合法集合、任务和运行条件下，与强规则策略比较完成率、时延和等待 |

API 模型、K8S、节点数量、Q 更新次数本身不作为贡献。当前没有明确的联合搜索优先策略，暂不主张一种新的联合搜索算法优于其他算法。若论文后续要主张该点，需要明确算法并单独比较同样工具和反馈下的通用搜索。

## 4. RQ1：自动接入比较

分析输入统一为仓库修订、目标任务／原入口说明、真实配置与资源位置、允许宿主及公共工具。生成器从零探索，不读人工边界答案、已生成候选或最终判定。已经参与当前开发的四源用于开发，不作为未见来源证据；新增来源选定后封存，公开预训练可能见过这些仓库，论文需如实说明。

| 对照 | 定义 | 是否已具备 |
|---|---|---|
| 通用工具 Agent | 同一模型、源码工具、可生成形式；依据一般适配说明提出入口与代码，再接受共同独立执行判定 | 计划实现比较臂；未运行 |
| 通用工具 Agent＋同检查器 | 与完整方法同宿主、同源码事实、同 W／H／R、同构建器及精确反馈；使用普通反馈修正，不提供目标操作的专门分析组织 | 关键强对照，计划实现；不能只给它弱类型检查 |
| SeamPact 完整方法 | 当前操作规则、构造／状态／控制分析与具体缺口反馈的完整工具循环 | 当前实现；现有记录是开发运行 |
| 专家人工适配 | 独立从原代码建立可用目标操作与运行条件，记录时间、改动和干预 | 计划采集；不是唯一正确分区 |

所有比较接受同一独立判定，不能用 SeamPact 的 READY 标签当真值。普通 Agent 提出的候选若不满足执行条件，记作未兑现，不在原服务上绕过必要限制。不要把自建参考臂称为 HarnessX 等原论文系统的复现；若后续添加现有系统基线，要先核实其公开实现与实际能力。

默认 API 额度、轮次与上下文继续不限。比较统一模型版本、工具、上下文保留、来源事实和人工停止规则，同时报告消耗。不能在不等预算下只比较成功率并把差异归因于规则；给出完成度—tokens／调用次数／时间的关系。若需要严格预算实验，作为单独研究条件商定，不修改平台默认配置。

先对每个选定来源／方法做 3 次独立新会话，用于看跨会话变化；后续论文数量按实际方差与目标差异补足，不把 3 次重复当稳定显著性的依据。重复中的缓存提供条件相同，候选记忆不跨方法共享。提供方未支持 seed 时明确记为不可控。

### 统计单位与指标

目标操作记为 `(source_revision, original_region, requested_operation, host_profile)`。多个候选描述同一源发生与操作只计一个；同一逻辑操作的粗／细替代版本不累加能力数。

- **任务兑现率**：成功执行预先指定任务的数量／全部指定任务数量。缺资源、未支持、分析失败、运行失败分别列出；另给资源齐备子集的条件成功率和分母。
- **有效边界率**：独立确认可执行且完成所请求操作的边界／生成边界。包装整个入口、内部原位调度和独立导出分别统计。
- **误开放**：系统声明某项操作可用，但独立判定其前提或实际行为不满足的比例；“未运行”不按运行成功处理。未决独立判定单列。
- **漏得能力**：专家已有可行依据、方法未获得的目标操作／专家可行操作。未支持的语言／宿主单列，不偷换分母。
- **自动化成本**：模型／工具调用、tokens、墙钟时间、候选修正、人工输入配置时间与人工修改代码时间。零人工边界不等于零人工资源准备。

报告来源宏平均和完整逐源表。来源内多个任务相关，不把所有调用当独立样本获得虚假的窄区间。需要区间时按来源／会话的层级配对重采样，并报告样本少时的不确定性。

## 5. RQ2：原行为保持与真实组合

每个已能运行的原流程先定义观察契约：返回值／异常、相关原状态、外部请求次序、文件写入及原超时范围。原入口和接入入口使用相同源修订、输入、模型、配置、初始状态与数据，由原实现作为保持参照。随机模型响应无法严格耦合时，先对原发生使用明确标记的响应记录观察结构保持，再用真实服务单独报告任务质量与费用；回放结果不算真实模型质量或时延收益。

覆盖三种有差异的路径：直接原入口；带实际构造器／工厂／共享对象的入口；包含 if／loop／try 的原位调用。用原 callable 的实际启动、原返回／异常和后续控制证据判断，生成的 adapter 或模型自己的“等价”说明不作判定。当前 `starts`、receipt 和退休记录可帮助观察，但它们由平台产生，正式论文还需要来源侧的独立依据。

组合使用事先写清的 TaskSpec：输入、需要哪些实际操作、输出与拒绝／失败要求、质量判据。先做源内数据处理→原评分／归约等真实链，再选择业务兼容的跨源任务；不能只因两个 schema 都是 string 就要求视觉校准器与数学评分器任意互接。原生对象边与 JSON 边分开，记录初始化、引用身份和效果。没有自然跨源任务时如实报告，不能用重复加前缀替代。

针对本轮已经观察到的固定样例输入缺口，检查不同真实任务输入能否到达原函数。针对状态与控制机制，选真实会话／对象共享、原分支不启用某调用、原异常停止后继等案例。每个案例改变一个相关前提，保留原算法；研究发生关系，不优化来源模型。

**主要指标**：满足观察契约的成对任务比例、漏／重复原发生、异常／后继偏差、实际数据边兑现比例、完整组合任务完成率。确定性结构观察与最终内容质量分栏。AST 可逆检查是变换依据，不等于任意程序的行为证明。

## 6. RQ3：调度比较

先记录每次决策的合法候选数。有多个相同要求的完整可运行方案才评价上层选择；有多个已使能合法发生才评价下层排期。原控制分支尚未激活的调用不能为了制造动作空间提前使能。当前同源两步前缀只有一个动作，不进入收益表。

| 比较臂 | 上层 | 下层 |
|---|---|---|
| 强固定方案 | 开发材料选出的最佳固定合法方案 | FIFO 与资源／owner 感知规则 |
| 规则方案选择 | 基于开发材料测得的成功／成本，在同合法集合中选择 | 同资源感知规则 |
| 仅上层 Q | 当前上层 Q | 同规则下层 |
| 仅下层 Q | 固定／规则上层 | 当前下层 Q |
| 两层 Q | 当前上层 Q | 当前下层 Q |

规则排期加入基于历史实际执行时间的短作业优先作为强时延参照；不能读取未来的真实耗时。必要的 owner、依赖、资源限制所有策略相同。当前托管配额为 1，可在多个已使能任务之间比较串行选择，不等于已实现源内并行。

固定现有 Q 参数 `α=0.2, γ=0.9, ε=0.1`，奖励是成功 ±1 减去 `t/(1+t)`。不为获得好结果私自更换算法或权重。任务质量作为独立约束／指标记录，当前奖励不能证明答案质量保持，也不能证明平均时延最优。

训练与成本画像仅使用开发材料；封存评价冻结 Q 表和取消探索，另行评价继续在线更新的条件及其成本。当前平台还没有独立冻结评价接口，这部分需要落实为调度器研究调用条件，不能用混合训练／评价记录报告泛化。建议先用 5 个独立训练随机种子；实际 episode 数由收敛曲线与任务覆盖决定，作为待确定研究参数。

任务负载采用同一到达序列、任务内容和资源条件，比较空闲与多个请求排队的场景、短长任务混合及重复／新任务。跨策略切换真实服务的执行顺序，以减小共享服务器负载漂移。来自其他用户的 GPU 占用作为环境协变量，不归因于本调度器。

**指标**：完成率、端到端与原生执行时延、平均／p95 等待、同样负载下完成任务数、费用、最长等待和各任务类别分布。小样本不报告 p99。成功任务时延之外必须给失败／未完成数量，避免删除慢失败任务产生虚假收益。完整方法总耗时包含分析／接入摊销，并分解模型请求、初始化、许可等待和执行。

并行、K8S 与远程作为有实际需求且实现后才开启的研究扩展。当前不会用模拟 worker 的收益支撑真实部署结论。

## 7. 有针对性的机制消融

| 移除／替换 | 要回答的问题 | 保持相同的条件 |
|---|---|---|
| 用普通反馈替代具体缺口反馈 | 定位反馈是否降低修正与人工成本 | 模型、工具、生成支持范围、独立判定 |
| 固定整体 W，去掉原位／构造选择 | 可运行内部边界是否带来实际复用 | 原算法、任务、服务与执行器；明确是消融，不是最强基线 |
| 固定值核对缺失 | 业务输入接口是否被样例硬编码 | 仅比较候选判断与实际无害数据任务；不让不满足前提的候选污染外部服务 |
| 规则策略替换 Q；分别固定上下层 | 收益来自规则／能力空间还是学习 | 相同完整方案、合法动作、任务与服务 |

暂不添加与主张无关的故障矩阵。完整 EXPORT／COMPOSE 证明、宿主支持扩展和联合搜索算法若后续改变，需要更新方法版本后再设计对应比较。
