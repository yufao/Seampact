## 改动及范围

| 问题 | 当前行为 |
| --- | --- |
| 任务失败，页面显示失败，重新分析却提示仍在分析 | 准入统一核对实际 RUNNING/CANCELLING 任务，来源残留 ANALYZING 不再阻塞。原调用、环境准备及部署占用仍独立检查 |
| 同一检查报告被多次携带，长对话持续膨胀 | check/submit、预处理交接及修订的旧报告均向模型提供精简反馈；保留具体问题、输入接口、映射和操作结论，去掉重复调用证据。完整报告另存且有内容摘要，read_analysis_report 按路径和页码读取 |
| HTTP 400 无具体原因，容易误认网络失败 | 有界解析供应商错误，仅保留状态码、有限错误类别及可识别的 token 限制整数，界面简明显示上下文、请求大小、输出参数、认证等问题；不保存供应商可能回显密钥或源码的原文。不能识别的 400 继续记为原因未确定 |
| 明确超长后只能丢失工作重新来 | 同版本普通分析在完整工具回复边界，若明确收到 context_length/request_too_large 且有当前阶段最近候选，允许手动“从已保存候选继续”。新会话带冻结请求、候选及精简检查反馈；原历史保留，提交仍完整重检，不自动重试或安装 |
| 已有类源码被报缺源码、内部函数被当作动态目标 | 有限调查类构造、原方法及词法内部函数；不支持的绑定、动态行为和调查上限与真实缺源码分开，规则缺口不要求模型反复补证 |
| 报告详情读取失败导致整个任务结束 | 无效报告路径/页码作为工具反馈返回；仅能读取当前分析明确关联、摘要一致的完整报告。沿用已完成分析时同时保留报告引用 |

精简反馈和调用调查只影响既有分析与检查流程，不增加 W/H/R、并行、远程或生命周期许可。原资源与运行参数仍须有依据，AnesSuite 的 max_workers 等没有原值时继续保留缺项。未知不会因缩小报告而变成通过。

## 长请求及恢复的限制

平台不根据字符数猜测准确 token 数或模型上下文上限，也不擅自减少用户配置的输出额度。每次请求记录实际字节数、消息字符数及所请求输出额度，供定位；只有供应商明确返回的错误类别才按上下文/大小问题处理。

明确超限的分析恢复由用户点击触发：有最近候选时开启新会话并重检；尚无候选但已保存完整工具边界时先整理上下文再继续。输入、配置或来源变化须从新冻结请求或当前草稿重新发起修复；候选不继承旧 READY。修订续接保留完整原任务，并核对草稿和生成配置。未分类 400 或不完整边界不伪称能恢复；网络及摘要传输中断按已保存完整边界处理。普通对话的已知窗口高水位整理和单次明确超限处理，按所选连接的自动整理配置执行。

0.14.8 的失败记录保留历史错误类别，不追认成已确定的上下文超限，也不加旧提示兼容续接。更新后对这些来源使用正常“分析 Harness”创建新分析。

## 更新后的操作

按[服务器部署](服务器部署.md)更新前后端，确认健康检查版本为 0.14.9，重新加载页面。相关 checker/worker 工件按当前核心身份核对和重建，不凭版本号沿用过期检查代码。

保留原来源卡片，优先重新分析 PaperGraphBench、TruFor、AnesSuite；无需删除来源或先准备所有模型资源。PaperGraphBench 验证新反馈与调用调查，TruFor 复核权重映射及剩余类调用，AnesSuite 继续明确原配置值和服务条件。只补资源时仍走保存并检查，实际模型运行和防护效果分别验证。
