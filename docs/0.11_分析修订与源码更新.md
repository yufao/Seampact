# 0.11.0 分析修订与源码更新

本文保留 0.11.0 的功能起点与历史核验记录；当前版本为 0.13.0，统一依赖镜像复用及过期工件处理见[统一构建说明](0.13_依赖镜像复用与统一构建.md)。0.12.0 的接入与任务接续记录见[本地接入与实验接续](0.12_本地接入与实验接续.md)。

**2026-10-24 当前口径补充：** 修订台是当前接入的人工／Agent 介入点，用于修复具体候选；经修订、完整机械核对或静态状态变更，不等于原目标已无辅助自动接入成功，须另看真实目标调用。记录中可归纳的共性问题应反馈并落实到通用分析器；单个来源的恢复与通用问题的解决分开记。已有 W／H／R 理论包含数据流、作用域和生命周期条件，本实现只覆盖其中有限规则；未覆盖项是实现缺口，不表示不存在共同核对原则。下文 0.11.0 功能说明和运行记录按其原批次保留。

## 2026-10-24 介入与结果记录

修订详情新增“介入与共性问题记录”及个例结果声明。提交 `POST /api/analysis/revisions/feedback`，请求为 `{revision_id, intervention?, result?, expected_basis?}`；`expected_basis` 可传 `{candidate_digest, source_version, installed_analysis_id}`，提供时三个字段必须完整且与当前修订相同，否则拒绝保存。前端总是携带此身份基准，以免旧页面把结果写到新候选或安装上。接口只保存声明，不改候选、检查报告或能力池。工作台可从相同 `pattern_key` 跳转查看关联修订；关联只用于查阅，不会同步或套用改动。

`intervention` 字段：`actor`（`user`／`external_agent`／`platform_model`／`unknown`，可附 `name`）、`cause`（资源配置、发现遗漏、未支持规则、检查器缺陷、构建器缺陷、语义不匹配或未知）、`change_target`（配置、候选、源码、平台或未知）、`summary`、`evidence` 及 `generalization`。后者包含 `disposition`（`case_specific`／`needs_review`／`generalizable`）、`pattern_key`、`target`（分析、规则、检查器、构建器、理论／语义或未知）、`status`（`open`／`implemented`／`verified`）、`resolution`、`version`、`evidence`。`generalizable` 声明需给出同类问题标识及处理目标；声明已实现或已验证时还需版本和对应依据。它们是填写者声明，不会自动改变规则集。历史 `HUMAN_EDIT` 等标签不能反推旧记录由谁执行，缺少来源者保持 `unknown`。

`result` 可声明 `status`（`unknown`／`succeeded`／`partial`／`failed`）、`summary`、`evidence`，并记录在 `result_basis` 下的 `candidate_digest`、`source_version`、`installed_analysis_id`。候选、来源冻结版本或新安装变化后，当前结果草稿与声明对旧身份作废；界面要求明确作废旧结果再为当前身份填写，不会自动把 `succeeded` 改绑到新身份，旧事件仍保留。介入表单下一次操作默认当前操作者为用户，历史主体继续保留；真实外部 Agent 可显式选择并注明主体。结果为人工声明，须结合绑定身份的运行记录核实；静态 `READY` 或安装成功不能替代目标调用证据。

每次修订操作都进入 provenance；候选编辑事件记录字段差异，并在需要时保存前后快照，检查记录关联其实现身份。新增共性分类和记录字段不等于共性修复已经落实或验证。

本版在已有分析后增加独立草稿：可以人工改候选、给分析器补充重点，或读取 Harness 新版本后沿用旧候选继续分析。每次都对完整新候选运行现有机械检查；只有点击安装才更新当前能力池。结构事实缓存只复用分析材料，不复用旧 READY、业务对象或执行许可。

## 1. 从哪里操作

在“来源与分析”详情页找到当前已完成、有候选的分析，展开“候选修订工作台”。历史分析保持只读，但可查看从它建立的修订及后续模型尝试。

1. 选择“同源修复”或“源码更新”，点击“创建独立修订”。前者使用原冻结源码；后者重新读取本地目录，或为 URL 拉取独立 checkout。URL revision 留空使用远端默认分支当前提交，填写时冻结对应提交；本地目录只读取当前内容，不替用户 checkout 或修改工作树。
2. 修改候选 JSON，填写希望关注的问题和修改理由。例如“上次主要发现了离线入口，请重点核对在线请求入口及原共享对象”。工作台展示源码增删改、候选字段路径差异及来源版本。
3. 点击“保存草稿”或“保存并完整重检”。这些操作不调用分析模型，也不改变现有能力池。检查失败时看具体原因；缺实际资源仍通过原服务／权重配置解决。
4. 需要模型补充时，点击“调用当前分析模型局部修复”。这是付费模型请求，使用当前分析角色及非敏感请求参数；发送结构化候选、差异、提示和反馈，按需读取原源码或缓存事实，不默认重放整段旧对话。
5. 模型提交的完整候选仍先保存在修订中。检查报告对应当前候选后，点击“独立安装新候选”。安装时再次完整核对并检查运行条件，生成新安装身份；旧分析及研究结果保留。

人工输入与模型结果都只是候选提议。文字“可以并行”不会开放并行；检查器不支持的构造形态仍会显示具体缺口。`CHECKED` 表示完整检查已完成，须继续看每项入口、资源和运行组的状态；它不表示所有 Unit 都 READY，更不表示原目标已经调用成功。

## 2. 草稿、版本与运行保护

草稿绑定父分析、父候选内容摘要、来源与运行环境。保存、检查和模型修复不会覆盖父记录。另一次分析、绑定或环境调整使基线变化后，旧草稿显示过期原因，不能直接覆盖新的能力池；应从最新记录创建修订。

安装沿用已有来源运行保护：原调用、研究运行、运行实例、构建或发布未结束时不能替换。完整检查后再次核对运行状态，保留原 owner 的互斥条件；替换后的旧绑定不接纳新调用。不会迁移活对象、业务栈或在途状态。

服务连接、凭据、权重登记、已有向量索引和历史运行文件不会因修订删除。当前候选仍按已核对映射使用资源；映射改变时重新选择或检查。不因源码修订默认下载模型、重新嵌入，也不把同名模型／接口视为收益兼容。

源码更新沿用当前选择的运行环境，并按新原库声明核对。若新版本要求不同 Python 或系统环境，本版不会自动切换或安装依赖：冲突在模型请求前报出；可将新版本独立接入并配置匹配环境，旧来源保留。独立解释器／worker 的实际镜像条件仍按 [0.10 运行环境](0.10_异构运行环境.md)处理。

## 3. 本版怎样复用材料

`revisions.py` 比较完整冻结文件清单，记录新增、删除、修改和未改路径，以及 withheld、目录范围和配置差异。文件结构事实按内容摘要、提取器实现和解析环境缓存，包含定义、导入、调用及注册候选；未改文件仍可能受其他变化影响。

模型上下文提供变化文件的事实及其他相关事实的引用。`read_revision_facts(path)` 只读取当前修订引用、且文件路径及摘要仍匹配的缓存；不可用时返回 UNKNOWN，模型可以按原源码工具补读。指定独立解释器却未实际附加时，不回落平台解释器冒充相同事实。注册／动态依赖闭包始终明确保留 UNKNOWN。

这些是文件局部结构事实，不是完整依赖图。源码锚点、原构造、共享状态、控制关系、资源、运行组和有限变换仍在提交及安装时完整核对。维护旧候选与发现新入口分别说明，不能承诺与完整重跑模型得到相同粒度或覆盖。

## 4. API 与记录

| 接口 | 行为 |
|---|---|
| `POST /api/analysis/revisions` | 以当前完成分析创建 refine／update 草稿；可选 revision |
| `GET /api/analysis/revisions/<id>` | 查看候选、版本、差异、反馈、来源和用量 |
| `POST /api/analysis/revisions/save` | 保存候选、guidance、reason，不安装 |
| `POST /api/analysis/revisions/check` | 保存并完整机械核对，不调用模型 |
| `POST /api/analysis/revisions/refine` | 用当前分析模型发起独立局部修复尝试 |
| `POST /api/analysis/revisions/install` | 重核当前候选及运行条件，再安装新版本 |

动作接口使用 `revision_id`；编辑接口的 candidate 是完整 JSON 对象。`/api/state` 提供 `analysis_revisions` 摘要，大候选按详情读取。草稿复用 Store，模型尝试保存在原分析历史中，安装另存零模型记录并引用父分析、修订及全部模型尝试。旧尝试费用不覆盖，新记录仅计当次实际用量。

传输中断续接保留原工具消息边界。修订候选、提示或理由已经修改，或分析模型连接发生变化时，应发起新修复尝试，不能用旧请求覆写当前草稿。失败、取消、未返回请求的 UNKNOWN 用量分别保留。

## 5. 实现与研究范围

实现位于 `service.py` 的修订生命周期、`analysis.py` 的独立修复与缓存读取工具、`revisions.py` 的差异与结构事实，以及原前端分析详情；三学习器更新算法与 W/H/R 规则不变。

本版实现“材料复用、局部模型修复、完整机械重检”。逐操作支撑依赖、覆盖域负判断、删除重推导和义务推导的跨版本迁移仍为后续研究，未实现完整证明或增量校验放行。它们的设计见工作区理论稿，不因本版新增界面就记作研究成果。实际费用节省、来源覆盖及模型修复质量仍需真实运行数据。

本机在现有平台的私有状态副本中，使用已有 REX 候选完成 JSON 人工修改、完整重检、读取同源当前目录和显式安装：保存／检查时父身份不变，安装后产生新身份，旧分析可见，另一个旧基线草稿显示过期；这些操作模型请求为 0。结构缓存有命中，也有解析不可用项，后者保留 UNKNOWN。Python／前端语法及差异格式检查通过。未调用原 Harness、真实修复模型、GPU、容器或 K8S；服务器尚未更新。本轮未编写测试脚本或改写原研究数据。
