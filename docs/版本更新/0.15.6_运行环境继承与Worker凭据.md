# 0.15.6 运行环境继承与 Worker 凭据

日期：2026-11-03。**用户已手动提交、推送并更新研究节点；健康接口确认 0.15.6，本地提交为 c119b5f。** 以下保留修复时的故障与核验范围，不将部署成功追记为真实来源调用成功。该提交还包含整轮实验镜像保留与可选备份，见[操作说明](../部署与操作/实验镜像保留与备份.md)。

AnesSuite 的辅助公共 API 候选已通过原参数映射检查，但第一次 worker 启动退出，没有执行题目。实际日志显示运行包和认证材料均不可用；构建回执进一步确认，来源已选 `eval/requirements.txt`，导出时未传 `environment` 却生成了空依赖环境。平台保存的服务凭据也没有进入 worker 的执行环境。这些是执行准备失败，不是评测模型的答题失败。

本地修复两处通用接线：

- 构建导出省略 `environment` 时，继承该来源已核对的运行环境，包括依赖文件、额外包和索引。显式传入的配置仍按原规则检查；Python 与源码核对解释器不符时继续拒绝。
- Docker worker 启动时，只解析该运行组实际映射到原认证参数的连接凭据，先核对冻结的连接／认证身份，再作为 Docker 客户端的临时子进程环境提供。命令参数只有环境变量名称，秘密不进入工件、配置、操作回执或父进程环境；命令输出及超时输出按本次秘密值脱敏。凭据缺失或发生轮换时须正常重绑，不使用旧缓存键继续启动。K8S 沿用已有 Secret 接线。

本地此前已有的完成检查修复一并纳入：调用后的文件访问或读取错误保留为观察 UNKNOWN，同时保留原退出码及输出。实际缺文件、结构无效、输入改变及非零退出继续按未完成处理，详见[当前实现](../设计与实现/当前实现.md)。

实现没有改变来源算法、原模型、W／H／R、owner、生命周期或学习器。AnesSuite 当前只选原公共 `eval_benchmark` 整体调用；原内部 W 候选及其未决事实保留，未将其改成合法细入口。CLI YAML 和 SGLang 服务不计作接通。显式开发配置为单并发、temperature=0、max_new_tokens=2048，不能称为被排除原 YAML 的取值；后续原生／平台配对双方须固定相同配置。

验证：完整 Python **480 项，478 通过、2 项可选 YACS 跳过**；前端 **13 项通过**。新增 7 项覆盖真实轻量子进程环境传递及脱敏、Docker 命令只含变量名、组级凭据隔离、缺失／轮换拒绝、worker 实际查找名称，以及依赖默认继承和显式覆盖。Docker 启动采用替身，**修复后的真实 AnesSuite worker 和答题仍未运行**。

更新后准备受影响来源解释器、零模型重检已有候选，并重新导出、构建匹配 worker。RefChecker 已完成一次零模型重检及匹配 worker 构建、发布；真实 RL 开发运行仍受容器自识别及 Docker 存储核验挂载阻塞，后续修复见[0.15.7](0.15.7_实验启动存储接线.md)。九库完整模型分析继续复用，不因本次修复重复提交。0.15.5 已冻结实验按原提交和工件身份解释，不能追记为使用本次修复。
