## 代码结构

原 `src/seampact/` 下 46 个模块迁入 7 个职责目录；根目录保留平台入口、对话、资源登记、原生 Unit 与执行协议。使用唯一新导入路径，不保留旧模块转发或两套实现。

| 目录 | 职责与主要模块 |
|---|---|
| `source/` | 冻结源码检查：`inspection`、`verification`、`lowering`、`callsite`、`dependency_closure`、`frozen_inheritance`；原执行目录与环境传递证明 |
| `configuration/` | 原消费者与资源绑定：`dependencies`、`configuration_*`、`resource_flow`、`resource_origins` |
| `analysis_support/` | 分析预处理、候选一致性、入口用途、报告、反馈与修订材料 |
| `hosting/` | 解释器、依赖镜像、worker 部署、受管服务及操作预检 |
| `scenes/` | 已有任务输入、接续与独立评价适配；只消费目录中可执行的 Unit |
| `scheduling/` | 功能与联合调度、学习器、训练、成本、生命周期及驻留资格 |
| `observability/` | 独立资源记录、进程／容器观测及窗口物理指标 |

根目录的 `service.py`、`analysis.py` 继续协调原主链，`units.py` 继续统一机械检查与原 callable 绑定。`python -m seampact`、`python -m seampact worker` 和独立 worker／checker 入口保持既有调用方式。文档中的当前源码路径同步到新目录。

本次同时修正三个与目录结构直接相关的点：分析实现归档使用包内相对路径并包含所涉及包的初始化文件；训练归档递归包含平台 Python 文件；资源观察器按新相对路径冻结实际采集实现。worker／checker 继续按真实导入闭包计算身份，构建只复制身份覆盖的文件；没有用整包版本号或旧工件兼容分支替代执行代码核对。

新增通用候选检查会在构建前报告 `resources` 中误作文件路径的依赖 ID，明确要求保留原依赖、映射和加载器；真实路径仍经过原存在性检查。这来自 RefChecker／TruFor 新候选及 TruFor 实际 worker 错误，不改变资源准入、W／H／R 或 owner 规则。

目录变化会改变受影响的代码身份。更新后按现有准备解释器、零模型重检和构建流程刷新工件，已有权重与依赖缓存继续复用。九库在 0.15.4 下的完整分析已经完成，不能因为目录整理再次默认触发九次付费完整分析。

## 停止收尾与更新观察

更新前实际观察发现，API 排空停止与后台控制器可能同时处理同一个实例：第一次删除成功后，另一次失败写入会覆盖释放标志，并读取已清空的停止请求。现按实例独占正在执行的停止操作，完成或异常均释放该操作占用；实际停止、删除和原调用 UNKNOWN 的资格保持不变。

`STOPPED` 与资源已释放分别判断：带后端句柄且未确认释放的已结束实例继续阻塞更新和环境修改；Docker 端只在对该实例容器精确查询成功且确认不存在时记已释放，查询失败保持待确认。控制器完整成功观察后才清除当前错误，实际实例和调用缺口仍由原预检报告，不把历史异常永久当作当前失败。

这一修正来自真实停止竞态，不改来源算法、W／H／R、owner 或生命周期许可。旧平台内存中的异常不会由本地编辑自动修复；更新前仍由操作者核对工作结束和实际后端资源，再按统一更新流程操作。

## 冻结输入的显式方案入口

远端 RefChecker 开发运行发现，模型在转抄任务参数时把一条问题及参考文本中的标点改写；整个对应批次按输入一致性失败保留，没有重跑覆盖。因此新增 `POST /api/plans`：提交与既有 `execute_harness_plan` 相同的完整方案 JSON，API 冻结请求及 SHA256，复用同一个 `compile_plans`、业务可见性检查、调度器选择、`NativePlanOwner`、运行时上下文和原 Unit 调用。该路径不调用对话模型，模型调用次数记录为 0；透明 Unit、未绑定能力、错误参数、原失败和 UNKNOWN 仍受原检查约束。

调用返回任务 ID 与请求摘要；完整请求、原结果、调用记录、错误和分项资源身份继续保存在原任务记录，可从既有状态接口读取。它与普通对话共用执行器，显式方案不混入对话历史，不接受构造原对象或重串来源内部步骤。本地轻量原 callable 的实际 HTTP 核验及路由替身核验已完成；远端 0.15.5 也已通过本入口完成 RefChecker 新运行的 100 条实际返回，全部请求逐批一致。先前发生输入改写的旧运行保留原身份，不能将软件修复倒填为该批成功。
