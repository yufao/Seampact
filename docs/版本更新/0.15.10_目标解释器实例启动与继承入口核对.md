# 0.15.10：目标解释器实例启动与继承入口核对

修复两个阻塞原生运行的问题，并纳入此前已验证的部署 GPU 观测配置。

## 目标解释器目录安装

选择独立 Python 解释器的来源，安装目录时曾只保存资源快照函数，遗漏启动阶段使用的 `worker_environment`。因此原镜像即使已构建、对后端可达，启动也会在创建实例前报 `SimpleNamespace` 缺少该属性。

现在与普通目录安装共用 `DependencyBindings`。原源码检查仍交给所选目标解释器，不在协调平台导入或安装 Harness。权重组无需服务凭据；需要服务认证的组在每次启动时核对冻结的连接及认证身份，再读取私有凭据。凭据不写入 Unit 或资源快照，连接变化仍拒绝沿用原绑定。

## 继承原方法的 W 绑定

`native_wiring` 允许使用文字说明原接线，也允许在已有有限规则内提交结构化接线。继承方法的完整 W 检查此前把说明字符串也误判为接线改写，导致已定位原父类完整方法的候选仍被拒绝。

现在允许说明字符串，继续拒绝继承 W 上的结构化接线、额外规则、多重边界及错误定义锚点。仍使用原子类接收者调用原父类方法，不改变默认参数、内部方法或生命周期资格。

## 平台 GPU 观测

统一部署入口增加 `configure`，复用当前镜像调整平台 GPU utility 观测，无 Git 拉取或镜像构建；安装与更新保存并沿用 `--gpu-observe`。探测成功后才进入正常停机、全量状态备份、替换及就绪流程。任务计算卡仍由运行组或后端配置决定。用法见[服务器部署](../部署与操作/服务器部署.md)。

## 更新与核验范围

本地双来源实跑发现空闲 Python worker 作为容器 PID 1 时，默认 SIGTERM 会等到 Docker 的停止超时。生成的 worker 镜像改用 `STOPSIGNAL SIGINT`，复用入口已有的 `KeyboardInterrupt` 收尾；仍须先排空原调用，再按后端实际停止和释放回执计费。依赖层配方不因停止信号改变。相关镜像生成／复用检查 14 项通过，实际退出时长另在新窗口核对。

更新平台后，为来源准备匹配的目标解释器；对现有候选或已保存修订重新机械核对，再按正常流程安装及生成匹配运行组工件、镜像。不需要为这两个缺陷重新调用分析模型，也不必重新上传输入与权重。检查器和 worker 的代码身份会变化，不能把旧镜像的历史 BUILT 状态当作新身份通过。满足精确锁及环境身份的来源依赖可按既有机制复用；源码更新本身不要求重选 Torch 等依赖。

启动资源接口、服务认证变化、继承原方法、独立解释器协议、GPU 分配及构建身份的相关本地检查共 47 项通过。原始 NLI 及父类源码的两份字节摘要与现场记录一致；使用现场保存的修订候选和资源绑定作本地静态重放，原源码／接口／构造检查通过，得到 `SOURCE_BOUND`。早期静态重放时本地缺少部分原依赖，当时环境条件保留 `ENVIRONMENT_DEFERRED`，不记为服务器解释器、CUDA 推理或训练通过。

部署 GPU 观测另有 7 项受控命令替身检查通过，连同上述 14 项生成／复用检查，本批合计 68 项；utility 观测与实际模型执行分别核验。

后续本地已按正常工件流程完成匹配解释器、候选重检、镜像构建和真实 GPU 运行。RefChecker 公共 NLI checker 与 TruFor 原逐图 CLI 的单种子开发协议共完成 105 个窗口、420 次请求发生，包含 32 窗 PPO 训练、四臂各 8 窗验证和各 10 窗汇报。PPO 有 128 次参数更新，两预算各 16 个有效选择窗，冻结臂更新数均为 0；420/420 输出与同机原方法逐件一致，全部窗口无排除、全部到达有交付。原始采样、策略摘要、独立质量评分和一致状态库已留存。本轮没有观察到 PPO 的实例秒收益，不把链路完成当作调度优越性证据。

上述调用沿用用户引导修订的 NLI 候选和既有 TruFor 分析候选，手动环境资源补充单独记录；图像使用固定小规模输入。早期缺依赖的静态重放、停止信号修复前的 pilot，以及共享状态存储上的诊断训练和部分验证均单独保留，不与本轮合并。当前结果限于固定驻留、根派发、两来源开发范围；远端更新、多来源终评及其他生命周期动作仍需对应回执。
