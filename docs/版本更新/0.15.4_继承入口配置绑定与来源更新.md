# 0.15.4：继承入口、配置绑定与来源更新

日期：2026-11-02。本版更新平台通用接入实现及操作入口；真实来源的模型执行、独立评分和资源收益分别记录。

## 原生继承入口

有限本地单继承可将子类作为原 owner，调用定义在父类中的完整实例方法。入口填写子类文件及 `子类.方法`，构造器仍为真实子类；整体 W 边界引用父类实际定义。平台记录类链、实际方法、冻结文件与 AST 摘要，运行时核对真实定义，保留原 `self` 分派、构造和内部循环。

不据此开放内部拆分、并行或回收；动态／外部／多继承、猴补和无法识别的属性协议仍保留缺口。RefChecker 的完整检查应覆盖原父类的参考分段、调用及合并；原 `_check` 组件成功不能代替完整检查成功。

闭包对原零参数 [`torch.no_grad()`](https://docs.pytorch.org/docs/stable/generated/torch.no_grad)及 [`spaCy.load`／Language 调用](https://spacy.io/api/top-level#spacy.load)使用有限外部协议：识别精确导入、未遮蔽／未猴补的目标，以及唯一受 guard 保护的模块单例写入；运行仍执行原装饰器和加载器。语言模型资产另记环境未核对，不从 SDK 协议推定其已安装。

## CLI 配置中的服务选择

原 CLI 通过命名参数打开冻结 YAML，并由原加载器把嵌套字段传给服务消费者时，分析器可以提出 `configuration` 映射。检查范围包括原参数解析、原文件、加载器、字面字段、调用和覆盖次序；唯一同源线程池回调也按真实提交追踪。未调用的定义不能作为消费者依据。

运行时只在私有临时副本中替换已证明的服务叶子；其他配置原文保留，原 CLI 和加载流程继续执行。凭据不进入命令参数，副本在正常返回或启动失败后清理，子进程结果中的已解析凭据被遮盖。原文件不被覆盖。

原消费者一致拼接唯一字面 URL 路径后缀时，证明中记录该后缀。如果所选连接已经包含相同后缀，临时字段去除一次，原代码再拼接一次；同一字段混用不同后缀时拒绝转换。冻结 YAML 使用不含真实凭据的原模板，秘密只在运行时解析。动态键、重复键、无法证明的标签／别名、覆盖或加载器继续保留缺口；明确的原环境标量标签可在核对其有限 getter 后保留。资源选中、静态绑定、原初始化、实际预测及效果评分各自记录。

原 CLI 环境映射另提供“条件可达见证”：证明原变量经一条真实原路径到已知消费者，明确记录后续路径未展开的范围；它不授予整个 CLI 的依赖闭包、分支启用或执行许可。完整入口仍须通过独立闭包检查。原 SDK 的类属性与已构造实例分别识别，虚构方法名不能作消费者依据。

## 检查 Harness 更新并分析

- “来源与分析”提供 **检查更新并分析**。配置的“Harness 接入”提供 **分析前检查上游更新；无变化时不重复分析** 选项。
- URL 来源重新获取仓库，本地来源重新读取目录，再冻结和比较内容；不覆盖旧克隆或旧冻结字节。
- 新接入保留用户指定的分支、标签或提交引用，更新时沿用该引用；未指定时检查默认分支。旧记录没有已保存引用时也明确显示默认分支，不从提交哈希猜测分支。修订台可显式选择另一个引用。
- 无变化时不调用分析模型。有变化时运行全新预处理和分析，原版本继续保留；新候选经过完整检查和安装条件核对后才切换。
- 页面区分分析完成与新版本安装；没有可绑定入口或安装受阻时说明原因并保留原版本。部分入口可安装不表示目标已经真实运行。
- 能力安装的状态写入与内存目录一同提交，安装中途报错时恢复旧目录；已完成的旧入口仍可调用，不留下半安装的新入口。
- 原版本重新分析仍使用未勾选更新检查的 **分析 Harness**。平台规则更新后，即使原源码没有变化，也需要这种重新分析；“检查更新”不会代替它。

本版采用用户发起的一次操作完成检查、获取和分析，不建立后台定时拉取任务。修订台仍可用于显式版本选择、人工修订和独立检查；新旧资源执行证据按版本隔离。

更新分析可在已有规则允许的中断边界续接原预处理／分析阶段；草稿、冻结请求、父来源及模型配置须保持一致。续接仍为新源码的完整分析，不改成旧候选修补。

## 来源与历史展示

“来源与分析”在按操作折叠之外再按来源折叠。选择全部来源时默认收起，选择单个来源时默认展开该来源；已有展开状态、修订定位和历史记录保留。

## 更新后的实验操作

1. 推送并按统一方式更新平台，保留来源、权重和历史记录；确认页面版本为 0.15.4。
2. 准备好当前代码身份对应的目标解释器，再对 **RefChecker、AnesSuite、PaperGraphBench** 在当前源码版本上重新完整分析，便于验证本版通用支持；本轮不同时混入上游源码变化。
3. **TruFor、VPC3** 先准备当前目标解释器并重新核对已有候选。新核心身份所需的执行工件按正常流程重新生成，已有权重复用。
4. RefChecker 的 NLI 权重、TruFor 官方权重及 VPC3 gate 已选择时保留。RefChecker 抽取／LLM 服务和 AnesSuite 服务在映射通过后选择已有 Flash 连接；PaperGraph 的文本服务与 embedding 服务分别核对；VPC3 仍需要原视觉专家服务。
5. 检索服务和其他重模型缺口继续逐项补齐，暂不以反复完整分析代替准备资源或修复未覆盖规则。先完成真实原生／平台配对与独立评分，再进入混合调度和模型替换比较。

## 本地验证结果

完整 Python 检查 **459 项：457 通过，2 项因本机缺少可选 YACS 依赖跳过**；前端 **13 项全部通过**。轻量原 CLI、真实本地 Git 分支更新、真实能力安装与中途失败回滚均经过贯穿核验；原模型未运行，测试中的 API 为本地替身。前端语法、变更文本及差异检查通过，浏览器核对九来源状态副本中的折叠和更新选项，临时预览已清理。

真实源码层面，RefChecker 完整继承入口和 PaperGraph 直接 `run_evaluation.py` 入口通过调用闭包；AnesSuite 三项配置字段及 PaperGraph 六项环境字段取得原消费者见证。PaperGraph 外层 `scripts/start.py`、`scripts/evaluate_dataset.py` 仍保留有限预算未覆盖范围；不把直接入口检查通过扩展成所有启动形式可用。详细事实和归因见[共性核验第 14 节](../设计与实现/分析器共性缺口与验证.md#14-0154-通用支持与源码检查2026-11-02)。

本批未暂存、提交、推送或部署。远端重新分析和新数据集评分仍需更新后实际执行；不把本版软件核验记作自动接通数或防护效果。
