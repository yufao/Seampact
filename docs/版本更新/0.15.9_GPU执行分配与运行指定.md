# 0.15.9：GPU 执行分配与运行指定

“运行组与部署”新增“任务 GPU 分配”：与资源观察共用精确识别逻辑，接受设备序号或完整 UUID，探查后勾选、保存。无需修改源码或手写 Docker 参数。分配作用于运行组实例，任务在该实例内执行；不进行逐任务热切卡、节点选择或现场迁移。

## 前端操作

1. 进入“运行组与部署”，展开来源、运行组及“任务 GPU 分配”。
2. 输入 `0`、`0, 1` 或完整的 `GPU-…` UUID，点击“探查设备”。资源观察中已保存的设备也会出现在选项中。
3. 勾选需要的设备，点击“保存 GPU 分配”，再按正常流程启动实例或开展研究运行。保存分配本身不启动模型。

运行组配置优先于部署后端的全局 GPU 设置。原生 worker 取消全部勾选再保存，表示不给新实例提供 GPU；若原程序要求 CUDA，其原执行失败不会被平台改成 CPU 算法。已有实例、状态未确认的后端对象、研究运行锁或实验镜像冻结范围会阻止改卡。先排空并确认释放、结束冻结范围，再保存新配置。新副本沿用同组设备选择；它不代表独占整卡。

同页另有“受管模型服务 GPU 分配”。服务需为所选 UUID 提供有依据的显存需求上界，原模型、参数和权重保持原规格。卡的总显存不会自动充当模型需求。保存会更新完整服务规格的摘要，引用该服务的连接须按现有流程正常重绑。GPU 服务不能通过便捷选择清空已有 GPU 需求。

平台进程／容器须能执行 `nvidia-smi` 并访问目标设备，Docker 后端须能启动所选 GPU 的容器。本轮只支持平台所在机器的现有 Docker 后端；不将本机设备序号套用到其他主机或 K8S 节点。探查失败会保留原配置。

## HTTP 接口

统一识别，不保存观察或分配配置：

```json
POST /api/gpus/probe
{"devices":["0","1"]}
```

返回 `devices` 中的名称、编号、完整 `gpu_uuid`、整卡显存等探查事实，以及 `gpu_uuids`。原生 worker 保存分配：

```json
POST /api/deployments/gpus
{"group_id":"运行组标识","devices":["0"]}
```

返回规范 UUID 列表 `devices`、`device_facts` 及 `checked_at`。查询 `GET /api/state` 时，运行组的 `gpu_allocation` 显示配置及当前能否修改；普通轮询不运行硬件探查。

原生 worker 可在冷态启动时直接指定：

```json
POST /api/deployments/start
{"group_id":"运行组标识","gpu_devices":["0"]}
```

省略 `gpu_devices` 时使用已保存的组配置，再回退至全局后端配置。显式指定且通过启动前核对后，同时保存为该组后续启动的默认分配；空数组表示不提供 GPU。已有副本或冻结研究运行仅允许重述相同的设备顺序，不允许改卡。`/api/deployments/add-replica` 支持相同字段，但不能使同组现有副本改变分配。所选 UUID 写入实例记录和 Docker 启动参数。

受管模型服务保存设备与需求：

```json
POST /api/managed-services/gpus
{
  "service_id":"服务标识",
  "devices":["GPU-完整UUID"],
  "memory_mb":{"GPU-完整UUID":12000},
  "basis":"模型加载及固定并发的需求上界依据"
}
```

返回更新的完整服务规格。省略 `memory_mb` 时，只复用原 UUID 的需求或同卡数、各卡等量需求的映射；设备数量／异构需求变化须明确填写。服务启动接口中的 `gpu_devices` 用于核对指定设备是否与冻结服务规格一致，不会绕过资源包络临时换卡。

## 启动和实验依据

worker 与受管服务共用 Docker GPU 参数生成：所选 UUID 同时用于 `--gpus` 和明确的设备可见范围；空选择明确使用 `NVIDIA_VISIBLE_DEVICES=void`，避免 CUDA 基础镜像及默认 NVIDIA runtime 使空选择继承全部设备。变量含义见 [NVIDIA 官方说明](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/docker-specialized.html)。

研究运行在清单中冻结 `gpu_devices`，并在加锁、准备和执行时核对；激活旧策略执行场景任务也核对原设备配置。设备变化需要按新条件重新冻结评价，不能保留旧设备记录却实际使用新卡。声明 GPU 资源容量时，worker 的 UUID 与 `gpu:<UUID>:memory_mb` 容量／正值需求须一致。只用调用槽的开发运行仍可运行，GPU 预留成本保持未知；设备采样继续可选，缺采样不能报告实测 GPU 收益。

配置 GPU 本身不改变来源源码或模型算法。更新平台代码后，检查器、worker 与当前代码身份仍须按现有准备、重检和构建流程核对；不以重复调用分析模型代替这些检查。

## 核验边界

本机临时平台页面已完成真实 GPU 识别、选择、保存和刷新后读取；HTTP 到 Docker 启动参数的接线使用受控命令替身核验，没有启动真实模型或远端容器。相关检查覆盖多卡 CSV 参数、空选择、失败保留、未释放实例／研究锁拒绝改卡、服务包络、运行配置冻结和激活策略的设备漂移拒绝。它们不构成远端 GPU 运行、模型效果或资源收益的证据。
