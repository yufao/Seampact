## 更新前先看什么

选择“更新平台”时，面板列出仍在进行的分析、环境准备、镜像构建／发布、任务、研究运行、调用及根请求、运行组锁、未释放的 worker／受管模型服务、服务租约和资源记录。每项说明原因、下一步和对应详情；磁盘上的镜像、权重和已释放实例不计为运行活动。

结果区分“当前未发现阻塞”“有工作正在进行”“需要先释放实例或结束记录”“仍有状态需要确认”。观察不等待长时间来源操作，不停止任务或容器，也不替代实际操作时的检查。更新脚本读取同一预检接口后继续原有空闲及 Docker 条件检查。第一次从未提供此接口的 0.15.1 更新时，脚本明确提示观察范围并沿用原检查，额外核对可见的受管服务实例；没有把未知实例直接视为已释放。

选择“调整来源环境”后再选择来源，可以查看该来源的准备、分析、构建、运行实例和调用条件。未关联到具体来源的操作无法从全局繁忙状态推断为可修改；来源锁忙时明确保留待确认。检查是即时快照，操作前可以点击“重新检查”。

## 怎样观察和保存资源

默认不采样。在页面选择当前支持的指标、记录名称、采样间隔及所需 GPU 后点击“开始记录”。离开页面后后台仍会记录；“停止记录”只结束探针，不会停止 Harness、模型服务或任务。若探针仍在结束，显示 `STOPPING`，确认退出后才允许另一条记录。平台重启不会自动恢复探针，未结束的记录标为中断。

| 可选指标 | 读取位置 | 展示边界 |
| --- | --- | --- |
| 平台进程 CPU／内存 | 当前进程 CPU 累计时间、RSS／工作集 | 不包含其他进程或整机总量 |
| 受管容器 CPU／内存 | 平台拥有的 Docker worker 与模型服务的 cgroup v2 | 内存含缓存和后代；探针本身开销在内；不与平台进程求和 |
| GPU 显存／利用率／功率 | 已配置 UUID 的 `nvidia-smi` 整卡读数 | 共享设备包含其他负载；不代表单任务显存、GPU 秒或能耗 |
| 任务与调用 | 已保存任务和运行时状态 | 排队／执行数量，以及记录开始后结束任务的计数与延迟；任务完成状态不等于防护效果通过 |

不可用指标会说明原因并禁选；选择后仍可能因权限、设备读数或实例变化而缺失，此时保留未知与原因。首版不采集 K8S 容器计数，也不测云端 API 服务端资源。无需为观察安装新的监控服务。

GPU 探针要求平台进程所在环境能够执行 `nvidia-smi` 并读取所选设备；只给 worker 配置 GPU 不会自动给平台进程提供这项能力。未满足时界面禁选并说明原因，不能把没有读数理解成未占用。容器计数则需要平台现有 Docker 后端、实例身份及 cgroup v2 读权限。

页面展示最近样本曲线、最新值、窗口内采样峰值、有效样本、采集耗时，以及整段记录的有效 CPU 秒和资源积分。CPU 曲线使用各读数自身时间计算的速率；实例代次、身份变化和采样缺口会断开。GPU 整卡能量积分只称设备能量估计。配置间隔为采样之间的等待时间，实际读数间距还包含探针耗时；过长间隔不积分，不将未知值填零。

JSON 导出会话配置、采集器身份和汇总，JSONL 导出完整原始记录。运行中的导出只包含当时已写完的记录，不代表最终结果；原始样本分块下载，不一次读入内存。文件保存在平台数据目录的 `runtime/resource-monitor/`，含本机进程／设备身份，分享前需去标识化。页面保留最近 30 条记录选择，详情支持分页，完整记录可通过对应 ID 读取。

## 与正式调度实验的关系

这一页用于定位加载、驻留、调用和释放期间的开销。正式运行仍使用既有窗口观察器，覆盖准备前到释放确认后的全过程；界面采样不会修改其配置、RL 特征或奖励。并行开启界面探针会增加采样开销，须记录并纳入有／无探针的配对对照。

指标定义、选择理由、有效分母、时间窗口、共享设备归因、背景对照和配置冻结见[性能探针与测量协议](../研究实验/性能探针与测量协议.md)。没有真实测量的资源收益、能耗和调度效果仍是待测结果。

## 更新与核验

本地代码、包版本统一为 **0.15.3**。本轮未推送、部署或停止远端任务。用户更新服务器前应先结束当前构建及任务，按既有方式排空释放实例；更新后进入“运行与资源”核对活动并按需开始记录。既有来源不需要全部重新调用分析模型，权重也无需重新下载；需要运行的来源按当前解释器身份重新准备、零模型核对及构建。

核验覆盖真实本地 HTTP 的开始／停止／读取／下载、完整 JSONL 行截取、未知值和身份切换、探针停止中状态、写入失败、操作阻塞及前端曲线。Docker／GPU 采样的真实服务器读数须在部署后核验，软件检查不计作实际性能结果。
