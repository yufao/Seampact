# 0.15.8：任务记录清理与 GPU 观察选择

本次增加任务面板的记录清理，以及独立于执行分配的 GPU 观察配置。现有分析、拆分和调度规则不变；不自动清理任何既有任务或设备。

## 任务详情

在“任务详情”中，每条已结束记录提供“删除记录”。页面顶部的“清理已结束记录”只处理当前来源／任务筛选范围，操作前显示确认。

删除从任务列表移除记录，原执行依据、会话、研究结果和重复提交判定仍保留；不用于释放数据库空间。运行中、状态未确认、仍有调用／根请求未收尾或仍占用实例／服务租约的任务不能删除。批量操作先核对全部任务，再统一保存；任一任务不满足条件时整批不删除。无需重新执行原任务。

接口：`POST /api/tasks/delete`，输入 `{"task_ids":["任务标识"]}`，返回 `{"deleted":["任务标识"]}`。

## 运行与资源

1. 在“GPU 观察设备”输入完整的 `GPU-…` UUID 或非负设备序号，例如 `0, 1`；多项用逗号或空格分隔。
2. 点击“探查并保存”。平台仅查询明确指定的设备，识别后显示名称、设备序号、显存和完整 UUID。所有输入均识别成功后才保存；失败不覆盖原配置。
3. 在“采集指标”勾选 GPU 指标，在“本次观察的 GPU”勾选设备，再开始记录。

设备选择保存到平台数据目录，重启后保留。序号在探查时解析为完整 UUID，后续采样使用该 UUID。输入留空再保存可清除手动设备；部署或受管服务原有的 GPU UUID 仍会列为候选。正在运行的记录固定使用开始时选定的设备，修改保存配置不会改变它。

此处只配置观察对象，不修改 worker 或模型服务的 GPU 分配。平台进程／容器须能执行 `nvidia-smi` 并访问目标设备；worker 能使用 GPU 不代表平台观察器具备相同条件。未知读数继续记为未知。整卡显存和功率包含共享设备上的其他负载，不归为某个任务的实际开销。

接口：`POST /api/monitor/gpus`，输入 `{"devices":["0","GPU-完整UUID"]}`；返回已识别的 `devices` 及可选的 `gpu_uuids`。`GET /api/monitor` 的 `capabilities.gpu_devices` 提供手动保存的设备信息，`gpu_uuids` 提供手动和已有部署配置的候选集合。
