# 服务、权重与 Harness 依赖配置操作

更新：2026-10-22。本文对应当前工作区的实现；完整约束见[资源配置设计](模型服务与权重资源配置设计.md)，项目整体结果见[当前实现](当前实现.md)。命名服务与权重配置不会代替平台分析器发现原入口、构造和拆分。

## 1. 从前端配置服务

打开独立配置页面 `/configuration`，通过分区导航进入“服务连接”，填写名称、协议、地址及原服务需要的模型 ID，选择其声明能力。“模型角色”“服务连接”“权重资源”“Harness 接入”“研究运行”和“入口范围”分别展示；在站内切换分区及返回对话／详情时保留未保存草稿，刷新或离开站点前需要保存。声明能力与实际调用结果分别保存。

连接卡片的“配置版本”是该连接执行配置的修订号，不是连接数量。编辑保留同一个连接 ID；登记另一个模型时先点“新增连接”或“新建”。

- `OpenAI 兼容`：可明确调用文本、图像或 embedding 操作，也可供三个平台模型角色选择。
- `原库 HTTP 服务`：供分析器核对原客户端的参数映射。连接检查只检查可访问性，不提供任意请求编排，也不把服务替换为平台聊天调用。

同机和实验室机器均填写平台进程能够访问的 HTTP／HTTPS 地址。`localhost` 指平台进程或容器自身。保存连接不会部署模型、复制权重或发起推理。地址中不能夹带用户名、密码或认证 query。

认证有三个明确选项：

| 选择 | 操作与含义 |
|---|---|
| 明确无需认证 | 仅在原服务无需认证时选择；缺少密钥不会自动变成此状态 |
| 私有保存的凭据 | 先保存连接，再在“连接私有凭据”中选择目标并单独保存认证值 |
| 平台进程环境变量 | 只填写变量名；值由运行平台的进程读取，不存入公开配置 |

凭据输入为空保留已有值。“清除所选连接凭据”才会明确清除。界面不会回填认证值。更换地址会解除原认证绑定，需要重新明确认证方式。仅改名保留执行配置身份；更换地址、模型或非敏感执行参数形成新配置版本。凭据轮换另存凭据版本。

“非敏感参数”是 JSON 对象。平台的对话、分析、教师模型及明确的文本／图像能力调用，会把其中字段直接合并到 `/chat/completions` 的请求体。例如，按 [GLM 官方对话补全文档](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)填写：

```json
{
  "thinking": {"type": "enabled"},
  "reasoning_effort": "max"
}
```

`temperature`、`top_p`、`stop` 等参数也使用这种直接字段形式，不包在 SDK 的 `extra_body` 内。平台不维护厂商与模型版本参数白名单；名称、类型、范围和组合须符合所选服务文档，不支持的参数由服务返回错误，不会静默删除后重试。空对象 `{}` 使用服务默认值。更新平台后，旧连接已经保存的 JSON 将对后续请求生效，调用前应核对。

- `model`、`messages`、`stream`、`stream_options`、`tools`、`tool_choice` 及旧式 `functions`／`function_call` 由平台管理，JSON 不允许覆盖；一次请求只处理一个回答，`n` 只能为 `1`。
- 最大输出优先使用独立“最大输出 token”字段。也可按服务文档在 JSON 中填写 `max_tokens` 或 `max_completion_tokens`，但两者只能选一个；若同时填写独立字段，数值必须相同，否则请求前明确报错。独立填写的输出值优先于模型列表发现的默认输出上限，不会被后者覆盖。
- 明确的 Embedding 能力调用将 JSON 合并到 `/embeddings` 请求体，例如 `{"dimensions": 1024, "encoding_format": "float"}`；`model` 和本次 `input` 由平台提供。支持标准 `float`／`base64` 向量返回，只保存数量、维度和用量摘要。参数是否被模型支持仍以原服务文档为准。
- Harness 原客户端仍只读取分析器生成、规则核对通过的 `parameters.xxx` 映射；平台不会把整个 JSON 自动塞进原客户端或改变原固定参数。

已选为模型角色的连接在保存、选择时核对请求字段冲突；明确能力调用也在发出请求前核对。实际参数进入分析记录的 `output_configuration`、训练模型／教师绑定的 `request_parameters`，以及连接能力记录的同名字段；续分析保留前后模型绑定，参数修改只作用于新请求。认证值必须走独立凭据入口，不能放进参数 JSON、Harness 初始化配置、来源资源声明或 URL。

旧版本曾保存但没有发送的非空 JSON 参数，升级后会改变实际请求。对应旧能力调用保留在历史中，不继续当作当前参数已核对的结果；需要时由用户再次明确调用，不自动发起请求。模型角色表单的最大输出输入框只回填用户显式值，不把服务报告的能力上限自动保存为用户设置。

## 2. 保留三个模型入口

“对话模型”“分析模型”“教师模型”分别选择已保存的命名连接并点击应用，也保留原角色配置表单。保存角色配置与保存凭据仍是两个动作。

分析角色沿用云端 HTTPS 和分析工具调用要求。某连接的文本调用成功，不自动证明它支持分析工具、视觉或 embedding。教师默认独立；需要复用分析角色时，在研究配置中明确选择，教师标准仍由用户在前端填写。

## 3. 区分检查连接与真实能力调用

连接卡片的检查对 OpenAI 兼容服务读取 `/models`；原库 HTTP 连接只检查登记地址。模型列表可访问只说明接口可访问，不表示原 Harness 已工作。

在“明确调用连接能力”中选择连接和操作，填写本次确实要发送的输入，再点击“使用上述输入调用一次”。这会发起真实请求，可能产生费用，页面刷新不会自动触发。

| 操作 | 输入与结果 |
|---|---|
| 文本 | 非空文本；非流式调用 `/chat/completions`，显示文本摘要 |
| 图像 | 非空问题及平台执行环境可见的本地图像路径；读取实际图像字节调用视觉接口 |
| Embedding | 非空文本；调用 `/embeddings`，仅保存数量、维度及用量摘要，不保存整个向量 |

能力结果单独保存请求数、用量、端到端时延、连接和认证版本；无法取得的费用或服务端推理时间保持 UNKNOWN。文本摘要最多保留 4096 字符。每项结果的 `target_execution` 仍为 `NOT_RUN`，因为它是服务操作核对，不能代替原库目标调用。

连接或认证引用发生变化后，旧操作结果保留在历史记录中，不作为当前配置的能力结果显示。相同 URL 也不能证明远端模型永久不变，未知服务版本仍需标记 UNKNOWN。

## 4. 登记权重及实际路径

在“权重资源”中选择目录或单文件，填写实际执行环境内的路径、已知模型 revision 和必要文件清单，再保存、检查。

Windows 平台填写 Windows 路径，Linux 平台填写 Linux 路径，容器内平台填写容器内路径。浏览器所在电脑的路径、`另一机器:/models/...` 或一个远端模型服务地址，都不能成为本地加载器可读的权重目录。

必要文件可以逐行填写相对路径，也可使用 JSON 列表，例如：

```json
[
  {"path": "config.json"},
  {"path": "model.safetensors.index.json"},
  {"path": "model-00001-of-00002.safetensors"},
  {"path": "model-00002-of-00002.safetensors"}
]
```

必要项可附已知 `sha256` 或 `bytes`。已存在的 Hugging Face 分片索引会用于核对所列分片。检查只读取文件和元数据，不导入原库、不反序列化 checkpoint、不加载或推理。空目录存在但没有必要清单时，不能据此判定模型资源齐全；仅路径、大小和 mtime 也不能证明内容身份。

检查结果分别显示缺失、类型错误、不可读、大小／摘要不匹配及文件存在。加载成功与目标推理成功由后续实际运行另行记录。

## 5. 让分析器提出依赖，再选择资源

接入固定版本的原仓库后，使用平台分析 API 自动预处理和分析。在“来源与分析”的 Harness 卡片中展开“依赖配置”，查看平台分析器提出且经过规则核对的需求。

1. API 依赖选择已登记的命名服务。
2. 可配置加载路径选择已登记、已检查的权重资源。
3. 原固定路径不提供无效覆盖输入；查看原位置、实际解析位置、必要文件和缺失项，在执行环境准备后重新检查。

保存依赖选择会保留原 API 分析产生的候选、原参数映射和构造，再做本地规则核对并形成新记录；该动作本身不需要重新调用分析模型。映射没有通过、资源不满足或构造不能保持原生命周期时，相关入口保留 MISSING，不由用户或开发者补写来源包装绕过。

原库直接操作模型对象时，继续使用原模型类、加载方式和 owner 生命周期。登记 HTTP 服务不会把它自动转换为 API 来源。当前跨机器范围只包含原库已经支持的兼容服务调用，不能借资源配置扩展通用 Unit 远程执行。

平台运行使用冻结的资源和认证配置；编辑用于新运行。原 owner 已缓存模型或客户端时，仍需符合原生命周期的新实例，不能用页面修改冒充旧对象已经更新。

## 6. 凭据位置与迁移

Windows 沿用当前用户 DPAPI。Linux 实现使用平台自己的私有目录 `0700`、凭据文件和同目录临时文件 `0600`，核对属主和权限后原子替换；已有不合适的权限会报错，不递归修改共享目录。Linux 私有文件依靠账号和权限保护，不是磁盘加密。

环境变量引用只保存变量名。外部终端修改变量后，已启动平台不会自动取得新值。原库的环境读取还必须符合分析器核对的读取时点；同一进程不逐调用临时改全局环境。

Windows DPAPI 数据不能直接复制到 Linux 解密。跨环境迁移保留非敏感连接与资源信息，在目标环境重新保存凭据或配置环境变量。不要把密钥放到命令行、Git、公开状态、分析上下文或研究工件。

源码中出现明确认证字段的非占位字符串字面值时，该文件会标记 `WITHHELD`。新快照不复制其文本，前端与分析工具只返回文件、单元、行号和原因；旧快照保持原样，但新读取也会阻断。此检查针对有限的明确字面值，不构成对任意源码秘密流的证明。原库无合法配置入口时，相关绑定继续 MISSING。

| 接口 | 用途 |
|---|---|
| `POST /api/connections` | 保存非敏感连接配置 |
| `POST /api/credentials` | 独立保存、保留或清除凭据 |
| `POST /api/models/select` | 为 chat／analysis／teacher 选择命名连接 |
| `POST /api/connections/check` | 明确检查连接 |
| `POST /api/connections/invoke` | 使用本次明确输入调用已声明能力 |
| `POST /api/weights` | 保存权重路径及必要文件信息 |
| `POST /api/resources/check` | 明确检查已保存权重 |
| `POST /api/harnesses/bind-dependency` | 为分析器核对的依赖选择资源并重新核对绑定 |
| `POST /api/harnesses/check-dependency` | 检查原固定资源放置位置 |

普通 `GET /api/state` 只观察状态，不触发下载、哈希大权重或推理。

## 9. 分析、训练观察与导出

“来源与分析”显示预处理、入口／拆分和规则／绑定阶段，以及已报告的分阶段输入、输出和总 token。等待响应的请求可能尚无用量；阶段完成不表示资源齐备或原目标已执行。完整详情还可查看本记录冻结的模型与请求参数。

- “导出当前进度”：随时读取 `GET /api/analysis/<id>/snapshot`，下载 `seampact-analysis-progress/1` 观察快照；包括已保存阶段、用量、工具读取元信息和候选检查汇总，不含原消息、源码正文、凭据或机器路径。它不能导入，也不能恢复正在执行的分析。
- “导出完成候选”：完成且有候选的分析使用原 `POST /api/analysis/export`。该工件可在目标平台按原接口重新核对；带有旧机器绝对路径的候选不能直接导入。
- “调度器”：进行中的研究运行自动加入观察，显示已完成任务／窗口进度、实际回报曲线、分项覆盖及已有联合模式表格。任务／窗口内部的执行状态继续从“任务详情”和运行组观察；回报与研究结果在完整任务／窗口边界更新。
- 每条研究运行均有“导出当前结果”，点击时重新读取最新落盘结果。`seampact-research-progress/1` 包含运行清单、已保存轨迹及曲线，并标注未完成状态；它是私有结果快照，可能包含任务证据与本机路径，不包含内存状态或策略权重文件，也不是可恢复 checkpoint。

这些观察和导出不会启动模型调用、分析或训练。页面刷新继续读取原持久状态。
