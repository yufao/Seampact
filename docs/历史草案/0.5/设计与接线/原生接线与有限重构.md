# 原生接线与有限重构：0.2.0 实现说明

更新：2026-10-11。当前交付两类确定性规则。Agent 负责发现候选、引用冻结来源、描述原生宿主；引擎负责检查规则前提和生成产物。模型不编写替代算法，也不自行宣布行为核验通过。

## 1. 接线究竟交付什么

W／普通 H 草案保留原 callable，由已有原生 owner 提供方法对象。注册列表型 H 多交付一个安装函数：宿主在原 setup 前安装，原初始化照常创建工具对象，安装函数在初始化返回时把指定 callable 替换为等待许可的代理，随后原 SDK 登记这些代理。

例如 MMCT 的原顺序是 `setup → _initialize_tools → _initialize_agents → 原团队运行`。代理放在工具初始化和 AutoGen 登记之间。原 Planner 仍选择是否调用 Vit，AutoGen 仍处理参数、工具返回和继续；SeamPact 只在已激活的调用开始前等待许可。门禁不包住整个 Planner，也不把图像重新编码成另一套算法。

引擎输入的结构化描述包含冻结 controller 文件／单元／类、原 initializer、列表属性、SDK intake 和 setup。有限 AST 检查确认列表写入、指定方法追加、SDK `tools=` 接收和 setup 源码顺序。这个 PASS 只表示锚点存在；分支可达性、别名闭合、回调与 SDK 真正保留了哪个对象需要动态探针。

同一原初始化发生可创建新工具，门禁为新工具生成新的身份。已包装列表不能再套一层。一个安装点存在冲突方案时，草案不能作为“全部同时安装”的包构建；能力族的备选版本和 TaskPlan 选择仍需后续实现。

SDK 若要读注解生成 schema，可以显式采用 `resolved-types`：在原方法命名空间解析类型，再把解析后的签名交给 SDK。注解求值的外部效果仍是独立待核验项。

## 2. R 确实生成代码，改动范围很窄

第一条规则为 `sequential-async-loop-body/1`。输入只指定冻结文件、代码单元、类的异步实例方法和顶层 for 的序号。引擎计算循环体的输入变量，创建一个异步 helper；原循环体改成 `await self.helper(...)`。没有提前把迭代器变成列表，没有把 Context 读取移到循环外，也没有复制模型或数据对象。

```python
# 原顺序
for node in retrieved_nodes:
    llm = await ctx.store.get("llm")
    response = await llm.acomplete(prompt(node))
    results.append(response.text)

# 提取后的原顺序
for node in retrieved_nodes:
    await self.helper(ctx, node, results)

async def helper(self, ctx, node, results):
    llm = await ctx.store.get("llm")
    response = await llm.acomplete(prompt(node))
    results.append(response.text)
```

例子用于解释，实际 helper 名和参数由源码分析得到。宿主加载独立的 `patched/` 工件后，在 helper 上安装门禁。原方法仍负责迭代、汇合、Context 写回与结果外发；helper 每轮只负责原有循环体，列表与对象按原别名传入。整个父方法不占住子 helper 的执行槽。

首条规则只支持直线局部赋值／调用。跨轮标量回写、循环体局部变量在循环后继续使用、修改 self／循环变量、break／continue／return、嵌套控制流或词法作用域、global／nonlocal、反射、未证明已初始化的输入均拒绝。更多形式以后需要独立规则和义务。

原工件在 `source/` 逐字节保留；Python 改动另存 `patched/`。Notebook 只替换指定 code cell 的 source，其他单元、输出、资料字段保持原值。AST 输出会调整代码排版和注释，不视为数据转换。没有执行 Notebook 顶层初始化或下载模型。

## 3. 数学检查与行为检查分别做什么

逆检查器从交付代码中取出 helper，确认接口和调用点，再把循环体放回原位置、移除 helper，比较整个原代码单元的 AST。它还从原源码独立重算规则和参数，拒绝伪造 recipe、helper 注解副作用、循环外改动或调用点改动。多处提取逐次记录输入／输出 hash 和逆检查。

这证明的是交付代码符合该有限结构变换。语义对应另依赖前提：对象别名按原方式传递；被观察的行为不包含 Python 栈布局、新方法枚举和 traceback 栈帧；原依赖行为仍由原宿主承载。动态探针比较冻结观察契约中的结果、读取／外发／写回顺序、异常和取消。排队延迟及真实超时不由 AST 一致性保证。

拆出 helper 不等于它可以独立导出、并行或远程调用。需要另验完整状态入口、跨项效果交换、故障下允许的外发，以及资源／生命周期闭合。0.2.0 的生成包保持 `BUILT_DRAFT`，逐操作 `admitted=false`，网页不会自动执行原工件。

## 4. 这次实际证据

| 检查 | 证据范围 | 结果 |
|---|---|---|
| MMCT Vit 注册和继续 | 固定原源码；AutoGen 0.7.5 真 SDK；真实 4×4 PIL 图像；受控模型回放；引擎生成 H adapter | 红／蓝图像、原 provider 异常共 3 情况 PASS |
| MMCT 负对照 | 在 SDK 登记之后才包装 | 实际绕过门禁，被探针检出 |
| CRAG R 提取 | 原 cell:10 的精确方法体；引擎生成 patch／adapter；受控 Context、LLM、event 和迭代器 | 空输入、逐项模型变化、循环体失败、迭代器失败、取消共 5 情况 PASS |
| 原 SDK 全流程／模型质量 | MMCT 完整可选后端、CRAG 实际 Workflow、在线模型及数据 | NOT_RUN／UNKNOWN |

CRAG 探针不执行整个 Notebook：取原方法／helper 的 AST，去掉 import、类继承、step decorator 和类型注解后装进受控宿主。方法体保持原内容。它用于检测顺序提取是否改变读写／失败行为，不证明 LlamaIndex Workflow 登记和生命周期已经贯通。

两套探针手工选取候选，属于规则和构建器的开发检查。正式自动拆分比较仍必须让 API 从来源自行发现切点；不能把这些预选候选作为“自动发现成功”的结果。

## 5. 开发复现

核心平台不需要第三方包。CRAG 片段机制探针直接运行：

```powershell
$env:PYTHONPATH = 'src'
python -B tools/probe_crag.py <LlamaIndex来源根> <独立结果目录>
```

MMCT 的真实 SDK 探针使用独立 CPU 环境，依赖版本见 [可选依赖](requirements-sdk-mmct.txt)。开发环境可以单独创建虚拟环境并在其中安装这些包；它们不是核心平台启动依赖，也不要求现在在共享服务器安装。发布包附带同修订的所选原源文件，可从 `sources/mmct-image` 运行探针。

```powershell
$env:PYTHONPATH = 'src'
./.venv-native/Scripts/python.exe -B tools/probe_mmct.py <MMCT来源根> <独立结果目录>
```

当前开发结果及完整依赖版本保存于研究工作目录的 `implementation/seampact-core/native-probes/`。真实 API 凭据、GPU、服务器部署都没有参与这些机制检查。
