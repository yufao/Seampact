# SeamPact 组会讲解稿

更新：2026-10-13，工程版本 0.6.0。当前原型聚焦异构 Harness 自动接入、有限拆分与两层 RL；旧 0.5 CRAG 专用任务及旧结果在历史草案中，不作为当前进展依据。

## 1. 研究问题

已有 Harness 不只包含算法函数，还包含原生对象、初始化、配置、数据资源、框架控制和返回路径。直接将函数列成工具，不能保证它在新任务中有正确的输入与运行上下文。

我们的目标是让接入者填写仓库 URL／本地目录，系统自动寻找真实能力入口，保留原算法和原生执行关系，形成能够被对话任务调用并被 RL 调度的 Unit。研究对象是通用分析器和调度逻辑。

## 2. 用户看到什么

首页是正常 AI 对话，配置里设置两种模型角色和 Harness 地址。分析结果进入能力池；对话根据真实能力接口提出调用方案；侧边栏显示真实任务、激活 Unit、时延及调度状态。

没有能力时也能普通对话。不存在必须选择预设来源、填写预设问题与资料、运行固定工作流的主流程。

## 3. 分析器怎样工作

接入读取整个目录结构。云端模型通过源码工具理解入口、导入、初始化、资源和控制关系，提出 `entries` 与 W／H／R 边界。机械引擎对照真实源码检查参数、位置和受支持规则，形成原生绑定。

API 负责发现，不能靠“安全／独立／可并行”的自述授予运行条件。复杂对象绑定或依赖缺失时，候选仍在能力池中显示缺失原因。

## 4. 拆分究竟改变什么

采用“包装／原生接入＋有限局部重构”。W 在原 callable 外加等待许可；H 在支持的原生注册点接线；R 只提取规则覆盖的顺序异步循环体。原 controller、owner、数据和算法保留。

一个完整 Harness 可以发现多个能力，但共享 owner 的能力不等于多个独立进程。内部边界通常仍由原 controller 触发，不能被对话模型随意启动。

## 5. 两层 RL 怎样参与

上层在对话 API 提交的同一要求下的完整可执行方案中选择。下层在原 controller 已使能、owner 和资源条件允许启动的调用中选择。两层均采用在线表格 Q-learning；合法集合由引擎和运行时提供。

首版参数是 `α=0.2`、`γ=0.9`、`ε=0.1`；奖励为成功 `+1`／失败 `−1`，减去 `t/(1+t)` 的时延项。方案步骤目前顺序执行。

这是用户批准的简单算法实现，不代表奖励已覆盖最终任务质量。只有一个候选时没有选择空间；Q 表发生更新也不能直接当成调度效果提升。

## 6. 当前工程交付

| 核心部分 | 当前实现 |
|---|---|
| 交互 | 标准对话首页，独立模型角色和自由地址配置，实际运行观察 |
| 分析接入 | 全目录结构与源码工具，真实 API 分析，有限原生入口绑定与 W／H／R 接线 |
| 调度 | 上层方案与下层已使能调用进入同一个原生运行时，两层 Q 表与实际反馈 |
| 部署 | 原生 Python 启动或一个 Docker 平台服务，状态与用户 Harness 在私有挂载目录 |

入口绑定支持有限 Python／Notebook／原仓库 CLI。其他语言可进入结构分析，但没有自动兑现为原生执行支持。缺依赖、动态 SDK 接线和复杂对象输入不会被隐藏。

## 7. 理论中的关键区分

三个区分帮助避免把工程结果讲成更大的理论结论：

- 发现边界、形成静态绑定与真实调用是不同事实。`READY` 只表示当前结构可绑定，初始化在实际调用时发生。
- 原流程内排期与供新任务调用不同。内部边界保留原 controller，独立入口必须具备输入和初始化条件。
- 多能力、可组合、可并行与可远程不同。当前方案可以顺序选择能力，未开放并行与远程。

候选创新是用原生状态、效果和继续关系约束自动接入，再让学习策略只在当前合法选择空间中决策。其理论可靠性、相对已有工作的差异和调度收益仍需证据支持，当前不宣称已证明。

## 8. 演示讲解顺序

打开普通对话；展示两个独立模型角色和一个用户指定的 Harness 地址；打开分析记录和能力池，解释 READY／MISSING；提交真正需要已接入能力的任务；结合实际任务记录讲解上层方案、下层调用和返回路径。

若尚未填模型或没有 READY Unit，就如实展示当前配置／缺失情况。没有产生真实 Harness 调用时，不把普通模型回复讲成拆分调度的成功结果。
