# 上下文记忆与来源更新

更新：2026-11-01，作为 0.14.9 的继续增补。本地实现与核验完成后再更新远端；没有触发真实模型、远端拉取或自动安装来源。

## 对话与正式实验的路径

普通对话的模型可以提出 Harness 方案，经已安装 Unit、现有调度器及原生 owner 执行。它适合交互使用和功能核验。选择冻结场景任务、正式训练及评价时，执行走 SceneSession／SceneContext 与冻结工作集；界面输入不会取代冻结样本。

本次上下文整理应用于普通对话和分析，不自动改变正式场景的模型输入或 RL 决策规则。对话记忆按会话隔离，分析记忆按冻结分析会话隔离，不能把前一个测试样本的答案带入后一个样本。正式实验若要比较记忆策略，须另在工作集与各对照臂中明确固定，不能从交互演示直接报告效果收益。

## 窗口展示与接近窗口时的处理

在命名服务连接或模型角色中可以填写“上下文窗口”和是否自动整理。窗口来自用户明确填写或服务模型元数据；未知时显示未知。窗口与整理开关是平台配置，不发送成模型 API 的请求参数。

对话输入旁、任务及分析详情显示模型窗口、当前输入估算、输出预留、上次服务实际返回的输入 token 和整理次数。初始估算采用可见文本字节的近似值，获得同一冻结绑定的实际用量后可以校准。估算不等同准确分词；含图像／音频时不显示完整占用百分比。可用输入预算是窗口减去所请求输出额度；输出预留占满窗口时会明确提示配置冲突。

已知预算达到高水位（当前为 80%）时，在完整工具回复边界整理旧上下文。保留系统要求、原任务、当前用户要求、最近消息及最近完整工具调用／结果；图像消息保留原形式，不把 base64 当文本交给摘要模型。旧历史先归档，摘要只作非权威资料，附原记录引用。摘要不能替代源码、执行结果或新的检查许可。必保内容本身过大或摘要没有缩小时明确报错，不悄悄删除必需内容。

整理使用该任务冻结的同一模型连接，本次摘要有独立的小输出额度，业务请求的输出配置不被修改。摘要的调用次数和服务用量单独留痕，也计入任务／分析总用量；摘要调用中断时用量为未知，不能记作零费用。关闭自动整理后不会因接口超限自动整理普通对话。

## 记忆工具与续接

普通对话保留可见历史与服务端完整工具轨迹；客户端只能追加当前问题，不能替换过去的消息。工具结果归档后可以用 `read_conversation_memory` 按引用和 JSON Pointer 分页读取。再次提问会使用服务端保存的上下文和工具依据，中断留下的未完成工具调用会标明结果未知，不自动重跑 Harness。

分析使用 `read_analysis_memory` 读取当前分析归档、`read_analysis_report` 读取完整检查报告，以及 `read_revision_facts` 读取当前材料身份下的缓存结构事实。材料绑定源码版本、输入／资源摘要、解析器、提取器和检查实现。摘要和旧报告可帮助定位；当前映射、构造、边界和运行组仍要完整重检。

明确超限后，有候选时可从最近候选开启新会话；尚未形成候选但已有完整工具回复边界时，可点击“整理上下文后继续”。模型传输或整理请求中断，也在完整已保存边界继续；不会回放已执行的 Harness。修订续接保留原任务、指导信息和材料引用，草稿、来源或生成配置已变时，应从当前草稿发起新的修复。无法确认的旧 HTTP 400 不自动追认为超限。

## 资源接入与原库更新

| 情况 | 使用现有入口 | 可以复用与必须重检的内容 |
| --- | --- | --- |
| 只补服务连接或权重 | 所需资源中选择并保存检查，零模型重新接入 | 原候选映射可继续核对；实际所选资源、凭据／文件条件和目标运行独立验证 |
| 改进当前候选 | 修订台创建候选修订，补指导后模型修复或人工修改，完整检查后独立安装 | 复用同版源码结构材料；旧 READY 不直接继承，完整候选保留仍需使用的入口 |
| 原仓库有新提交或本地源码变化 | 修订台选择“源码更新”，指定原仓库的分支／标签／提交或重新读取本地目录 | 原有流程已支持重新获取、冻结新版本和 added/removed/modified/unchanged 差异；新增能力仍须调查，旧文件字节及历史结果保留 |
| 源码、配置、资源或平台实现改变 | 对新冻结输入核对并修订 | 材料身份变化使旧检查身份失效；同字节结构事实可按摘要复用，映射、资源选择和许可要求当前检查 |

本次补强了源码更新的材料身份，以及运行证据的版本范围：同名服务、同名映射或相同参数名，不会将旧源码／旧资源下的执行成功带到新版本。原结果回写也须匹配实际运行的源码、输入及绑定版本。

修改连接或权重登记，不会悄悄替换已冻结选择；需要在来源下显式选择新版本并零模型重检。源码更新形成草稿不会自动替换当前已安装入口；完整检查并独立安装后才改变当前能力池。

## 借鉴的实现模式

本轮核对了 [LangGraph 的会话记忆与历史整理](https://docs.langchain.com/oss/python/langgraph/add-memory)和 [PydanticAI 的消息历史处理](https://pydantic.dev/docs/ai/core-concepts/message-history/)，借鉴请求前处理、完整状态与活动上下文分离、检查点及工具消息边界的做法。实现复用平台已有存储和模型接口，没有另接一套 Agent 框架、向量数据库或跨任务用户画像。资料核查日期：2026-11-01。

最终完整本地 **334 项测试通过，无跳过**，前端语法、上下文用量展示组件及差异格式检查通过。软件测试、模拟模型摘要及本地源码更新用于验证实现；不能替代真实长会话质量、原目标防护效果或正式资源调度实验。最新验证范围见[当前实现](当前实现.md)。
