# 工作区、知识资料与会话记忆

更新：2026-11-11。项目数据管理、项目数据挂载与隔离 Python 执行已进入更新后的服务；完整检索能力已在同一 Agent 办公任务中调用并完成交付，跨实例持久索引复用也已验证。该合成任务不是正式基准；七个办公防护来源、正式数据集和 PPO 训练仍未接通。

## 项目、会话与任务

项目是资料与会话的归属边界，无需先接入任何harness或RAG就能创建。一个项目管理多段会话；一段会话包含多次任务执行，并持续使用自己的工作区。默认项目让普通用户直接开始使用，不要求先配置目录或容器。初版是本地研究平台的组织方式，不新增多租户身份系统。

项目共用资料对业务工具只读，会话工作区可写；两段会话的修改不会相互覆盖。上传资料进入项目受管目录，业务模型需要修改时另写工作区。任务临时目录只承载本次执行的中间文件。工作区和资料均通过受限文件工具按需读取，不随消息全量载入上下文。

实验场景可以作为一个项目，任务执行使用独立会话／工作区或按原协议延续会话。场景名只是项目配置，不进入存储实现；训练与评价各自绑定数据和运行身份，同一项目不意味着可以互读答案或共享可写实验状态。原始输入、评分与冻结结果单独保留。

清理分清对象：任务结束且调用已收尾后自动删除临时文件；工作区在用户明确清理时删除；删除历史会话只是隐藏记录，不能暗中清空文件。清理项目临时数据不删除项目资料、交付件或实验记录。归档项目保留数据并停止新增工作。进程重启后无法确认的在途使用继续阻止清理，待确认实例已结束再释放，不靠超时猜测数据已无人使用。

项目资料也可由用户明确逐文件删除；这与自动临时清理分开，且必须没有在途使用。已交付的文件副本与实验冻结输入不随之删除。不能因资料可读就允许业务模型自动删除项目共用输入。

镜像、权重等可复用资产归平台管理，项目只是引用者，不为每个项目复制一套。移除项目引用不等于删除共享资产；镜像回收还须核对实际容器和其他引用。当前不增加全局自动清空或磁盘清扫器。

## 四种不同对象

| 对象 | 作用与所有者 |
|---|---|
| 当前上下文 | 本次模型调用实际看到的消息和选定材料，受上下文长度约束 |
| 会话记忆 | 宿主持久保存的对话、摘要、轨迹及引用，按需读回 |
| 会话工作区与任务临时空间 | 会话文件跨调用保留；本次任务临时文件在执行收尾后清理 |
| 知识资料与索引 | 可跨任务复用、有版本和访问范围的外部文档及检索资产 |

ReAct式模型—工具—结果循环是运行方式，不是另一种存储服务。RAG从有权限的知识资料中检索片段，业务模型再使用它们；没有必要把整个知识库放进上下文。会话持久化与语义检索分别提供，首批不另做向量长期记忆系统。

## 精简宿主和基础工具

已采用 Pi Agent core 1.5.2 的模型／工具循环和上下文接口。平台已有的项目文件、受限 Python 和会话归档作为工具提供给 Pi，不引入 coding-agent 的另一套文件和会话存储；企业知识库 RAG 仍是外接能力。[Pi Agent 核心](https://github.com/earendil-works/pi/tree/v1.5.2/packages/agent)

工作目录cwd只决定路径起点，不提供隔离。文件工具须检查归属、规范路径与符号链接，代码／命令在受限的执行容器运行。若直接复用Pi文件工具，也要放在相应隔离边界内。宿主只看到授权工具和结果，调度器不靠修改cwd获得安全保证。[Pi安全说明](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/security.md)

初始基础工具包括列目录、按范围读文件、写／编辑文件、受控运行代码、登记交付件和读取会话记忆。生成能力通过相同的资产引用读取输入；RAG另外暴露检索操作。无需开放任意宿主机路径或将文件内容全量塞进提示。

## 镜像、数据卷和生命周期

镜像保存代码、依赖和固定配置；任务数据、知识资料、索引与权重按身份登记并挂载。沿用现有Docker后端，不额外部署存储集群。

| 逻辑空间（容器内示例） | 访问与清理 |
|---|---|
| `kind=data, form=project, area=data` | 资源以不可变 `project_id` 绑定；通用 worker 路径为 `/work/projects/<project-id>/data`，只读。隔离 Python 的活动项目资料挂在 `/data`，也只读；跨项目访问由路径检查和工具过滤共同限制 |
| `kind=data, form=project, area=indexes` | 路径为 `/work/projects/<project-id>/indexes/<namespace>`；namespace 由能力包摘要前 24 位生成。索引持久可写，worker 释放后保留，能力包身份更新时使用新命名空间 |
| /models | 已登记权重，只读复用；停止模型实例只释放内存，不删权重 |
| /workspace | 当前会话的可写文件空间；后续工具调用看到同一份变更 |
| /scratch | 单次任务临时文件，无引用且调用结束后清理 |

交付文件先登记到独立的工件存储，再按生命周期清理工作区；不能先销毁容器再假定文件仍可下载。会话继续工作时保留工作区使用权；冻结实验记录引用其实际输入与交付版本。业务文件、模型缓存与实验轨迹各自保留，不用一个目录承担全部用途。

不同能力只挂载需要的空间。完整检索能力读取授权知识资料和索引，并在同一实例内按需加载 embedding 与 reranker 权重；代码工具只读项目资料并读写当前工作区。可写索引当前采用单一所有者、并发度 1，不配置副本；不允许多个 worker 无约束并写。

平台根据数据资产ID、版本、归属和读写模式生成挂载及容器内路径。用户选择一次资料集合或工作区；已有映射自动复用，不为每个能力填写Docker卷。缺少真实数据、权限或版本冲突时再询问。外部目录默认只读，任务修改在受管副本进行。

## RAG作为接入能力

当前完整检索能力 `search_documents` 使用官方 Haystack 2.31.1；该版本的 Sentence Transformers 组件仍与 Haystack 同仓，3.x 已将这些组件移出主仓。只使用检索能力，不启用其 Agent 宿主。能力提供关键词／dense 检索、可选重排和带来源的结果。结果包含文档／片段 ID、来源版本、位置及得分，Agent 可继续读原文或换查询。

英文资料的本地模型为 BAAI/bge-base-en-v1.5 和 BAAI/bge-reranker-base，已从官方仓库按固定修订下载；embedding 与 reranker 权重在同一个完整检索能力实例中按需加载。业务模型与分析模型继续使用现有远程服务。业务模型已在同一 Agent 办公任务中调用该能力并使用检索结果完成工作、交付文件；三次 dense+rerank 调用的引用与交付结果已核对。该合成任务不代表正式基准或七库防护实验。

语料分块和文档向量预先准备，计入准备成本；每次在线向量检索只编码当前查询，不能为制造资源压力重复编码全库。首批使用本地资料与可恢复索引快照，无需向量数据库服务。InMemoryDocumentStore只是运行时内存结构；必须明确将哪些分块、向量或索引导出到卷，并在实例初始化时加载／构造结构，不能将挂载原文档等同索引已经持久化。[Haystack存储说明](https://docs.haystack.deepset.ai/v2.9/docs/inmemorydocumentstore)

当前把检索作为一个完整能力包和同一个实例调度、部署。它读取授权资料与索引，支持关键词／向量检索和可选重排；embedding 与 reranker 权重按实际调用路径在该实例内按需加载。内部方法不拆成独立 Unit，也不宣称两组权重可分别驱逐。只有后续实测证明拆分能带来明确的资源或调度收益，才考虑独立部署；否则维持完整能力。

首批知识库是固定只读资料。Agent新写文件保留在工作区，直接文件工具可读取，不自动发布进共享知识库。未来需要发布／更新时显式形成新语料和索引版本并切换，保留在途任务所绑定版本。索引身份至少覆盖语料、分块方法、embedding模型及配置，防止模型更换后误用旧向量。

检索前按用户／应用的数据范围过滤，检索返回在进入模型前经过适用防护。模拟攻击的语料版本或返回内容不得被干净缓存绕过，缓存身份覆盖实际材料与权限范围；正常／攻击、训练／评价不能通过索引混用泄漏。

## 当前实现与差距

更新后的服务已接入项目创建／选择、项目资料上传下载、会话工作区、逐文件删除与显式清理。默认项目承接旧会话，续聊不能改换项目。业务模型可列目录、分页读取UTF-8文本、写会话文件并交付文件；上传支持二进制，宿主文本工具本身不解析工作簿或 PDF。文件工具不接收主机绝对路径，不开放主机命令执行。

更新服务后的使用入口在对话页：选择或新建项目，在“项目资料”中上传文件，发送任务后可切换查看当前会话文件。新对话保留项目共用资料，另建工作区。单文件上传上限16 MiB，列表一次展示至多200项，文本按页读取；大资料集合的索引导入由后续RAG接入处理。清空工作区须明确确认，单文件删除不影响已保存的交付副本。

项目实现独立于RAG和宿主选择，位于[项目空间](../../src/seampact/project_spaces.py)与[文件工具](../../src/seampact/workspace_tools.py)。普通聊天已连接任务占用与临时目录收尾；不确定调用保留占用，清理前按真实调用及实例状态重新核对。开始任务与文件操作只查询相关活动占用，不读取全部完成历史。

Docker PythonExecutor 已实跑项目 `/data` 只读、会话 `/workspace` 可写、超时限制，以及 XLSX 读写和结果交付。通用 worker 挂载按资源类型和项目归属过滤，索引卷使用能力包身份隔离并在 worker 释放后保留。当前可写索引只有单 owner、并发度 1，不配置副本；同项目新会话已在冷启动的新实例上复用持久索引。Pi 1.5.2 已接管业务循环，迁移后的检索与交付链路运行成功。AgentDojo 原生评分已经接入；七库防护应用绑定和完整调度实验仍在推进。

## 已有会话与来源更新

普通 Agent 保存对话上下文和实际工具轨迹。过长工具结果可以归档，通过 `read_conversation_memory` 按引用与 JSON Pointer 读取；继续对话时由服务端恢复，客户端只追加新内容。

流式正文在活动任务中保留有限事件队列，终态保存；失败的部分正文标注未完成。重连读取已有事件，不重放可能已执行的工具。每个工具只有参数完整之后才执行。

来源生成独立于聊天记忆，从冻结仓库按需列出、检索和读取文件，限制上下文及自动修复次数。依据不足时继续读取或报告缺口，不将未知判断为成功。来源引用、生成包及验证身份属于这一次输入。

重新生成会形成新的包内容身份，可以复用确定的资源；旧验证成功不自动移给新能力。在途实例未释放时拒绝覆盖安装。远程仓库更新以对应版本重新提交和冻结，旧源码与调用记录保留。

历史摘要分页或按标识读取。普通轮询不读取全部工具轨迹，不重装全部历史分析，也不启动旧训练器。实际范围见[当前实现](当前实现.md)。
