# 当前实现与边界

更新于 2026-11-14，源码版本 0.16.0。目标见[平台设计](Harness接入与调度重设计讨论.md)，后续工作见[实现计划](实现与落地计划.md)。部署版本和运行结果以对应运行目录的记录为准。

## 执行主线

完整仓库 → 读取代码、配置和说明 → 生成能力包 → 准备独立运行环境 → Agent 按需调用 → 流式正文或文件交付。

总入口已改用新能力包，不再自动恢复旧分析、安装旧 Unit 或启动旧训练器。旧记录可查看和导出；旧检查点不会自动载入新策略。实例身份、调用排空及后端释放机制继续复用。

## 仓库接入

生成器冻结仓库，按需读取源码、依赖和示例，产出能力描述、标准适配与复用源码。平台检查接口、内容身份、生成代码语法和引用；可修复错误在同一任务内有限处理。默认保留完整用途，多个方法可以共用一个实例，不因函数数量而拆容器。

当前分析目标是接入外部来源；来源 ID、路径、参数和运行环境由本地流程解析，生成结果保留来源追溯，不要求手写 adapter。新入口先做快速清点并跳过旧式入口点分析，再按需读取源码、依赖和示例。清单以分页方式返回元数据、资产与未读取项，避免一次性把大清单塞入分析上下文；文件元数据按需复用，避免对同一文件重复探查。本轮还修正了修复上下文、把字段检查前置到执行前，并使大包导出不阻塞状态读取。本次适配明确关闭了来源遥测；已验证的是生成能力的实际路径，不等于整个来源库的功能等价。

平台从已登记资源中自动匹配无歧义的连接、权重和确定默认值。项目资料以 `kind=data`、`form=project` 绑定不可变项目 ID；通用 worker 路径为 `/work/projects/<project-id>/data` 且只读，隔离 Python 将活动项目资料挂入 `/data` 且只读。索引路径为 `/work/projects/<project-id>/indexes/<package-digest-prefix>`，前缀取能力包摘要前 24 位；索引可写并在实例释放后保留。跨项目访问由路径与工具过滤共同限制；可写索引当前采用单一所有者、并发度 1，不配置副本。Docker 权重继续只读挂载。缺失文件、资源冲突或不能确定的条件显示为具体缺口。

能力包自动安装、准备镜像，并对具有源码依据且效果允许的样例首调。未通过首调的生成能力不进入 Agent 工具列表；明确人工调用成功也可开放相应能力。镜像构建和业务首调分别记录。

生成的检查能力声明检测类别、适用对象、所需证据和源码位置。生成器按宿主支持的输入输出接口校验声明，项目用同一接口匹配检查。项目启用的多个库可以提供同类检查，每个可调用的实现各自进入候选。当前支持文本清理、注入、隐私、凭据、代码安全、输入安全、输出安全和事实支持八类接口。新库可复用已有接口，全新输入或判定类型需要扩展宿主契约。

业务工具声明读取、检索、写入、外发或执行等效果。接入库由分析器生成声明，场景自带工具由提供工具的环境声明。Pi 宿主随实际调用传递工具来源、效果及当前阶段。同一发送检查因此可挂到不同项目的发送工具。项目选择参与的库、隐私检测的实体类别和发现问题后的处置。一项检查能否运行取决于该阶段、可见材料和实例可用性。

续改先核对冻结源码、包和已接受的提案，并继承已验证的运行环境。大候选通过内容摘要和分页读取进入模型上下文。编辑按候选身份修改局部代码、契约和证据，完整保存后仍经过包校验。请求按分析模型的窗口预留工具描述和输出预算，文字用保守估算，实际输入量依赖服务端回传。模型窗口未知时使用本地预算。

## 通用 Agent

正常流程为输入、模型流、完整工具参数、能力调用、工具结果回传及交付。Pi Agent core 1.5.2 已接管模型与工具循环，Python AgentRuntime 只提供平台连接和执行边界。普通对话与实验使用同一路径。业务模型和分析模型由现有远程服务承载，本地检索模型由能力实例管理；调度器决定合法请求的执行时机和实例生命周期。

宿主在输入、工具调用前后和最终交付前提供挂载点。办公项目默认把首次适用的防护检查交给策略选择。外发前选中的检查拒绝内容时，仅扣住这次调用，模型收到工具错误并可修改，后续适用外发重查该检测项。交付检查可要求同一 Pi Agent 修订一次答复。修订只生成文字，已有工作与文件保留，拒绝项复核通过后才能交付。两种处置都记录在任务事件中。项目可显式配置整任务终止。

取消停止继续交付，并请求取消在途操作。工具在安全点退出才记为确认取消；关闭 HTTP 流不证明远端模型停止计算或计费。流中断不重放可能已经执行的调用。

会话继续使用服务端记忆；活动流只留有限事件队列，终态写入记录，历史分页读取。文件以内容身份提供下载。

服务已更新项目管理、项目资料上传下载、会话工作区和明确清理入口。项目管理多段会话，续聊复用同一工作区；业务模型可列文件、分页读UTF-8文本、写会话文件并交付。项目共用输入对模型只读，文件交付保存独立副本。任务占用在实际收尾后释放并清理临时文件；运行中或无法确认的占用阻止相应清理。旧会话按默认项目读取，无需重写全部历史。

会话记忆、文件工具和RAG分别承担不同用途。Docker PythonExecutor 已实跑：项目 `/data` 只读、会话 `/workspace` 可写，超时约束生效，工作簿读取／写入及结果交付可用。结构化处理由隔离 Python 执行。Haystack 2.31.1 与固定修订的 BGE embedding、reranker 已接入完整 `search_documents` 能力；两组权重在同一实例内按需加载，不拆成独立驱逐的 worker。迁移后的 Pi 业务链路已多次调用检索、隔离 Python 并完成文件交付和任务清理。

## 调度与目标

已实现的候选包含可选防护／继续、就绪调用派发及空闲实例保留／释放。容器按需启动，温实例复用，释放前排空并确认后端消失。规则默认按期限和 FIFO 派发；只有一个合法动作时直接执行，不制造学习样本。

调度配置显式开启 `elastic_actions` 后，真实排队调用可选择按需预热；可复制组存在真实积压、实例满载且未达 `max_replicas_per_group` 时，可选择增加副本或等待。已有空闲实例的排空释放同时承担缩容；可写项目索引组不复制。预热和扩容不使用预测的未来请求，规则默认优先派发、对扩容选择等待；开发压力探针可另设规则 `scale_when_saturated=true`，只在实际存在合法扩容候选时选择它。异步弹性操作的实例进入同一资源账本，工作负载收尾等待操作和实例释放；取消、失败或资源未知保持实际状态。特征版本已更新，旧 PPO 检查点不能用于新动作。办公驱动可按冻结的到达段派发。启用 `arrival_schedule` 时，段内后续波按相对时刻发出，`arrival_width` 限制同刻到达数。表格和模拟外发使用任务自己的只读输入，涉及共享检索资料切换的题单独成段。段间等在途任务收尾，实例生命周期由策略决定。

PPO 用同一网络为各个合法候选打分。规则基线共享候选与项目处置。策略看到操作阶段和效果、证据覆盖以及本次已有的检查反馈，每个候选还带有同类检查最近是否给出有效判定、实例冷热、已知的任务剩余时间和近期调用耗时。候选在列表中的位置不参与学习。文本长度和时间使用对数尺度，避免长文本和长时限压过其他信号。RAM 与 VRAM 使用当前实例可归属的新鲜计量，缺测分别标为未知。每个能力组新增真实入队速度、队列等待、worker 执行时间和副本启动至首次 READY 的时间，并提供样本数量及缺测位。特征版本 `capability-event-features/7` 参与检查点身份。

连续训练将更新批次与实例生命周期分开：积累已完成且已取得真实评分的任务后，在下一次真实多候选决策前更新，使用该决策状态续接价值估计；中途不强制排空或重建实例。跨更新的资源成本仅结算已有真实采样端点覆盖的区间，活动尾段后续补计，最终结算与完整任务流目标核对。旧有限工作负载记录保留原语义，不自动改写。

表格独立评分回传绑定任务、输入清单、评分清单及实际交付文件摘要，补充原生hard质量与soft分数，不改写业务终态、时延、API用量或分母。评分只进入实验账本与训练奖励，不进入业务上下文或策略观测。连续训练后台评分，冻结评价在整条流释放后评分；未知评分保持未知。

统一目标分别配置质量、交付、时延、RAM、VRAM 和 API token 的系数。首轮小规模协议采用质量与未按时交付系数各 1，四项成本系数分别为 0.1；成本尺度由独立开发子集实测均值冻结。API 用量汇总业务模型、上下文压缩及能力内上报的真实请求，缺少用量回执保持未知。质量未评分或所选成本口径缺失时，效用保持未知，不填零训练。失败和未交付保留在全部到达分母中。

实测与预留分开。实测只使用可核对实例归属的容器内存与 GPU 进程数据，不把整机 RAM、整卡显存或其他程序直接计入能力成本。共享实例计一次，启动、空闲及释放尾段均在成本范围内。采样缺口保留覆盖率，不能当作完整积分。外部模型费用不由本机内存推算。

新资源账本在线累计活动实例，确认释放后冻结汇总并退出活动索引；历史按需读取。Docker worker 的 RAM 端点使用创建后未启动的真实状态和删除后的实例身份确认，完整生命周期积分已通过真实隔离进程核对。Linux 完整显存按同内核进程与容器归属核对后统计；Windows 无法归属或显存返回 N/A 时保持未知。创建、启动和释放由生命周期端点计量，周期采样在启动端点完成后参与，并通过已有停止标记避开物理释放，避免进程切换中的并发探针截断记录。端点间按实际时间做梯形积分，属于采样估计；生命周期测量真正失败时仍保留未知。旧部署控制器仍有历史对象整理工作，不能据此宣称全仓所有路径已经有界。

## 已验证与后续范围

契约、HTTP worker、流式工具循环、必需插件、取消、历史分页、实际队列和 PPO 检查点已有针对性检查。完整 Mistune 仓库已由真实模型生成能力包，通过 Docker 首调和释放；普通聊天也已真实调用该能力、返回正确 HTML，并由空闲规则确认容器释放。本轮同一 Agent 办公任务中，业务模型调用 `search_documents` 三次，执行了三次隔离 Python 操作，均正常完成并交付 XLSX 与 Markdown。表格结果与授权资料中的政策引用已核对。该合成任务证明检索、代码执行和文件交付在同一业务链路中的连通性，不是正式基准。任务结束后原实例已释放；同项目新会话在冷启动的新实例上复用同一持久索引，跨实例索引读取已确认。细节和首轮失败见[运行记录](../history/实现与运行记录.md)。

Pytector、detect-secrets、Bandit、Presidio、LLM Guard 和 Haystack 参与了此前的六库小实验。Linux 上已完成 4 次开发、8 次训练以及三种策略各 8 次冻结评价。随后 NeMo Guardrails 完成原库输入／输出自检，RefChecker 完成原始样例的4条非空主张抽取、逐引用 NLI 和真实模型用量记录。上述结果和检查点属于当时的版本。本地办公八库已走新版分析器并完成此前的首调与校准；新特征尚待重训。部署时须对齐目标主机上的能力包和项目配置。AgentDojo Workspace／Slack 使用原工具、状态及原生 utility／ASR，普通聊天没有任务评价器时质量保持未知。

RefChecker 沿用原提示、主张解析和 NLI，模型调用采用原生 `custom_llm_api_func` 扩展点并配置零重试，替代源工具函数的限流重试。特殊错误下 SDK 的格式纠正请求仍可能不可单独观察。NLI 保留原有512-token截断限制，适用输入范围须随实验记录。主机与隔离 Python 容器的 RAM 当前未计入受管 harness 资源账本。

聊天可为本轮选择只读。只读模式只开放读取、检索与元数据工具。使用项目权限时，输入检查评估用户目的，具体操作的可选检查接收原始用户要求、工具、效果与参数。

办公项目以模型实际可见的工具结果维护证据。结构化读取保留字段关系与来源，日期等元数据也可参与核验。整条 JSON 答复与唯一完整的可见读取结果严格同值时可直接核对结果忠实性。自由文本仍经过事实核验，任务完成与否由原生评分给出。读取或检索得到的资料和操作回执分别计数。回执仅保留操作、调用身份及可确认的目标或返回标识，发送或写入的正文不会随回执成为事实依据。来源按各次读取排名轮流选段，总计最多六条、12000 字符。副本截取、预算裁剪和只有预览时记录覆盖受限。事实核验需要可见引用、问题和待核验的正文，超出文本长度等适用条件时记下缺口。首次可选事实核验未取得判词时记录未知，已经拒绝的操作或答复须获得有效复核。判词、实际工具效果和最终交付分别记录。

连续训练每次真实 PPO 更新后会原子保存检查点及内容摘要，不再只在整组结束时导出。表格原生评分前仅去掉逗号分隔范围两侧的空白，保留原范围与传入范围；答案和比较函数不变。评分仍未知时保留记录并停止后续派发。实验驱动支持仅运行开发校准，确认问题解决后再复用同一次校准尺度启动七组开发比较。

### 项目演示与运行观察

项目页选择参与后续任务的库。带自有工具的场景和普通对话都在任务登记时取得项目候选。调度器可以直接继续，也可以运行一个检查，看到结果后再选同类或其他检查。业务模型按需请求检索等工具。绑定项目资料的检索实例仅服务该项目。办公比较默认从项目取得候选，开发校准记录实际检查能力和检索声明，各权重及评价臂沿用同一组。协议也可显式限定参评能力。

普通对话和手动发起的合成办公任务共用 Pi。合成任务读取虚构项目资料，向模拟收件人交付，研究端分别判断合法任务是否完成、受保护字段是否泄露。任务观察面板展示实际调用、冷启动等待、检查决定及阻断原因。关联实例释放后可查整个实例的驻留时间和 RAM／VRAM 积分。多次任务共享实例时，在实例粒度统计这笔资源。

结束演示时可关闭该项目的候选库，按需清理已结束会话的工作区。能力镜像和其他项目可复用，共享实例由调度器排空回收。已交付数据、索引及共享镜像的删除分别按各自生命周期管理。

Pi宿主、项目与工作区已经更新到服务。本地进一步准备了256次训练、32次开发、三种策略各72次评价及连续训练结算；这批新代码尚待用户提交推送后通过Git部署，不能视为服务器已更新或新实验已完成。来源原题、变体和重复执行分别计数，见[办公协作场景方案](../研究实验/办公协作场景方案.md)。11月10日五来源数据仍按原版本解释：12个训练窗与两种资源偏好等原始记录保留。旧图的RL汇总来自两次评估的各项较优值，不是一套配置同时得到的联合结果。
