# 实现与落地计划

更新：2026-11-11。本轮先落实设计与实验文档，用户手动提交后再改实现、部署和运行实验。沿用当前工作区，不代用户暂存或提交，不启动旧训练器。目标见[平台设计](Harness接入与调度重设计讨论.md)，事实见[当前实现](当前实现.md)。

## 当前起点

0.16.0 已接通整仓读取、标准适配、worker、模型与工具循环、容器启停、部分测量与 PPO 主体接口。新平台实证能力只有 Mistune Markdown 渲染；它不是安全防护库。尚无新场景的完整评分、应用防护绑定与实际训练驱动。

生成器仍偏向首个完整用途，限制生成适配且复制冻结文本；操作与部署单元尚未充分分离。当前实际策略动作主要是就绪派发和空闲超时释放。不能把上述连通性写成多防护联合调度实验已具备。

## 同一条实施链

| 顺序 | 实际改动 | 交付 |
|---|---|---|
| 1. 宿主和应用接口 | 固定一个精简开源宿主版本与接法；将模型／工具循环、会话所有权、执行前和交付前控制接到平台 | 正常使用和实验使用同一入口，只有一套循环 |
| 2. 能力包和生成 | 分开操作、Unit、实例、调用；支持所选生产文件及资产、必要重构、资源自动绑定 | 完整库自动产出可运行子集，排除无关前端和测试替身 |
| 3. 防护与数据 | 接入真实防护方法；实现适用事件、受限干预、调用隔离、输入文件、制品交付和清理 | 防护参与实际业务，重复调用和提前结束语义明确 |
| 4. 实验环境与评分 | 先桥接一个 AgentDojo 任务套件的工具／状态／评分，再增加表格、资料和软件任务适配 | 完整任务经同一 Agent 运行，由原评分器判断任务及攻击结果 |
| 5. 调度与训练 | 可选防护和真正可控的实例动作进入候选；内容和资源特征、奖励结算、训练驱动与冻结评价接通 | 同一能力池与信息下比较常规配置、调优规则、PPO |
| 6. 多场景与展示 | 扩到两至三个混合场景、每场七至十个有用来源库；输出同配置整组原指标与成本 | 有任务、能力和资源变化的比较，保留失败与实际分母 |

这是一条工程依赖链，不增加逐步审批或独立验证平台。环境准备、来源分析和评分器适配可以并行。每个正式比较须运行该比较声明的完整方法；减少预算优先减少冻结任务数和重复数，不将删掉方法组件的版本冒称完整方法。

## 宿主选择与可复用实现

优先选择 Pi 最小宿主组合，需确定其同步执行控制、待交付流和取消接口如何连接 Python 平台；DeepSeek Harness 与 oh-my-pi 只作同一选型的备选。最终只留一个宿主。当前自有 AgentRuntime 是迁移起点，可用于诊断，不能与开源宿主并行维护两套正式业务循环。

直接复用源码身份和读取、资源登记、Docker 后端、实例身份、在途排空、存储、模型传输与 PPO 优化主体。移除其对旧候选、预算轮换和固定生成核验流程的依赖。旧 joint/training 的场景路径不作新训练驱动。

## 实现时需一并修正

- 状态不再只用 call/instance 模糊表达；会话状态与可回收缓存分开，回收依据真实所有权和占用。
- 容量按实例计算，再叠加全局限制；调度观察显式带请求身份，和真正选用的实例一致。
- 输入、工具结果和输出的替换／阻断落到实际执行位置；取消在调用登记前后均不能丢失。
- 应用、诊断和实验调用有独立计量范围；诊断消耗不能混入实验分子而不计任务分母。
- 采样边界和覆盖率采用可兑现的规则，解决启动／释放间隙导致完整资源回报始终未知的问题；缺失不填零。
- 实验原评分进入训练映射；接上实际 PPO 更新调用。单一合法动作不伪造学习样本。
- 文件和资源缺口用可操作语言呈现，研究细节收进研究视图；修正资源入口跳转和原始 JSON 默认展示。

## 今晚取得数据的安排

首先取得同一宿主上的真实完整任务、真实防护调用、原生判分与归属成本，形成可追溯的开发批次。若训练和能力池也完成，再跑冻结对照；若未完成，如实交付任务／防护数据和剩余工作，不将首调或模拟任务当作完整比较。

第一候选是无需浏览器整站部署的 AgentDojo 工具环境；先取一个有多种任务和原生判分的套件，再组合来源。今晚不新建多客户服务实验、桌面虚拟机集群或等待受门控环境审批。其他数据集的优先级见[数据源选型](../研究实验/Agent任务与攻击数据源选型.md)。时间取决于来源、权重、宿主桥接和实际任务耗时，尚无实测工时可保证整套多场景 PPO 今晚完成。

## 研究参数与运行记录

能力库、任务版本、业务模型、政策、动作、评分器、数据划分、目标系数及成本口径随同运行配置冻结。奖励总分仅用于训练；论文报告数据集原指标及成本。原始实验、来源快照、权重和检查点保留；新目标不加载旧轮换偏好检查点。

检查只围绕被修改的真实路径：完整任务执行与原判分、防护实际阻断／替换、文件交付、取消／释放、成本结算与 PPO 更新。复用来源例子和原评分器，不另造测试平台；取得运行事实后不重复无关检查。
