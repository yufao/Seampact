| 3. 检索、防护与数据 | 八个来源已真实接入，正式配置记录版本、资源、适用事件和干预行为 | 逐项保留原实现调用与用量，完整比较采用同一能力池 |
| 4. 实验环境与评分 | AgentDojo 两个办公套件已接通；继续完成 RAG 映射、表格三用例与 AgentHarm 原生工具／评分 | 完整任务经同一 Pi Agent 运行，由原评分器判断任务及攻击结果 |
| 5. 调度与训练 | 训练更新与实例生命周期分离，连续流中按真实评分和资源区间更新，整流末尾统一收尾；扩充多源题池并保留原生评分 | 同一候选接口下的常规应用配置、确定性资源规则与PPO，更新不强制释放实例 |
| 6. 多场景与展示 | 扩到两至三个混合场景、每场七至十个有用来源库；输出同配置整组原指标与成本 | 有任务、能力和资源变化的比较，保留失败与实际分母 |

这是一条工程依赖链，不增加逐步审批或独立验证平台。环境准备、来源分析和评分器适配可以并行。每个正式比较须运行该比较声明的完整方法；减少预算优先减少冻结任务数和重复数，不将删掉方法组件的版本冒称完整方法。

## 宿主选择与可复用实现

宿主固定为 Pi Agent core 1.5.2，已更新在线服务。Pi 负责实际模型／工具循环，Python 通过本地协议提供流式模型响应、上下文、工具效果和取消；密钥留在 Python 连接层。平台的原始记录和归属机制复用，Pi 事件只保存必要执行事实，不重复存整段历史。

直接复用源码身份和读取、资源登记、Docker 后端、实例身份、在途排空、存储、模型传输与 PPO 优化主体。移除其对旧候选、预算轮换和固定生成核验流程的依赖。旧 joint/training 的场景路径不作新训练驱动。

## 实现时需一并修正

- 状态不再只用 call/instance 模糊表达；会话状态与可回收缓存分开，回收依据真实所有权和占用。
- 容量按实例计算，再叠加全局限制；调度观察显式带请求身份，和真正选用的实例一致。
- 输入、工具结果和输出的替换／阻断落到实际执行位置；取消在调用登记前后均不能丢失。
- 应用、诊断和实验调用有独立计量范围；诊断消耗不能混入实验分子而不计任务分母。
- 采样边界和覆盖率采用可兑现的规则，解决启动／释放间隙导致完整资源回报始终未知的问题；缺失不填零。
- 实验原评分进入训练映射；接上实际 PPO 更新调用。单一合法动作不伪造学习样本。
- 文件和资源缺口用可操作语言呈现，研究细节收进研究视图；修正资源入口跳转和原始 JSON 默认展示。
