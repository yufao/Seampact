# 平台分层、能力接入与 Agent 调度设计

更新：2026-11-11。本文规定目标；已经实现和运行的范围见[当前实现](当前实现.md)。字段与执行语义见[能力契约](Harness分类与调度契约.md)，实验选型见[研究实验方案](../研究实验/研究实验方案.md)。

## 系统关系

业务大模型与系统平台共同构成一个 Agent。平台内部包括一个精简基础宿主，以及接入能力的调用和资源管理。基础宿主负责上下文、会话、基本读写工具、模型与工具循环、取消和交付。外接 harness 在适用位置参与这一个循环；平台不再另造规划或生成循环。

仓库接入发生在能力准备阶段：分析模型读取完整库，生成可运行能力。业务模型负责实际用户任务。两者角色、成本和记录分开。

实验使用同一业务运行链路：实验驱动提供任务、初始环境和冻结配置，任务进入同一个 Agent，运行轨迹、交付件和环境变化交给数据集原评分器。实验记录和观察属于平台用途，不形成另一套业务引擎。训练奖励由评分与成本转换而来；论文直接报告任务成功、攻击成功、误拒和资源等分项指标。

普通用户只需输入、文件、进度、结果和真实缺口；开发者查看接入与故障；研究者查看策略、轨迹、评分和实例成本。这是同一系统的信息展示范围，不增加三套平台。

## 精简宿主

只复用一个项目的最小运行路径。优先考察 Pi 的 Agent 核心及所需会话、工具组件；DeepSeek Harness、oh-my-pi 是选型备选，不能同时拼成多套会话或工具注册系统。当前仍为自有 AgentRuntime，开源宿主的固定版本和最终接法尚未冻结。

选择条件是上下文与工具循环可复用，工具执行前可以等待平台决定，待交付流可以由平台控制，取消能传播，工具结果能回到原循环。仅能事后通知事件的接口不足以承担执行前防护。借鉴所需接口，不引入完整应用前端、微服务网格或通用工作流语言。

依据：[Pi Agent 核心](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md)、[DeepSeek Harness 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)、[oh-my-pi Python 接口](https://github.com/can1357/oh-my-pi/blob/main/sdk/python/omp-rpc/README.md)。

## 挂载位置与实际运行

挂载位置表示宿主此时允许能力参与的操作，不是每个请求必须走完的防护流水线。最少覆盖任务开始／结束、模型调用前后、工具执行前后，以及内容实际交付前。上下文中的外部材料无论来自工具、附件还是检索，都应有对应的接入位置。可参考 [HarnessX 的生命周期设计](https://arxiv.org/html/2606.14249v3)，无需引入其自进化系统。

直接回答、文件修改、多轮检索和提前拒绝都是正常流程。平台不定义统一“草稿”，不要求问答附带图片或生成后固定核验。同一能力可以多次触发：算法内部的检索／分析循环由能力完成，业务模型根据工具结果继续工作则由基础宿主完成。

观察事件可以异步记录；保护工具效果的检查先于执行；保护用户可见内容的检查先于交付。流式防护按所需片段或上下文缓冲，通过后发布；必须看全文的方法等待全文。已发布内容无法收回。请求取消、停止交付、上游确认停算分别记录。

## 平台、业务模型与策略

业务模型提出业务工具需求。平台根据事件、输入类型、能力契约和应用要求形成合法候选，并执行必需工作；策略在可选防护、可执行调用和实例操作间选择。数据集金标、攻击标签、未来任务和事后评分不进入在线观测。

触发者、模型可见性、是否必需和干预权限分别记录。“透明”仅作业务模型无需主动申请该防护的简称，不表示必做，也不表示结果绝不能反馈给模型。同一能力可以作为业务工具和平台触发的防护，共用实现及实例。模型申请不等于获得执行批准；任务明确要求的工作不能为省成本而省略。

必需检查的错误处理由应用政策确定；无法完成时返回明确未完成或阻止被保护操作，不把运行错误当作安全通过。检查输出映射到继续、替换、阻止某次操作或结束任务，权限由宿主约束。多个检查是否顺序依赖以及替换后谁消费结果须明确，防止重复处理和循环触发。

## 能力操作、部署单元与实例

能力操作表示“做什么”；Unit 是共同拥有资源和状态、一起启停的部署边界；实例是 Unit 的一个实际进程或容器；调用是某次输入对应的执行。包是版本化发布产物，不自动等于一个操作或一个容器。

一个库可以提供多个操作或多个 Unit，多个操作也可以共享同一 Unit。轻量内部步骤保持普通函数。独立部署须有明确输入、独立资源与状态归属，以及具体可用的决定：差异化加载、独立排队／复用、独立释放或合法复制。仅增加中间入口、日志和传递不构成拆分收益。

例如完整主张核验可以包含抽取、NLI 和聚合；共享活对象且没有独立资源收益时一起执行。只有 NLI 可接收明确主张／证据、独立拥有模型且存在复用或独立释放机会时才形成单独 Unit。合并实现也允许正常惰性加载和释放，比较计入冷启动与传输。

多请求先预留隔离、实例匹配、每实例容量、调用取消与会话占用接口；本轮不运行多客户服务器实验。可重建缓存允许回收；业务状态由明确的会话或持久存储所有者管理。有活状态的会话保留实例占用，结束后才释放；共享实例不能因一个调用取消而整体退出。

## 完整来源与运行子集

主线是能力抽取与标准重构，尽量复用原算法。平台读取代码、配置、依赖、README 和相关例子，选出与用途有关的生产代码、资产和依赖，生成能力描述、适配或必要改写、部署安排。源码原件按版本保存；运行产物可以重构，保留来源对应关系。

前端、演示、测试替身和无关训练代码默认不进入运行包；按真实依赖判断，不能仅按目录名删除。文本外的模型、模板、词典和数据资产同样需要声明。已有资源唯一匹配时自动绑定，确实缺失或冲突时再问人。用户不逐个填写接线、分组和启动规则。

IR 是上述结构化描述，不另造一门语言。接口、资源所有权与可执行条件可机械检查；源码引用和首调不构成任意语义等价证明。只有对特定转换需要更强保证时才进行限定验证，见[Translation Validation](https://cs.nyu.edu/home/people/in_memoriam/pnueli/transval-icalp98.html)。

## 数据与历史

来源和构建物按版本去重，权重与大资产独立登记。调用临时文件归调用所有，确认无引用后清理；用户交付件、会话记忆独立于可回收实例。调试记录限量保留，冻结实验保存必要原始结果、配置和引用身份。调度热路径只持有活动状态和有限摘要，历史落盘分页读取。

## 同一目标配置与独立评价

训练使用一套冻结系数同时考虑任务效果、交付、时延、RAM、VRAM及实际相关费用；不交替“省 RAM／省 VRAM”。奖励映射由各场景的原始评分与归一化成本构成，质量与风险可以是多个分项。系数和尺度在开发侧确定，正式评价冻结。

评价直接使用数据集规定的任务与安全判据，奖励总分不替代原指标。无评分、测量缺失和真实失败分别记录。共享实例成本只计一次，声明预留成本与归属实测分开。具体比较、划分和计量见[实验协议](../研究实验/多来源共享资源场景协议.md)。

两至三个混合场景共用这一结构，每场计划配置七至十个有实际作用的来源库。数据集数量、模态和库数量是实验安排，不成为平台接口条件。场景内正常使用占多数，正常任务也可多次用工具；风险类型和任务来源多样，实例冷热和任务组合可变化。
