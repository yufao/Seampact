# 共享服务器操作说明

更新：2026-10-14，0.7.1。用户通过 Terminus 执行远程命令，代码和文档走 Git；密钥、模型、数据和私有工件按需 SFTP。当前有限原生宿主以 Python 3.11 为范围。

## 已知环境

用户在 2026-10-12 提供的结果：Ubuntu 24.04.4，账号 `jym`，系统 Python 3.13.3，Docker／Compose 已安装；当时 Docker service 与 socket 为 inactive，containerd 正在运行。管理员已明确允许启动系统 Docker 服务。无需重复探测 GPU、系统内存或 CUDA，当前平台核心不需要 GPU。

旧上传包 `~/seampact-workspace/releases/seampact-core-0.4.0` 是历史版本。当前仓库为 `git@github.com:yufao/Seampact.git`；不要覆盖旧运行状态。

## 获取当前代码

首次拉取，在用户自己的目录执行：

```bash
mkdir -p "$HOME/seampact-workspace"
cd "$HOME/seampact-workspace"
git clone git@github.com:yufao/Seampact.git Seampact
cd Seampact
```

已经有这个 Git 克隆时，在该克隆目录更新：

```bash
git pull --ff-only
```

如服务器没有 GitHub SSH 凭据，也可使用 HTTPS 仓库地址；私有仓库需要账号已有的访问凭据。

## 选择启动方式

只先打开平台界面和配置云端模型，用[Docker 单服务部署](Docker部署.md)。系统 Docker 尚未启动时，使用此前已获管理员授权的操作：

```bash
sudo systemctl start docker
```

需要原生 Harness 的 Python 依赖时，使用专属 Python 3.11 环境。已知系统 Python 是 3.13.3，直接由它创建的 `.venv` 也会是 3.13，不能用于当前 B-CALL 规则。Docker 镜像已经使用 Python 3.11；服务器有独立 `python3.11` 时，可在仓库目录执行：

```bash
python3.11 -m venv .venv
. .venv/bin/activate
PYTHONPATH=src python -B -m seampact serve --home var/prototype --port 8880
```

没有 `python3.11` 或缺少 `venv` 组件时，使用当前 Docker 方式或返回实际报错讨论专属环境；不要修改共享的 `/usr/bin/python3`。随后只在这个专属环境中按 Harness 自身依赖文件安装运行库。

平台默认绑定 `127.0.0.1:8880`。Terminus 配置 SSH 本地转发：远端主机 `127.0.0.1`，远端端口 `8880`，本地端口 `8880`；浏览器打开 http://127.0.0.1:8880。

## 用户需要提供什么

页面中填写对话与分析 API 的实际地址、型号和密钥。无需把密钥发到聊天里。DeepSeek／GLM 都可按实际接口设置填写；本地对话模型使用实际部署提供的 OpenAI 兼容地址。

Harness 可直接用 Git URL，或通过 SFTP 放到 `~/seampact-workspace/harnesses/<name>`。原生运行填写真实服务器路径；Docker 运行按挂载填写 `/harnesses/<name>`。入口说明只定位完整 Harness，拆分候选由平台分析 API 产生。已有配置、数据和模型资源以真实路径提供。

本地四源已经完成真实 API 分析；MMCT 的 `mmct/image_pipeline/agents/yolov8s.pt` 和 NeMo 的 `examples/configs/rag/pinecone/kb/data-00000-of-00001.arrow` 没有准备，不能因上传源码就称物料齐全。额外接入的 MADL 权重也尚未准备。具体入口按实际依赖／资源显示 `READY` 或 `MISSING`，见[0.7 运行记录](0.7_规则兑现与实际运行.md)。这份本地记录不表示服务器已经更新或运行。

配置未完成时可以先打开页面；分析和对话只有用户实际发起后才调用对应模型。普通对话不要求先有可用 Harness。
