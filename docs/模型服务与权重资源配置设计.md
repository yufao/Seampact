## 设计起草记录与规格

更新：2026-10-20。状态：用户要求的实现设计，新增配置功能尚未实现。本文落实前端服务连接、Windows／Linux 凭据、本地权重和依赖绑定；不把设计写作已可运行功能。实现事实仍查[当前实现](当前实现.md)。

目标是让用户在前端配置原 Harness 实际需要的资源，并让平台分析器和原生绑定机制使用这些资源。继续使用现有四层、原构造／W／H／R 规则、三学习器与下层 FIFO。原库入口、构造与拆分仍由平台分析链提出，配置界面不承担人工包装或内部接线。

## 1. 范围与现有基础

首版包含两条路径：**API 依赖绑定到已启动的服务；本地加载依赖绑定到执行环境中的权重文件或目录。** 同机和跨机器的 HTTP／HTTPS 服务都支持登记，跨机器部分仅复用地址配置和原客户端，不增加机器调度、自动部署、文件同步或通用远程对象。

| 项目 | 当前代码事实 | 本次设计 |
|---|---|---|
| 对话／分析／教师 | `providers.py` 中三个独立角色，前端已有表单；教师可明确复用分析角色 | 保留三个操作入口，底层引用命名连接；默认独立，复用由用户明确选择 |
| 密钥 | Windows DPAPI；非 Windows 私有凭据文件／环境变量；公开状态排除密钥 | 复用并补齐凭据引用、Linux 权限检查、显式保存／保留／清除与跨平台迁移说明 |
| Harness 资源 | `intake.py` 接受路径元数据，初始化配置保存在来源记录；`service.py` 拒绝其中的 API Key | 增加前端命名服务／权重记录和基于分析结果的依赖选择 |
| 原生绑定 | `units.py` 核对固定实参来源、构造与原对象；尚无统一服务／凭据引用解析 | 在已有“配置值／资源引用”范围补通用解析、检查和运行时注入 |
| 训练快照 | `training.py::BoundProfiles` 冻结三个平台角色 | 同时冻结被使用的 Harness 依赖配置与资源身份，秘密只留运行所需内存 |
| 远程执行 | `deployment.py` 仅支持有限同步标量运行组 | 原范围不变；远端服务地址不授予 Unit 迁移、对象跨组或模型驻留许可 |

分析角色支持本地或远程 HTTP／HTTPS 兼容连接，并依据明确选择的鉴权模式检查凭据；Chat Completions 与工具调用能力仍为必要条件。对话、教师及 Harness 服务按各自契约支持本地或远程连接。注册一个可访问地址，不自动证明它适合全部角色。

## 2. 最小配置记录与身份

使用现有 Store／配置存储，不增设平台层。以下是配置记录，不新增理论核心对象：

| 记录 | 最小内容 | 身份与用途 |
|---|---|---|
| 服务连接 | 名称、协议、地址、服务能力、可选模型 ID、必要非敏感参数、可核对版本、认证方式／凭据引用 | 随机稳定 `connection_id`；名称可改，执行配置另有 revision／摘要 |
| 权重资源 | 名称、执行环境、文件或目录路径、资源角色、已知模型 revision、必要文件清单及校验结果 | 随机稳定 `resource_id`；实际资源内容身份与路径分别记录 |
| 私有凭据 | 随机 `credential_ref`、存储方式、可用状态、版本；秘密值仅在私有存储 | 不以 API Key 或其直接哈希作主键，不自动按 Key 去重 |
| 依赖需求 | 来源修订、源码锚点、能力／资源类型、原配置入口、读取时点、owner 作用域、是否为原运行必需 | 由平台分析器发现，引擎核对；需求 ID 不使用显示名称 |
| 绑定 | 需求 ID → 连接或资源 ID＋版本，以及获准的原配置字段映射 | 多个 Unit 可引用所属原 owner 的绑定；同值不推出对象共享 |
| 角色选择 | chat／analysis／teacher → 连接 ID | 保留现有角色 API 的兼容视图，不改变教师明确复用的含义 |

连接能力可标记文本生成、视觉生成、embedding、检索及原专用服务；能力声明和实际核对结果分开。首版只接现有适配器或原客户端已经支持的协议，不建设任意 HTTP 请求编排器。OpenAI 兼容接口也需分别核对 chat、图像、工具、embedding 等具体操作。

同一把 Key 可经用户明确选择用于不同连接；同一地址也可保存不同模型配置。改名不产生执行版本，改变地址、协议、模型或生成参数产生新版本。凭据轮换使用独立凭据版本，不把 Key 变化自动视为模型能力变化。

非敏感配置摘要采用规范化字段计算，排除显示名称、秘密值及秘密值的直接哈希。保存凭据引用／版本用于说明运行采用哪项认证材料，不用它冒充服务或模型身份。运行记录另存实际可得的模型、权重及服务版本；无法核对则 UNKNOWN。

## 3. 前端操作

在现有配置窗口内增加“服务连接”“权重资源”，在 Harness 详情中增加“依赖配置”。不新建管理后台。

### 3.1 服务连接与平台角色

用户填写连接名称，选择协议／用途，填写 URL、模型 ID（如需要）和必要参数；认证选择“无需认证”“保存凭据”或“引用环境变量”。对话、分析和教师仍各有清楚的配置入口，可选择已有连接或就地新建。

凭据输入为空表示保留已有值；另设明确的“清除凭据／改为无需认证”操作，不能用空白同时表达两种意思。界面只显示“已配置、未配置、无法读取”等状态，不回填秘密值。更换目标地址时解除原凭据默认绑定，用户需明确为新目标选择认证，避免随地址变更自动转发旧 Key。

保存只保存配置，不启动模型、不触发收费推理。另有“检查连接”及用户主动触发的最小能力调用：前者核对可用协议入口和认证，后者使用明确输入核对实际操作。原服务无探测接口时显示“尚未验证”，不能用根路径返回 200 或模型列表代替目标功能成功。

### 3.2 权重资源

用户输入执行环境内的文件／目录路径并点击“检查资源”。首版使用路径输入及检查，不做浏览器上传大权重或通用服务器文件管理器。

界面始终显示“此路径属于平台实际执行环境”。Windows 平台填写 Windows 路径，Linux 平台填写 Linux 路径，Docker 平台填写容器内路径。浏览器所在电脑的文件选择结果不能自动变成服务器文件。

资源可以是完整模型目录、单个 checkpoint、adapter、tokenizer／processor 或模型配套文件；可以按原资源清单组成一组。单个 LoRA 文件不等于完整基座，目录存在不等于所有分片齐全。路径可登记为尚不存在，便于接入准备；此时明确显示缺失。

### 3.3 Harness 依赖配置

平台完成源码分析或形成部分需求后，显示每项依赖的作用、资源类型、配置方式、原文件／位置、当前绑定和缺失原因。用户为服务需求选择命名连接，为权重需求选择已登记路径。

原路径不可配置时，改为显示“源库要求的位置”：执行环境、原相对路径及其基准、解析后的绝对路径、所需文件和缺失项。用户自行把权重放到该位置后重新检查。界面不提供实际上无效的路径覆盖选项。

未绑定资源时仍可分析能静态确定的源码事实，保留需求和 MISSING；不能为生成表单先伪造构造参数、把缺 Key 解释为无认证或使用假权重。

## 4. 两条运行路径

### 4.1 原库通过 API 调用

分析器识别原 SDK／HTTP 客户端、配置读取入口和调用操作，绑定器核对将连接中的哪些字段供给原参数或配置。优先使用原本存在的 `base_url`、模型名、认证及其他真实配置入口；保留原请求格式、图像处理、生成参数、响应解析和错误行为。

不能把所有客户端替换成平台统一的聊天调用。连接层统一描述资源，真正调用仍按原客户端或已有获准适配器执行。embedding 维度、视觉输入方式、输出字段和必要参数均属于匹配条件；接口形式相同不意味着模型可互换。

只注入原接口允许且已经核对的字段，不把连接里的全局默认参数无条件合并到每次原请求。原方法固定的生成参数、提示词和模型要求继续保留；用户在原可配置范围内改变它们时，显式形成新的方法配置并记录，不能隐式覆盖。

凭据由后台在需要的执行边界解析，按获准绑定交给原客户端。分析器只见非敏感元数据及凭据需求，不见实际值。依赖关系和参数映射由分析器提出、规则检查；用户提供资源值不构成手工预写入口。

### 4.2 原库加载权重并操作模型对象

保留原模型类、工厂、加载参数、设备选择和生命周期。前端只提供原加载路径可接受的资源值，不因为登记了权重就将模型改为 API 调用。

| 原读取方式 | 前端及绑定行为 |
|---|---|
| 原参数／配置允许指定路径 | 选择文件或目录，绑定到经过核对的原参数／配置字段；原配置类仍调用原实现 |
| 原代码读取固定环境变量 | 显示变量名和实际读取时点，按第 5 节的环境作用域绑定 |
| 原代码固定相对路径 | 核对相对于 cwd、`__file__`、配置目录或其他原基准；显示运行时实际目标位置和放置说明 |
| 原代码固定绝对路径 | 显示目标路径及缺口；用户在目标环境准备，不能自动改源码或假装输入另一路径已经生效 |
| 动态计算且尚不能确定 | 显示“位置未确定”及源码依据，继续由分析器处理；不猜位置、不扫描整台机器找近似权重 |

原路径基准必须对应真实运行宿主，而非浏览器目录或随手选取的仓库副本。源码快照与原工作目录不同的，显示绑定实际采用的位置。所需运行目录尚未形成时，先显示已知相对约束，绝对位置保持未确定。

不自动复制、移动、建软链接、改写源码路径或更换 cwd 来掩盖不匹配。既有宿主若已经提供明确的资源映射，可按原规则使用；未覆盖的装配方式留为具体缺口。模型资源与冻结源码分别记录，不能把 GB 级权重、凭据文件当文本发送给分析 API。

资源检查只做路径存在、类型、可读性、原清单必要项和可取得的身份核对，不导入源库、反序列化 checkpoint 或加载模型。已知 manifest／分片索引时核对所列文件；不在每次页面刷新重新哈希全部大文件。正式研究运行保存可得摘要及验证时间；只有路径／大小／mtime 时明确不能证明内容相同。

真正加载及推理另行记录结果、耗时和资源消耗；如原加载器会联网补文件，记录实际获取版本及费用，不把静态资源检查写成加载成功。用户提供同名权重也不能证明与原方法版本相同。

## 5. Windows／Linux 凭据与运行作用域

### 5.1 凭据保存

| 环境／模式 | 首版决定 | 前端说明 |
|---|---|---|
| Windows 保存凭据 | 沿用当前用户 DPAPI 保护，秘密通过私有凭据引用访问 | 当前 Windows 用户可读取；不能直接复制到 Linux 使用 |
| Linux 保存凭据 | 后端以运行账号创建私有凭据目录 0700、文件及临时文件 0600；使用同目录原子替换，校验实际权限与属主 | “保存到服务器私有文件，依靠账号／文件权限保护，非磁盘加密” |
| 环境变量引用 | 只保存变量名，运行进程解析；不把值转存到公开配置或 JSON 导出 | 显示可取得状态，不显示值；外部终端修改不会自动更新已启动服务 |
| 无需认证 | 显式选择，不因 Key 缺失而自动推定 | 按原服务／SDK 的无认证约定处理 |

Linux 选用无需桌面 Keyring 的方案，适合 SSH、容器和无桌面服务器。私有文件不是加密保险库，不宣称能隔离 root 或同账号进程；不在本轮新增 Vault、主密码服务或用户权限体系。权限位的实现依据为 [Python 3.11 文件权限接口](https://docs.python.org/3.11/library/os.html#os.chmod)。

Linux 创建时即限制权限，不能先以可读权限写出密钥再收紧；已有不合适的权限、属主或文件系统不支持限制时，明确报错，不自动放宽其他目录。仅管理平台自己的凭据文件；不对共享工作目录递归 chmod。Docker 按实际映射 UID／GID 检查可读写性，私有数据卷持久化，凭据不进入镜像层。

Windows DPAPI 通常与原用户及机器关联，跨系统迁移重新填写或重新配置环境变量。迁移只导出非敏感连接、资源元数据和待重绑定提示，不导出秘密或把 DPAPI 密文当 Linux 可用凭据。[Microsoft DPAPI 说明](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

保存／更新凭据使用专门写入通道；普通配置、`/api/state`、分析工具、错误信息、运行清单和配置导出不包含秘密。URL 中不夹带认证值；旧配置中的敏感字段也不能随迁移进入分析上下文。认证复用必须在已选连接范围内明确配置，用户未提供时不得自动借用平台对话／分析密钥。

服务器配置界面沿用现有本机访问或 SSH 转发／受保护的 HTTPS 部署方式，不为这次功能增加公网管理服务。

### 5.2 原库的环境变量与配置文件

后台保存凭据和原库读取凭据是两件事，必须将下面的读取路径落实：

- 原构造器或方法有参数：在原构造／调用位置解析引用，保留原创建次数，不经普通任务输入暴露秘密。
- 原 CLI／既有进程宿主读环境：在启动该原进程时通过明确的环境映射注入，不把 Key 拼进命令行；保留原 cwd 和生命周期。[Python 3.11 子进程环境接口](https://docs.python.org/3.11/library/subprocess.html#subprocess.Popen)
- 原代码在导入或初始化时读进程环境：绑定到该宿主启动时固定的环境；已初始化的对象不能靠前端改值宣称更新成功。
- 同一进程内两个来源要求同名变量但不同值：不得逐调用临时改全局 `os.environ`。可用原显式参数或既有支持的隔离宿主时按规则处理，否则保留不支持的绑定原因，不擅自增加通用进程迁移。
- 原库只读含秘密的配置文件：保持该文件在分析范围之外，仅使用原库支持的路径入口和独立私有文件。首版不自动生成任意来源格式的秘密文件；无合法入口时提示用户按原格式准备并核对路径。

原源码本身包含硬编码密钥时，不作为可重用配置提取给模型；报告该位置需要处理，不能复制到新资源记录或工件。这里的字段过滤和引用解析不代表平台可证明任意源码不会泄露秘密。

## 6. 跨机器的最小支持

首版支持用户手动启动机器 A 上的模型／检索服务，在前端登记其可访问 URL，再绑定到本机原 Harness 的兼容 API 依赖。使用已有 HTTP／HTTPS 客户端，连接记录中的机器名称仅作说明，不是 RL 部署动作。

```mermaid
flowchart LR
    F["前端：服务与权重配置"] --> B["后台：需求核对与绑定"]
    A["分析器：从原库识别依赖"] --> B
    B --> U["原宿主中的 Harness Unit"]
    U -->|"原 API"| S["本机／其他机器／云端已启动服务"]
    U -->|"原加载器"| W["执行环境可读的权重文件"]
```

例如已有兼容服务可通过 URL、模型 ID 和认证调用；vLLM 提供这类 HTTP 接口，但支持操作与模型能力仍须分别核对。[vLLM 服务文档](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/)

连接检查从实际调用方执行。`localhost` 指该进程／容器自身，不能解释成浏览器机器或另一台服务器。跨机器图像、文件使用原协议支持的实际内容或服务可访问地址；平台本地路径不是远端可读文件。

Linux／Docker 权重首版必须在实际执行环境可见。用户可在外部用既有 SFTP 或容器挂载准备文件，前端仅登记和核对容器／进程内路径；不能把 `机器A:/models/...` 当本机路径验证。自动 SSH 登录、远程挂载、权重同步和 GPU 模型部署均不属于本次实现。

若来源只有本地模型对象接口，将其放到另一机器执行属于原生宿主／运行组问题，沿用既有远程许可。此次配置不扩展 `python311-scalar-worker/1`，不为 MADL 等来源临时编写 HTTP 包装。当前机器条件不足时记录资源／宿主缺口。

## 7. 分析、绑定、状态与版本

需求信息进入现有分析产物的版本化扩展；连接／资源记录由用户配置提供。分析器能读必要的非敏感元数据，不能访问凭据文件。需求包括源锚点、原配置字段、类型、读取时点和 owner；“需要 API”这一描述不足以自动执行注入。

绑定 IR 中新增受限的配置／资源／凭据引用形式时，应明确对应已有构造语义中的值来源，逐字段检查，不接受自由生成 Python。秘密引用只能进入已核对的原认证位置；资源标记必须在运行边界解析为原接口所需的实际值，不能将引用字典直接作为原函数实参。

多个拆分 Unit 继承所属 owner 的依赖，不按“同一路径／同一个连接”合并原对象，也不把一次加载复制为每个 Unit 单独加载。必需依赖未满足时排除对应可执行候选；任务必需工作缺资源则任务未满足，不能让 RL 以“跳过”获得成功。

依赖按入口、原初始化和控制条件确定，不把某个入口缺资源扩散成整个来源均不可用。反过来，原 owner 初始化确实无条件加载多项模型时，不能因某个 Unit 的函数体只使用其中一项就省去其他加载；降低初始化范围也须有合法导出和生命周期依据。

前端分别展示以下结果，不能汇成一个含义不明的“已就绪”：

| 维度 | 至少区分 |
|---|---|
| 依赖绑定 | 未选择／已保存选择／已核对映射／绑定缺口 |
| 凭据 | 不需要／未配置／可解析／读取失败 |
| 权重文件 | 未检查／缺失／不可读／必要文件存在／已核对摘要 |
| 服务连接 | 未检查／可访问／认证或连接失败 |
| 操作与能力 | 未验证／匹配／不匹配／无法确定 |
| 原目标执行 | NOT_RUN／实际成功／实际失败，附时间和配置身份 |

原 Unit 的静态 READY／MISSING 按原语义保留；探测结果另存检查时间与配置版本。服务列表可访问或文件存在都不代表 Unit 已完成实际目标；加载／推理也不能在定时刷新中自动触发。

每次运行冻结连接、资源、绑定及配置版本；后台运行所需凭据按现有 BoundProfiles 思路固定，不随前端编辑切换。改名不影响在途运行；配置修改用于新运行。原宿主缓存了客户端／模型时，新配置需创建符合原生命周期的新实例或明确提示重启，不能悄悄改旧 owner。

仅凭据轮换不改模型语义；修改模型、生成配置、权重或底层服务后需重新核对方法与经验兼容性。同一 URL 不保证远端模型未更新，服务版本不可观察时保存 UNKNOWN。运行快照是配置证据，不是外部服务永不改变的证明。

## 8. RL 与研究记录

首版服务和权重绑定由用户确定，RL 仍选择合法 Unit 及原任务允许的动作，不新增选厂商、换模型或部署机器的动作。连接 ID、凭据及主机名不作为能力语义特征；如使用已知能力、实测成本或资源可用性，沿用共同表示与可见时点规则。

成本包括已发生的请求、网络与执行时延、加载、付费能力核对和接入准备；一次总时延不再与其嵌套子时延重复相加。只能获得端到端时延时，不伪造服务端推理时间；本地算力／token 无法测量的项保留 UNKNOWN。

记录来源修订、依赖／绑定身份、模型与权重版本、原加载／生成参数、原宿主及配置摘要，支持旧运行追溯。更换模型后重新训练的收益不得归因于单纯调度优化；重放和条件重评继续遵守既有兼容范围。

已有路径和非敏感初始化配置保留。已有来源尚未形成依赖需求时，继续显示旧配置及缺口；不能为了迁移由开发者手工填入每个仓库的需求／构造答案。补齐资源后复用仍有效的源码分析，重新核对受影响的绑定并产生新版本，不因改名或轮换 Key 重新付费分析整个仓库。
