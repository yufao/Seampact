# 0.13.0 依赖镜像复用与统一构建：版本记录

功能起点：2026-10-25；文档合并：2026-10-29。当前版本为 0.14.0。现行规则、已有来源更新、平台与 worker 的操作统一维护在[镜像构建与依赖复用](镜像构建与依赖复用.md)；本页保留 0.13.0 的实现和验证事实，不作为当前构建命令来源。平台安装与更新仍从[服务器部署](服务器部署.md)进入。

## 1. 当时引入的机制

0.13.0 将运行组构建从整仓源码先复制改为“基础镜像 → 可独立安装的第三方依赖 → 原库源码与 worker”，并将 `--no-cache-dir` 改为同一 builder 的 BuildKit pip 下载缓存。

- `image_build.py` 检查原 requirements 及递归 `-r`／`-c` 引用，生成两阶段 Dockerfile 和 `build-reuse.json`；不能确认独立安装的形式继续使用原源码上下文。
- `backends.py` 先导出命名依赖镜像，再构建最终 worker，两步共用超时预算；当时最终构建主要依赖 BuildKit 层缓存。
- 生成、构建、发布与启动核对来源安装身份、运行组契约和平台核心身份；过期工件重新生成。
- 前端增加依赖镜像提示，以及来源／运行组的一键准备与释放后面板记录清理。

当时额外包和项目安装仍在源码后，环境标识使用基础镜像引用；平台自己的 Dockerfile 尚未分离依赖与源码。2026-10-29 补齐了平台依赖环境及精确锁、worker 实际基础镜像身份核验和直接环境复用、可独立额外包前置及执行模块闭包身份。后续行为以[当前说明](镜像构建与依赖复用.md)为准。

这些构建改动没有改变原库算法、参数映射、拆分规则、W／H／R、owner 生命周期或 RL 学习器。0.12.0 的接入与实验事实仍见[本地接入与实验接续](0.12_本地接入与实验接续.md)。

## 2. 已有来源与资料保留

原仓库、冻结源码、权重、数据、索引和历史研究记录继续保留；旧整库镜像不会自动拆成新的依赖环境，旧版未留下的 pip 缓存也不能推定可复用。需要重检时沿用当前来源配置、完整候选和正常构建流程，不增加旧实验专用转换路径。

### 一键准备与普通重启

现行步骤、跳过条件、session／代次含义和“清理记录”的范围已合并到[统一操作说明](镜像构建与依赖复用.md#一键准备与普通重启)。该面板清理不删除镜像、权重或运行中的容器。

## 3. 历史验证边界

当时已有一份原来源运行组镜像的真实构建成功记录，只能证明该次镜像构建与包依赖检查通过。0.13.0 通用复用逻辑完成本地针对性核验，一次性脚本与试构建目录已清理；开发机没有可用 Docker 引擎。

**跨库实际缓存命中、节省时间和空间、GPU worker 推理及当时的完整调度训练仍须分别实测。** 旧构建成功或静态检查通过不代表这些结果，也不证明 2026-10-29 新机制已经在 Docker 上实跑。存储和运行边界见[当前构建说明](镜像构建与依赖复用.md#5-证据与存储边界)，统一实现与临时文件清理规则见 [AGENTS.md](../AGENTS.md)。
