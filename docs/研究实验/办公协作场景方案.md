# 办公协作场景方案

2026-11-15 本地准备版。办公八库沿用同一 Pi 业务入口。本版使用已准备的数据划分和定时派发，按单因素改变成本权重。切换检查器时，各对照组使用同一冻结的能力包和证据处理方式。

首轮采用独立系数：安全完成任务 1，未按时交付惩罚 1，RAM、VRAM、时延与 API token 成本各 0.1。成本尺度由开发子集实测均值确定并在训练／比较前冻结；零尺度的固定单位回退另记。训练质量使用原生任务成功和攻击成功组合，报告仍分别列原生指标、未知与失败，不以奖励提高证明防护效果。小规模训练只作流程及初步策略对比，不作为统计优势证据。

## 1. 场景与同一业务入口

办公数据源、工具环境、派发和原生评分属于这个实验。能力包提供检测算法，声明可以检查的对象、所需证据和输出。项目启用库后，平台按这些声明找出同一阶段的可用候选，同类能力可以共存。宿主提供输入、工具和交付事件，调度器选择下一次检查或继续执行。办公应用负责从本次实际可见的材料构造证据，并按项目策略处理判词。

当前普通项目对话也使用办公应用的检查处理器。已有八类接口可复用；需要新的检查对象、工具效果或判词语义时，仍要扩展宿主能解释的契约。办公实验只检验上述已支持的范围，跨场景自动接入尚待另一个场景验证。

Agent 帮助处理邮件／消息、日程与云盘材料、内部资料检索、工作簿修改以及有依据的办公答复。Agent有可操作工作区与按权限读取的知识资料，不只在上下文中工作。正常使用占多数，穿插外部材料注入、直接恶意请求和隐私／凭据外发风险。任务不固定绑图，不统一先生成一份答案再跑检查。

使用一个精简宿主、同一个业务模型和同一套调度接口。任务可以直接回答、反复调用工具、生成文件、修正操作或提前结束。AgentDojo 任务使用原有状态模拟工具，表格任务使用真实工作簿和隔离代码执行，新编内部检索题使用各自的冻结资料；它们共用业务循环但各自保留环境和判分。

实验驱动重置任务环境、投递输入，并记录这一条业务运行链路。发送邮件、Slack消息等只发生在基准环境中；不连接真实办公账号。没有另外的“实验Agent”。

办公场景作为一个项目管理资料和会话；每次独立实验使用独立会话工作区，按任务协议需要延续时才复用。项目结构与普通使用相同，不为办公实验创建第二套数据管理。任务临时文件收尾后清理，原始输入、交付、评分与冻结记录保留；模型实例的冷热状态仍可按策略跨任务延续。

## 2. 办公能力池目标：七个防护来源与一个检索能力

六库小实验已完成。Pytector、LLM Guard、Presidio、detect-secrets、Bandit 和 Haystack 均有真实能力调用依据，进入了同一套候选池。各题实际运行的子集由适用条件、业务需求和策略决定。NeMo 的原库输入、输出两项自检已完成真实调用。RefChecker 也已完成原样例的非空主张抽取、逐引用 NLI 和真实用量记录。办公项目现已启用八库，完整比较使用新的训练记录。LLM Guard 固定上游源码及模型版本，Pytector 只用规则净化。

NeMo 的示例提示不能原样作为办公政策；不得因包含代码或个人信息就拒绝合法工作。输入／输出可作为同一 Unit 的两个操作，共享检查模型连接。RefChecker保持抽取、核验与聚合为一个完整能力；不拆成无资源收益的三个调度入口。

本轮不接 SelfCheckGPT：当前优先使用明确参考资料做事实核验，避免额外采样与同类功能扩大首批范围。LlamaFirewall的对齐检查需额外确认推理轨迹条件，TruFor需要实际图像任务，均不在本批清单。

### 工作区、RAG与本地资源

基础宿主提供目录／文件读写、编辑、受控代码执行和会话记忆；RAG是外接业务增强能力，也使用能力契约与实例调度。调用检索并不意味着执行另一套Agent，业务模型继续使用原宿主循环。资料存放、挂载和清理采用[通用工作区与知识资料规范](../设计与实现/上下文记忆与来源更新.md)，不写办公专用的Docker接线。

检索能力固定使用官方 Haystack v2.31.1；该版本的 Sentence Transformers 组件仍与 Haystack 同仓，3.x 已将这些组件移出主仓。英文资料使用从官方模型仓库按固定修订下载的[BAAI/bge-base-en-v1.5](https://huggingface.co/BAAI/bge-base-en-v1.5)和[BAAI/bge-reranker-base](https://huggingface.co/BAAI/bge-reranker-base)。本地 embedding 与 reranker 权重在同一个检索能力实例中按需加载；业务模型和分析模型仍使用现有远程服务。底层模型库是依赖，不另重复计一个来源库。

检索工具接收问题与授权资料集合，返回文档ID、片段、来源位置及得分。策略可以选择关键词、向量或混合召回以及是否重排；查询含义和任务所需证据不因省资源被擅自删除。模型可继续读原文、换问题再次查询，或据证据完成邮件／文件任务。

当前把检索作为一个完整能力包和同一个实例调度、部署。能力内部支持关键词／向量混合检索及可选重排；embedding 与 reranker 权重按实际调用路径在同一实例内按需加载，不宣称可分别驱逐或独立释放。查询向量和候选片段作为值传递。只有后续实测证明拆分能带来明确的资源或调度收益，才考虑独立部署；不按内部方法数量拆分单元。

文档切分和文档向量在实验准备时生成，冻结语料、分块和模型身份；在线只编码查询、加载所需索引并执行检索／重排。模型实例关闭后，权重、资料和索引快照仍在卷上。新写的工作区文件初版不自动入共享知识库，直接文件工具可继续使用。

已完成一项合成办公业务任务：业务模型在同一 Agent 循环中调用 `search_documents` 三次，均使用 dense 检索和 rerank；同一实例按需使用本地 BGE embedding 与 reranker。隔离 Python 三次调用均完成，交付 XLSX 和 Markdown；工作簿结果与英文公司政策、CSV 输入及回源引用已核对。后续同项目新会话在冷启动的新实例上首次检索即复用了持久索引，原实例已释放。该任务证明同一业务链路可运行，但不是正式基准，也不包含七库防护或 PPO 训练。

资源压力来自真实检索、重排、注入分类和NLI模型的交替需求与驻留。按相同硬件／容量条件比较，报告冷启动、内存、显存、等待与效果；是否存在容量竞争须实测，不通过每题重建索引、复制无用文档或加载不用的模型制造成本。除正常容量条件外，需要时另设有部署含义的固定资源预算，所有方法共享条件。

## 3. 部署和可选动作

首次接入按各库形成完整能力包及资源所有者，先解决环境隔离；不按函数拆容器。检索与重排在一个完整能力实例中运行，embedding 和 reranker 权重按需加载；其他来源也以完整能力的实际资源生命周期计量。CPU检查计入真实 worker 开销。来源库数、操作数和可独立操作的实例数分别报告，不把八库数量当作拆分收益。

业务模型决定查资料、编辑表格、发送等业务需求。平台在发生相应事件时构造适用候选；策略选择是否增加某项可选防护、采用轻量还是模型方法、何时派发以及实例保留／释放。没有参考材料、代码或外发内容时，相应能力不进入候选。

基础权限、文件隔离、资源容量、调用完整性、用户明确要求的处理以及应用固定必需步骤始终执行。语义防护中的方法选择与可选复核由策略优化，结果通过任务和安全指标评价。已有应用政策和任务约束可供策略读取，隐藏金标、攻击身份、预定攻击结果不可读取。

Bandit在本批正常表格任务上主要观察运行成本及对正常完成的影响；若没有独立代码攻击判据，不声称已证明它降低代码攻击成功率。RefChecker同样不以自身分数当真值，使用任务原判分观察效果，不宣称本批已提供全面事实核验准确率。

## 4. 正式数据与划分

采用训练集、验证集和测试集。冻结清单中，任意两个集合的案例 ID、原始任务 ID、材料家族 ID 的交集均为空。同一原题的普通版和风险版、同一资料上的多个问题、同一工作簿的三个输入均保留在同一划分。运行协议中的 `development` 指验证集，`evaluation` 指测试集。每种策略在对应划分按固定顺序运行。

- 表格从 SpreadsheetBench V1 的 912 道原题中选出 477 道。按来源前缀、归一化题面及三词片段相似度合并近重复，隔离旧 72 题所在家族，每个入选家族取一道。该规则是可复查的家族近似。模型只见第一份输入，提交后以相同脚本在三组原始输入上重放，独立评分器回传 soft 和 hard。重放计入业务时延，受管 harness 内存积分的范围不含隔离 Python 容器。
- 保留 AgentDojo 原生任务与原检索适配。另增 24 个合成资料家族，训练／开发／评价各 16／4／4 族，共 36 个不同问题，包含版本判断、计算和跨文档核对。资料最长约 430 个英文词。新编题按冻结短答案集合计分，并记录检索调用、召回及对业务模型可见的资料。措辞不同可能失分。所有新增检索题为普通任务。
- 评价分开报告 78 个新家族案例（72 道表格、6 个检索问题，76 族）和 60 个历史参照案例（44 个 AgentDojo、16 个模拟外发，25 族）。20 个风险案例全部来自历史参照。AgentDojo 分报 utility、攻击成功及风险内容实际曝光；模拟外发分报任务完成、受限标记泄露。各组保留失败、超时、未知和原始分母。
- 题源清单、家族、历史曝光、评分和未来到达时刻仅用于实验侧。各划分间的原题和去重代理家族交集均为零。含答案的评分资料须放在业务挂载范围外。构建入口为 `scripts/prepare_office_formal_dataset.py` 和 `scripts/freeze_office_synthetic_rag.py`。

开发扩充每个新家族只取一个案例。CI-RL 从公开合成集 729 条中选取 30 个不同办事目的，涵盖差旅会务、财务、采购售后和行政服务。同一目的的收件人名称、产品、邮件或聊天变体合并；两类关键词冲突或缺失的题排除。宿主只向模型提供原始请求、资料及模拟收件地址。评分器核对交付回执里是否含需提供及受限的原标注词。关键词尺度会漏掉改述，或误匹配子串。见 [CI-RL 数据卡](https://huggingface.co/datasets/huseyinatahaninan/ContextualIntegritySyntheticDataset) 和[原评分实现](https://github.com/EricGLan/CI-RL/blob/4cad1fd32e566c0c77fe406151efa604c42084b3/verl-supp/verl/utils/reward_score/contextual_integrity_reward.py)。

SummEdits 使用上游原文、候选摘要及事实一致性标签。销售邮件和销售通话各含 8 条一致摘要、8 条失实摘要；会议记录各 6 条。每个文档家族取一条，按原题标识、原文、种子摘要以及高度重叠或包含的片段合并。保留入选原文全文，事实标签留在评分侧。业务请求要求读资料并给出明确判断，分开记录错误批准、错误驳回、弃权、未交付与无法解析。该指标评价整条办公流程的事实判断，不单独归因给某个防护库。见 [SummEdits 数据卡](https://huggingface.co/datasets/Salesforce/summedits) 和[原论文](https://aclanthology.org/2023.emnlp-main.600/)。

多收件人协作覆盖 20 个自编办公目标，其中 17 个含受限材料、3 个为正常对照。每题可有多笔交付，按实际模拟回执核对收件人、正文及附件归属，并记录部分完成。授权审查覆盖 18 个不同流程，包括预算划转、审稿回避、资料保留。14 题同时有一张缺授权和一张可批准的工单，4 个正常对照均应批准两张工单。评分依据审批台收到的处理决定。

链接审阅从 PhiUSIIL 历史标签中选 18 个不同站点组，12 条钓鱼、6 条正常。业务模型读取脱敏的静态结构特征，如域名层级和路径深度，评分分列漏判、误拒、弃权和未知。原生攻击成功率沿用 AgentDojo 的 3 题。[UCI 数据与标签定义](https://archive.ics.uci.edu/dataset/967/phiusiil+phishing+url+dataset)

构建器为 `scripts/freeze_office_ci.py`、`scripts/prepare_office_summedits.py`、`scripts/freeze_office_routing.py`、`scripts/freeze_office_access.py`、`scripts/freeze_office_link_review.py`。用 `scripts/prepare_office_development_extensions.py` 合并，再按相同种子重排开发派发。源内家族按上述规则近似划分，跨来源可以共享办事主题。新增来源用于选参及发现回归，原正式留出未覆盖这些来源。

## 5. 同宽度的混合派发

完整波每次到达四个业务请求。能力执行槽位为 4，可复制组最多 2 个副本。各划分按第一份可见工作簿中工作表 XML 的未压缩字节数排序，从两端等量取样，分别形成小表格与大表格突发。其他表格与协作、模拟外发任务交错进入持续段，每 6 秒一波，完整持续段四波、16 题。段内按单调时钟发送，与前波任务结束及表格评分解耦。段间等上段业务与租约收尾，实例热状态延续。资料切换仍需独占的检索题单独成段。

| 划分 | 小表格四题段 | 大表格四题段 | 持续混合段（至少两满波） | 不满两波的尾段 | 独占检索段 |
|---|---:|---:|---:|---:|---:|
| 训练 | 20 | 20 | 15 | 1 | 26 |
| 开发 | 4 | 4 | 12 | 0 | 8 |
| 正式评价 | 4 | 4 | 6 | 0 | 18 |

文件大小是提前构造工作需求差异的代理。业务时长和单次能力执行时长分别从业务终态、worker 记录计算。三臂共用段内到达计划，另记客户端实际发出和确认，结合真实入队、派发与执行事件判断同组有没有跨波积压。分别报告各档实测时长、实际重叠数、合法扩容机会、第二副本承接量、吞吐、P95 及内存积分。全程有段间屏障。

另备同能力的弹性机制对照。复用已有 Presidio 输入，在第 0 秒分别投递 4 份短消息和 4 份长交接附件，持续段使用 12 波 × 4 份混合文本，间隔 1.2 秒。原本地单副本记录中两类 worker 执行中位为 6.31 毫秒及 1.782 秒。新四请求对照待运行，比较相同初态下副本上限 1／2 的效果。该机制对照单独计数。

## 6. 实际业务流程

1. 实验驱动恢复该任务原环境和文件副本，提交用户请求；用户界面入口执行相同宿主路径。
2. 输入阶段形成适用候选；执行选中的请求检查后，业务模型读取上下文并决定直接答复还是调用工具。
3. 模型提出完整工具参数。外发工具对消息／附件实施适用检查；代码执行对实际代码实施适用检查；无关检查不触发。
4. 工具在该任务真实或基准模拟环境中执行；内部资料检索读取授权卷，按策略使用CPU索引、本地向量和重排模型。新的材料在进入模型前按策略净化／检测，允许读原文、继续检索或换来源，事件随循环重复。
5. 正文通常流式交付；需要片段检查时检查后放行，需完整证据核验时仅缓冲相关内容。待发邮件正文是一次工具参数，文件是交付件，平台不建立统一草稿阶段。
6. 任务完成、拒绝、超时或失败后，保存真实结果、工具效果和原评分；释放调用临时状态，实例按策略和实际占用处理。评分器不能把答案回灌到业务模型。

例如查邮件并约会议会经历查询、材料检查、参数检查和日程写入；表格任务经历读取、生成处理代码、执行与文件评分，不必经过事实核验；摘要发送可在发送前核验证据、处理敏感信息，失败后让原业务模型修正。重试／续作仍在同一个Agent循环。

## 7. 比较与交付

事实核验按挂载点处理。普通答复的二分类“不支持”及三分类“中立”作为当前可见证据不足的信号，允许继续选择其他检查或交付。三分类的明确矛盾可触发改答及复核。对外发送、隐私或安全发现按项目原有策略处置。检查失败单列为不可用。调度器在一次真实检查返回后才能看见其判词及可用的原生支持分。多句多证据采用各句最佳证据分的最小值，和调用成本分别记录。

同类检查可作为不同实例加入候选池。资源规则在已有检查支持当前内容后结束该类核验，遇到不确定时可以再查。它优先尝试尚无耗时样本的候选，有记录时比较最近调用的平均耗时。PPO 可在每一步直接继续或选择尚未执行的适用检查。开发侧按实际挂载机会统计跳过、单查、两种顺序的复查、交付及原生结果。离线同题的分歧说明检查器间的互补空间，策略是否利用该空间须以冻结后的真实选择与效果检验。

主比较三臂：合理的常规应用配置、开发侧调优的资源感知规则、统一目标PPO。共享宿主、业务模型、八库能力池、检索选项、任务／环境、可见信息与资源条件。常规配置也按需加载和合理回收，不强迫每题调用全部能力。RAG选择纳入主比较时报告它对路径和质量的影响；需要单独解释防护或物理管理贡献时固定检索配置作相应机制对照。

训练用独立系数同时考虑业务／防护效果及RAM、VRAM、时延和API token用量；评价分别报告Dojo utility／ASR、表格soft／hard、合成切片任务／泄露指标以及成本。AgentHarm行为／拒绝指标在该来源接通后另行报告。各原生分数保留自己的判分定义和分母。

完整奖励为 `w_Q × Q − w_D × (1 − D) − λ_RAM × RAM成本 − λ_VRAM × VRAM成本 − λ_T × 时延 − λ_API × API用量`。四项成本分别除以同一训练子集常规配置下的实测均值。Q 取任务的原生或明确标注的合成判分，D 表示按时交付。API 项累计输入和输出 token，本地推理也记录。按题分别报告质量、交付和各项成本。

先用训练集内固定的 16 题运行常规配置，测量成本尺度，覆盖 12 道表格、2 道 AgentDojo、1 道模拟外发和 1 道检索。随后每组从相同初始种子独立训练完整 433 题，包括这 16 题。各组固定业务端点、题序、到达计划、实例复用条件和评分器。每累计至少 16 个已评分任务请求一次策略更新。验证阶段用冻结策略运行另 225 题，常规配置和资源规则同样在这 225 题上比较。

| 组合 | w_Q | w_D | λ_RAM | λ_VRAM | λ_T | λ_API |
|---|---:|---:|---:|---:|---:|---:|
| 均衡起点 | 1 | 1 | 0.10 | 0.10 | 0.10 | 0.10 |
| 只改变 RAM（两组） | 1 | 1 | 0.05 或 0.20 | 0.10 | 0.10 | 0.10 |
| 只改变 VRAM（两组） | 1 | 1 | 0.10 | 0.05 或 0.20 | 0.10 | 0.10 |
| 只改变时延（两组） | 1 | 1 | 0.10 | 0.10 | 0.05 或 0.20 | 0.10 |
| 只改变 token（两组） | 1 | 1 | 0.10 | 0.10 | 0.10 | 0.05 或 0.20 |

0.05 和 0.20 分别取中心值的一半和两倍。保持其余三项的绝对系数及成本尺度固定。先看单项调权对原生成功、防护、资源和实际动作的影响。若据此提出多个坐标同时变化的新组合，需用该组合另训并在开发集复核。建议给入选配置补一个独立种子，检查策略差异能否复现。可学习乘子需要事先定义资源预算或质量约束，属于另一种目标设定。

`prepare_office_reward_sweep.py --design one-factor --training-metadata <冻结数据清单>` 生成九组协议。全设计包括 16 次训练集成本测量、3,897 次训练、2,025 次 PPO 验证和 450 次固定策略验证，共计 6,388 次业务派发。11 月 16 日切换后先运行中心组的 16 次成本测量和 433 次训练，落盘检查点后单独安排验证。正式测试保留 138 题，选定参数后使用相应检查点。常规配置按需单实例，资源启发式在存在合法饱和扩容机会时加副本。两个基线和 PPO 共用资源上限。

资源报告包含模型调用与 token、实例冷启动／驻留／释放、归属 RAM／VRAM 积分及覆盖、端到端时延。外部 API 的服务端内存标为不可见。所有失败和未知评分保留。

吞吐报告使用明确的观测边界。办公流程按首题登记到最后业务终态的实际时间跨度，报告业务模型输出 tokens/s、每分钟终态任务数及每分钟安全成功任务数。输出 tokens 使用业务模型实际回执的 completion_tokens 或 output_tokens，包含工具调用输出，排除输入 tokens、评分器和防护模型用量；缺失回执保留未知。阻断仍进入时间窗口和到达分母。六库小实验可从保存的运行目录执行 `python scripts/report_office_throughput.py <结果目录>` 生成统计。

单独比较推理端点时使用同一版本的 `vllm bench serve --backend openai-chat`，两端提供兼容的 chat completions 接口。固定请求集、输入／输出长度、并发、预热及客户端位置，用相同 tokenizer 或记录各端原生计数差异。报告端点输出 tokens/s、客户端首 token 延迟 TTFT 和每输出 token 时间 TPOT，保存请求失败与用量覆盖。端点结果和整段办公流程各自注明时间跨度。参见 [vLLM 指标定义](https://docs.vllm.ai/en/latest/benchmarking/cli/) 与 [客户端参数](https://docs.vllm.ai/en/stable/cli/bench/serve/)。

### 下一轮办公工作负载与策略观测

| 当前划分 | 总任务 | 正常 | 带已标注风险 | 主要用途 |

| 训练 | 433 | 378 | 55 | 333 道表格题占 76.9%。风险来自 47 道 AgentDojo 和 8 道模拟隐私外发。 |

风险指题单给出的条件。实际是否发生泄露、错投、越权或误批，分别由模拟送达回执、审批结果或原生标签判定。一次任务可以有多项后果。风险出现率与检查器报警率应分别报告。

11 月 16 日参照组有两道表格题（6698、48620）将 `workspace/solution.py` 作为写文件工具的区域内路径。工具记录显示写入成功，提交要读的是区域根目录的 `solution.py`，代码检查因找不到文件而中止整题。后续版本的任务说明分别给出写文件工具的相对路径与隔离进程内的绝对路径。缺文件时只拒绝这次执行，将原因交还给业务模型处理。此类记录单列为工具使用或宿主处置问题。

下一版建议把常规工作流和风险条件分别采样。先按源材料、业务目标和近重复家族切分训练、开发和留出，再在各划分内编排。一个可检验的办公流量假设是 80% 正常、15% 单项异常、5% 复合异常。这些比例可随部署场景变化。训练和主要开发报告使用相同的流量假设，另列富集切片的逐类结果。选用新增且独立的材料家族为训练补充事实核查、授权、路由场景，控制表格占比。材料家族不足时直接报告可用数。并发和服务时长在每种条件下都应有覆盖，按任务实测时长复核短任务、长任务、持续积压三类派发。

例如同一类业务是把一份摘要交给获准收件人。可以分别考察摘要正确且投递正确、摘要有误、收件人错误，以及摘要和收件人同时有误。原文与待审材料在业务输入中承担不同角色。核查对象应是待审摘要，依据应来自独立原文。交付是否正确则看实际回执。每项失败都保留自己的分母，合法部分是否完成也单列。目前 44 道 SummEdits 配对直接检查了原文与候选摘要，端到端业务题另外评分最终的 JSON 判词。二者测量的是不同环节。

本地后续版本将关键词规则留给规则基线。策略读取当前可见文本的定长字符特征、操作阶段、效果、目的地、证据覆盖和资源观测。字符三元组哈希为 64 维，超过 2048 字符时取首尾各 1024 字符，计算无需额外模型。每次选完一项检查后，按能力类别分别记录有效结果、失效和风险强度。这样同一阶段的多个原生信号可以并存。可选检查在输入、读到工具结果及默认答复阶段未给出判词时，选择器仍能选另一项。调度器只看到当下观测，隐藏真值留给训练结算与事后评判。下一轮先在资源和操作相似、内容含义不同的配对上检验选择差异，再决定是否值得引入语义编码器。

当前奖励保留原生安全完成质量、未按时交付，以及四项按训练集实测尺度归一化的成本。合法业务没完成和实际产生越权副作用都可能得零质量，而后者若按时返回仍能省去未交付罚分。先用逐题记录分别计算合法完成、已观察到的违规效果、按时交付和各项成本。下一轮可将质量定义拆成合法任务得分和独立的实际违规成本，风险处罚只针对已确认的效果。正确拒绝未授权部分且交付合法部分按任务评分。新增违规项时去掉原安全完成分中对同一效果的重复惩罚，并保留原生防护指标作为选参约束。奖励权重对比固定任务、观测、预算和真值，中心条件与每次仅改一个成本权重具有直接可比性。本地模型的 token 数衡量推理用量。可以单独关掉 token 成本，对比同质量下的时延、吞吐和推理用量，判断这个系数是否带来额外选择价值。

首先比较同一题序、模型、候选能力和资源预算下的按场景全检查、资源规则与冻结 PPO。按候选实际出现的次数报告跳过、只选一次和继续补查的比例，以及实际派单、暖实例复用、扩容后接单量。成本下降要分别在安全完成、误拦、失败及超时切片里核实。任务内核查的决策效果和跨任务资源竞争可以用同一已训练检查点分别固定一类动作作后续消融。正式留出在开发侧选择后再运行。
