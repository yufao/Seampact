# SeamPact 研究实验方案

更新：2026-11-11。实验直接运行[同一 Agent 业务链路](../设计与实现/Harness接入与调度重设计讨论.md)。实验驱动提供任务和环境、收集轨迹并调用评分器，不另写生成—检查主循环。当前未产生新协议实验结果。

## 研究问题与证据

| 问题 | 证据与比较 |
|---|---|
| 自动接入是否简化使用 | 固定完整仓库到真实可用能力的耗时、缺口和实际人工修改；相关原例子／任务评分。该项属于接入阶段，不是业务模型先生成草稿 |
| 联合策略是否节省成本且保持防护与业务能力 | 相同任务、环境和能力池下完整运行 Agent，直接比较原生任务成功、攻击成功、正常拒绝及归属成本 |
| 收益来自哪一部分 | 选择与实例管理分开的策略作为关键机制对照；固定调用轨迹仅分析物理资源管理贡献 |
| 对变化是否适应 | 同一能力池改变正常任务／风险类别组合，增减有用途的能力；分别说明冻结策略、重新训练及训练中见过的来源 |
| 拆分是否有收益 | 仅对真实独立资源边界比较合并／拆分，双方均允许正常缓存和释放，计入传输、冷启动及任务效果 |

## 场景与来源选择

准备办公协作、软件工作台、资料与文档三个候选场景，落地两至三个完整混合负载。每场七至十个有实际用途的来源库；每个请求只调用适用能力，可重复调用或提前结束。正常请求占多数，混合比例属于研究构造，不宣称来自真实用户分布。

[数据源选型](Agent任务与攻击数据源选型.md)比较常用 Agent 跑分和攻击测试来源、原生评分、环境成本及适用边界。[能力候选](Harness候选与两层评价方案.md)区分防护库、业务工具和实验评分器。优先用 AgentDojo／AgentDyn 的完整任务及安全判定，再加入原生表格、软件和资料任务。静态注入题不能代替完整 Agent 运行，单一修复或问答集不能独自代表混合场景。

## 主比较与机制对照

主比较使用同一宿主、业务模型、能力池、任务／初始环境、可见信息和资源限制：

1. 合理的常规应用防护配置：按实际阶段启用相关方法，并正常按需加载和回收。
2. 调优的资源感知规则：利用与 PPO 相同可得的内容信号、能力信息及冷热／容量状态，开发集确定阈值和保留策略。
3. 联合 PPO：一套目标配置、一份冻结检查点，选择可选能力和合法实例动作，报告同一次运行的全部指标。

进一步补充与研究最接近、能在相同设置下实现的自适应方法；未完成来源及可实现性核查前不宣称覆盖现有强方法。全适用检查可作为补充条件，不称防护上界或唯一主对照。

关键消融将能力选择与实例管理分开，尽量保持模型容量、训练预算与其他实现一致。固定调用轨迹只比较物理管理，不替代主实验；不同策略改变业务路径时，主实验允许自然产生不同轨迹，并报告实际调用和效果。

## 评价指标与训练奖励

任务与攻击是否成功由选定数据集原评分器判定。保留其原义：程序环境检查、测试通过、答案匹配、模型裁判不是同一种证据。记录评分器版本；使用模型裁判时冻结模型与提示。由任务结果和成本构造训练奖励，奖励总分不代替任何原指标。

至少报告正常任务成功／质量、受攻击任务成功、各风险类型攻击成功、拒绝或阻断、失败／超时，以及时延、RAM／VRAM积分和适用的API费用。正常任务失败不自动等于误拒；只有正常可完成标签结合明确拒绝／阻断事件时才计算相应误拒指标。图表不拼接不同运行的最优分项。

## 数据与运行安排

训练、调参与冻结评价按基础任务／仓库／文档或环境族划分，同一任务的干净与攻击变体在同一分区。原测试集不拿来训练；只有测试划分的基准先用于冻结评价，另用许可适当的训练来源。攻击标签和未来任务不进入策略。

优先完成一个完整环境的多类任务和原生评分，再扩能力池、训练和冻结比较，随后扩场景。预算不足时先缩小任务清单与重复数，保留所声明方法和完整任务流程；首调、mock或无评分连通性不作正式结果。[运行协议](多来源共享资源场景协议.md)规定混合、归因和失败处理，[测量协议](性能探针与测量协议.md)规定成本。
