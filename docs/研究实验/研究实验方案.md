# SeamPact 研究实验方案

更新：2026-11-12。实验直接运行[同一 Agent 业务链路](../设计与实现/Harness接入与调度重设计讨论.md)。实验驱动提供任务和环境、收集轨迹并调用评分器，不另写生成—检查主循环。当前七组实验只做开发侧训练与奖励调权，尚未形成正式主比较。

## 研究问题与证据

| 问题 | 证据与比较 |
|---|---|
| 自动接入是否简化使用 | 固定完整仓库到真实可用能力的耗时、缺口和实际人工修改；相关原例子／任务评分。该项属于接入阶段，不是业务模型先生成草稿 |
| 联合策略是否节省成本且保持防护与业务能力 | 相同任务、环境和能力池下完整运行 Agent，直接比较原生任务成功、攻击成功、正常拒绝及归属成本 |
| 收益来自哪一部分 | 选择与实例管理分开的策略作为关键机制对照；固定调用轨迹仅分析物理资源管理贡献 |
| 对变化是否适应 | 同一能力池改变正常任务／风险类别组合，增减有用途的能力；分别说明冻结策略、重新训练及训练中见过的来源 |
| 拆分是否有收益 | 仅对真实独立资源边界比较合并／拆分，双方均允许正常缓存和释放，计入传输、冷启动及任务效果 |

## 场景与来源选择

准备办公协作、软件工作台、资料与文档三个候选场景，落地两至三个完整混合负载。每场七至十个有实际用途的来源库；每个请求只调用适用能力，可重复调用或提前结束。正常请求占多数，混合比例属于研究构造，不宣称来自真实用户分布。

[数据源选型](Agent任务与攻击数据源选型.md)比较常用 Agent 跑分和攻击测试来源、原生评分、环境成本及适用边界。[能力候选](Harness候选与两层评价方案.md)区分防护库、业务工具和实验评分器。优先用 AgentDojo／AgentDyn 的完整任务及安全判定，再加入原生表格、软件和资料任务。静态注入题不能代替完整 Agent 运行，单一修复或问答集不能独自代表混合场景。

## 主比较与机制对照

现有“常规配置、资源规则、PPO”三臂属于 pilot，用于流程验证和开发选配。七组奖励权重也只在训练／开发集选择配置；当前冻结的七组协议中，常规配置与资源规则都使用全适用检查和 TTL 保留，规则结果只是工程参考，并未形成不同的强策略。正式基线尚待选择、实现和冻结，不沿用 pilot 即宣称完成强方法比较。拟保留以下最多四类主比较，共享宿主、业务模型、能力池、任务／初始环境、可见信息和资源限制：

1. **常规应用配置**：按实际事件启用相关方法，正常按需加载和回收，固定合理的检查映射与保留时间。
2. **开发集调优的风险级联与保留策略**：先运行适用的轻量方法，再根据已得到的检查信号、剩余时间和冷热状态决定升级；按历史复用间隔、冷启动与驻留成本确定保留／释放，开发集选择阈值。
3. **情境 bandit 或预测贪心，二选一**：检验简单的上下文学习是否足够。可先以完整的“检查级联＋保留程序”配置作为任务级候选，使用任务终态原生评分和实际成本训练；bandit 学习候选收益，预测贪心拟合质量／交付／成本后选择当前预期最优配置。不得把同一终态质量直接复制给所有事件动作。跨任务缓存仍会影响未来状态，需明确该方法采用短视决策，不能套用标准 bandit 的独立轮次保证。
4. **联合 PPO**：一套目标配置、一份冻结检查点，联合选择可选能力、合法派发与实例动作，报告同一次运行的全部指标。

基线设计借鉴以下原始论文的比较与方法原语；本项目的适配须单独说明，不称直接复现这些系统。

| 原始来源 | 可借鉴内容与本场景关系 |
|---|---|
| [DeepRM，HotNets 2016](https://people.csail.mit.edu/hongzi/content/publications/DeepRM-HotNets16.pdf)，§4.1；[Decima，SIGCOMM 2019](https://arxiv.org/pdf/1810.01963)，§7.1 | DeepRM 对比 SJF、Packer、Tetris*；Decima 包含调优加权公平及经参数搜索的 Graphene*。借鉴认真调优领域基线的比较方式。当前办公负载逐题串行，没有多业务队列竞争，不能直接用 SJF／公平调度代表有效强对手。 |
| [Pensieve，SIGCOMM 2017](https://people.csail.mit.edu/hongzi/content/publications/Pensieve-Sigcomm17.pdf)，§5.1 | 与规则方法及 MPC／robustMPC 比较，支持纳入预测／优化型对手。当前尚无经过验证的检查效果与未来调用模拟器，优先考虑可核验训练反馈的预测贪心，不直接宣称实现 MPC。 |
| [Serverless in the Wild，USENIX ATC 2020](https://arxiv.org/pdf/2003.03423)，§4.2、§5 | 根据历史调用间隔调整保活与预热，并与固定保活比较冷启动和内存时间。可迁移自适应保留部分；当前没有主动预热候选，不宣称覆盖原论文完整策略。 |
| [FrugalGPT，2023 arXiv 版本](https://arxiv.org/pdf/2305.05176)，§3–4 | 学习服务序列及升级阈值，在成本约束下优化质量，可迁移为检查级联。其原任务是答案服务选择；本场景仍以任务／安全原判分评价，检查器分数不是真值。 |
| [LinUCB，WWW 2010](https://www.schapire.net/papers/www10.pdf)，§3、§5 | 使用上下文和候选特征学习收益，与 ε-greedy、UCB 及其上下文变体比较。可作为情境 bandit 的算法来源；本项目需处理任务终态反馈与缓存状态影响。 |

所有方法只读取决策时可得的信息；新增风险预测、复用统计或成本估计也向其他方法开放，训练及推理开销计入。正式比较前冻结训练交互和开发搜索预算，分别记录配置试验次数与实际调用成本；七组 PPO 调权和一次规则开发运行不能自动视为等预算。预测器只使用训练侧可取得的反馈，未选动作的结果不能凭空补齐。使用多个训练种子和配对任务统计，先在开发侧冻结原生任务质量、安全与交付的可接受范围，再比较满足条件的方法成本，并保留质量—成本权衡；奖励总分提高不单独证明收益。

关键消融将能力选择与实例管理分开，尽量保持模型容量、训练预算与其他实现一致。PPO 与 A2C／DQN 的候选动作适配比较如有必要另作算法敏感性分析，不替代上述领域基线。固定调用轨迹只比较物理管理，不替代主实验；不同策略改变业务路径时，主实验允许自然产生不同轨迹，并报告实际调用和效果。全适用检查可作为补充条件，不称防护上界或唯一主对照。

## 评价指标与训练奖励

任务与攻击是否成功由选定数据集原评分器判定。保留其原义：程序环境检查、测试通过、答案匹配、模型裁判不是同一种证据。记录评分器版本；使用模型裁判时冻结模型与提示。由任务结果和成本构造训练奖励，奖励总分不代替任何原指标。

至少报告正常任务成功／质量、受攻击任务成功、各风险类型攻击成功、拒绝或阻断、失败／超时，以及时延、RAM／VRAM积分和适用的API费用。正常任务失败不自动等于误拒；只有正常可完成标签结合明确拒绝／阻断事件时才计算相应误拒指标。图表不拼接不同运行的最优分项。

## 数据与运行安排

训练、调参与冻结评价按基础任务／仓库／文档或环境族划分，同一任务的干净与攻击变体在同一分区。原测试集不拿来训练；只有测试划分的基准先用于冻结评价，另用许可适当的训练来源。攻击标签和未来任务不进入策略。

优先完成一个完整环境的多类任务和原生评分，再扩能力池、训练和冻结比较，随后扩场景。预算不足时先缩小任务清单与重复数，保留所声明方法和完整任务流程；首调、mock或无评分连通性不作正式结果。[运行协议](多来源共享资源场景协议.md)规定混合、归因和失败处理，[测量协议](性能探针与测量协议.md)规定成本。
