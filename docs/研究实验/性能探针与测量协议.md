# 成本测量与运行记录协议

更新：2026-11-11。用于[同一 Agent 的混合负载](多来源共享资源场景协议.md)。当前实现已有部分归属采样和在线累计，启动／释放边界与完整训练结算仍需补齐；旧0.15窗口观察器不等于新协议已经运行。

## 计量对象

| 对象 | 记录内容 |
|---|---|
| 业务模型 | 请求、token及可用费用；受管本地服务另计归属资源 |
| 基础宿主与业务工具环境 | 进程／容器成本、任务时间；与防护成本分列 |
| 防护 Unit 实例 | 初始化、执行、空闲、排空、确认释放；RAM／VRAM及调用 |
| 调度与观察 | 决策耗时、采样开销；实验评分和构建成本另列 |

共享实例的资源只积分一次。不能把整机RAM、整卡显存或其他程序成本归到某个能力。借用API不能按本机零显存推断其服务端零成本。基准中的模拟业务工具可按原协议运行，但本地真实防护实例与实际资源必须据实记录。

## 指标和单位

RAM、VRAM记录归属采样峰值和时间积分，统一使用明确的byte或MiB及秒；峰值注明是采样峰值。预留容量乘驻留时间另称预留成本，不与实测混用。运行时延包含模型、工具、防护、冷启动和等待，另报各部分及交付时长。CPU、API费用等在可靠可用时纳入。

正式配置固定成本口径、计量对象、采样间隔和边界处理。定义首尾观测与相邻采样的积分方法、允许间隙及覆盖率；不能要求采样恰好覆盖每一瞬间却永远不给有效成本，也不能无条件用零补首尾。未观测段保持未知，必要时报告可观测区间积分。

释放请求与后端确认释放分别记时。实例结束或跨批保留均按预先约定观测终点处理。任务失败、取消后已经发生的资源开销保留。实验、普通业务和诊断调用有明确范围，诊断成本不混入实验任务分母。

## 事件与历史

记录run／task／call／unit／instance身份与代次、单调时间、阶段、动作及结果、采样值和单位、覆盖与缺失原因。业务终态、用户交付、原评分器结果、实例释放是不同事件。正式运行保留原始结果及事件，在线仅累计活动状态；终态落盘，历史分页读取。

源版本、工作负载、目标／策略、业务模型、实际资源配置与初始缓存状态保存在同一运行清单。凭据仅保存引用，不导出秘密。模型裁判、接入构建和下载可单独统计，不藏入某个策略的线上资源节省。

## 对照与汇总

主实验比较相同初始任务／环境下完整 Agent 的原指标和总成本。防护改变后续调用时，报告工作量与路径变化，不将全部收益称为纯调度收益。固定调用轨迹另作物理管理对照；合并和拆分双方都允许合理缓存和释放。

同一任务清单在各组完整执行，保留失败及评分未知。不同任务的质量不强行统一成一个原生准确率；报告分来源指标，混合汇总使用预先固定的权重。奖励映射只服务训练。结果中的缺失测量显示未知，不能用另一组采样填入。

检查优先复用本次运行的事件和实际后端状态。只有观测明显影响性能或研究要声称测量开销时，再安排专门开销比较；不为每次实验固定追加整套探针实验。历史测量及原输入保持约束仍按[历史运行记录](../history/实现与运行记录.md)解释。
