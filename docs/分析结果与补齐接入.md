# 查看分析结果与补齐接入条件

更新：2026-10-31，SeamPact 0.14.8。本版功能、运行事实与服务器迁移见[更新说明](镜像构建与依赖复用.md)。

当前依赖镜像复用、已有来源重新核对及过期工件处理见[统一构建说明](镜像构建与依赖复用.md)。构建成功、实例就绪和原目标调用成功分别记录。

“分析完成”表示这一轮分析结束。入口静态可绑定、资源可用、真实调用成功和任务效果分别记录。

## 适配问题怎样归纳与改进（2026-10-31）

采用小批归纳、按共性修复的方式：每批先考察 3–5 个结构不同的库，使用已保存分析记录；需要新增分析时再按实际任务启动。不能把单库一个报错视为已验证的跨库共性，也不必等全部来源齐备才修复已经定位清楚的通用缺口。

每个失败样例保留冻结版本、目标入口、原始参数传递关系、候选、检查反馈及历次修正，区分候选证据错误、平台尚不支持、运行环境缺失和资源未配置。将相同程序结构归为一项改进，不按库名逐个放行；每项规则补充需验证正常样例和应继续拒绝的样例。原有库作为回查对象，原算法、owner 和拆分义务保持。

首批已核查 VPC3、MADL、REX-RAG、RefChecker、MiniCheck、PIGuard 的六份分析记录，并在摘要一致的源码上复放 26 条依赖检查。结构归纳、源码核验、Harness 范围建议及逐项验证依据统一见[分析器共性缺口与验证](分析器共性缺口与验证.md)。两个静态 READY 均为辅助入口，不能计作目标防护接入成功。接入检查器能力、分析器根据反馈修正的流程、最终缺口分类分别改进，不通过修改显示文字让失败检查变成通过。

2026-10-31 本地核心改进已接通有限参数传递、SDK 字段、资源来源及初始化缺口检查。检查反馈给分析器具体字段与缺少的原源码范围；界面分开显示候选缺项、证据不全、平台未支持、模型来源和初始化遗漏。分析结束另记剩余条件，不要求靠删除依赖将所有入口改到 READY；完整范围及尚未覆盖结构见上述记录第 7 节。

更新前后端并重新启动后，在“Harness 接入”找到原来的库，点击“分析 Harness”，使用 API 预处理和完整分析生成新记录；不删除来源、不重新添加仓库、不选择沿旧候选局部修复。旧分析记录用于对照。仅想检查规则变化可另用零模型重检，但该操作不会重新发现入口与映射。当前本地改动尚未推送或部署，旧服务器点击分析仍使用旧规则。

## 完整仓库中哪些入口需要接入（2026-10-31）

读取完整仓库，是为了看清原构造、依赖和控制关系，不表示要把每个可调用函数都放进能力池。现有源码分类主要给形态和调用线索，不能可靠证明一个入口是真防护、MOCK 或无关展示；可运行、静态检查通过和任务相关性分别判断。

预处理与分析指示现要求在 purpose/description 中说明用途、目标相关性及依据；未接入的已识别功能在分析说明中保留排除理由，不删除其原源码。

| 实际用途 | 当前接入原则 |
| --- | --- |
| 真实检查、阻断、校准或修复 | 与当前任务相符才作为防护候选，并追踪输入、输出和控制关系 |
| 原模型构造、资源读取、初始化、清理 | 作为必要支撑保留，不因不单独导出就跳过 |
| 普通对话/业务任务宿主 | 需要它承载真实任务时保留；不计成额外防护方法 |
| 前端展示和演示界面 | 通常不单独接入；若含唯一原请求/防护路径，先追踪并保留必要流程 |
| MOCK、固定结果、测试替身 | 不作为真实防护执行或效果证据，可保留为明确的工程测试材料 |
| 离线训练与评价 | 与在线防护分开；原评价程序可承担独立评分，训练入口不因可运行而自动纳入 |
| 混合或尚不明确 | 保留未知和具体源码位置，继续核查或由用户选择，不仅凭文件名删除 |

## 人工选择要保留的入口（2026-10-31）

在当前分析的“候选修订工作台”创建独立修订后，使用“选择本次接入的入口”勾选列表。已能运行和仍缺条件的候选均可取消勾选，不需要手改 JSON。填写修改理由后，先“保存并完整重检”，再“独立安装新候选”才改变能力池。保存前可重新勾选或全选当前候选；安装前的原候选和逐次差异仍保留。

选择只减少单独导出的入口。系统同步缩小运行组成员和明确属于被移除入口的资源映射，保留共享边界、剩余入口的必需依赖和全部原源码；完整检查与安装时运行条件继续生效。取消一个入口不会授权跳过原 controller 内部必须调用的检查。若剩余入口无法独立接入，仍显示缺口，不因人工勾选强行放行。

允许全部取消：应用后该来源的当前入口全部退出能力池，原仓库、分析及运行历史保留。若模型重新生成候选或源码版本变化，须重新确认入口列表；本次选择不是永久的库级黑名单。候选尚未生成、JSON 损坏或入口 ID 重复时，先修正候选才能逐项选择。人工选择及理由留在修订记录中，与无辅助自动接入分别归因。

## 页面上的简明提示（2026-10-31）

所需资源默认只显示资源名称、当前问题和下一步。内部编号、英文错误、逐入口检查及参数映射保存在“查看原始检查记录”，不在卡片上反复显示。

| 页面提示 | 含义与下一步 |
| --- | --- |
| 待平台处理 | 原代码接线尚未核对通过，需要分析器继续修正，或由开发者补通用能力；此时不显示资源下拉框，不引导用户重复添加连接 |
| 待选择服务连接／模型文件 | 接线已核对，可以选择资源，点击“保存并检查” |
| 正在分析／来源已停用 | 等分析结束或重新接入后配置资源 |
| 需要检查所选资源 | 已有选择仍有问题，检查配置或文件；真实服务可用性和模型效果仍需实际运行 |
| 平台暂不支持这段代码的接入方式 | 仅在已有明确的规则不支持结果时显示；不把所有英文检查错误都猜成这一类 |

这些提示不表示后台正在自动修复，也不改变资源选择、入口许可或调用状态。真实运行结果继续单独记录。

最新本地支持还会检查上层入口调用的下游功能：显示“上层入口漏了下游所需资源”时，需要分析器补齐该入口的映射；显示“下游调用还没有查完整”时，需要补读实际调用的同版源码。补一个资源名称或重复选择连接不能解决。有限子进程继承与原 CLI 配置覆盖的具体支持见[核验记录第 11 节](分析器共性缺口与验证.md#11-宿主依赖与原配置覆盖支持补齐2026-10-31)，更新平台后生效。

## 预处理结果是什么

预处理先阅读冻结源码，查找实际功能、原入口、构造与初始化方式，以及服务和权重需求。保存的“预处理工件”是交给后续拆分分析的中间记录，包含源码位置、入口候选、依赖和未解决条件。

预处理不运行原功能，不安装 Unit，也不决定 W/H/R 边界或运行组。后续拆分分析仍可调整入口，并接受独立检查。

“来源与分析”先显示目标、功能位置数、候选入口数和外部依赖数；展开可看用途与源码位置。原始 JSON 和内部编号放在“预处理技术记录”。预处理时的缺口属于历史发现，当前状态以最新分析结论、依赖配置和能力池为准。

## 条件补齐后怎样接入

| 缺少什么 | 怎样补齐 | 后续操作 |
| --- | --- | --- |
| 服务或权重，原参数映射已核对 | 在配置中登记服务或权重并检查，在来源的“所需资源”选择资源 | 点击“保存并检查”，使用已有候选核对并接入满足条件的入口，不再调用模型 |
| 原库要求的固定文件 | 按页面显示的原位置准备文件，并检查位置 | 点击“重新检查并接入可用入口” |
| Python、包或宿主环境 | 在 Harness 配置中准备和核对运行环境 | 从最新分析记录重新检查并接入；环境变化可能使旧候选需要修订 |
| 原参数映射、源码依据或入口候选 | 创建接入修复草稿，补充指导信息，调用当前分析模型局部修复 | 完整重检后，点击“独立安装新候选” |
| 通用宿主或有限规则尚未覆盖 | 修复平台通用实现，或继续保留缺口 | 不能通过选择资源或点击安装强行放行 |
| 当前来源需要交互源码适配 | 用户或外部 Agent 按真实来源修改原入口／配置接线，记录实际介入；原算法及拆分条件保持 | 选择“源码更新”重新冻结，提交完整候选、机械重检并安装；单列人工辅助结果，不算无辅助自动接通 |

“创建接入修复草稿”只创建草稿并填写缺口提示，不会立即调用模型。模型修复后也不会自动替换当前接入结果。

“保存并完整重检”结束后显示 CHECKED，只说明检查流程完成；同一报告仍可包含 READY 和 MISSING。安装草稿会以完整新候选替换当前来源的入口，因此需保留仍要使用的旧入口，不能把模型意外缩减的候选当成修复成功。映射已核对但尚未选连接时，先安装含该映射的候选，再到“所需资源”完成选择。

同一依赖的部分入口映射通过时，可以为这些入口选择资源，其余入口继续保留具体缺口。实际服务停止不会自动把全部静态 READY 改为 MISSING；目标调用时仍可能连接失败。CLI 的目录调用正常返回，也须检查进程退出码与目标输出。

“重新检查并接入可用入口”沿用已有完整候选，创建独立修订、完整检查并安装；不请求分析模型，不更改拆分理论。仍缺条件的入口继续保留待接入状态。

接入后通过“查看该来源的能力池”检查具体入口。静态可绑定之后，还需用真实任务核对初始化、调用结果和目标效果。普通对话中可描述所需任务，由模型使用已接入且开放的真实 Unit；不适用的入口不会因这次接入自动变成目标能力。

## 历史会话

对话页顶部提供“历史会话”和“新对话”。历史支持按问题或回答搜索、重新打开、继续对话，以及刷新后恢复当前会话。

每条历史会话提供“删除”，从历史列表移除后可点击“撤销删除”。删除会话不移除任务执行证据；这些记录仍在任务详情中。运行中的会话需等任务结束再删除。

新消息保存在平台本地状态库中。旧版仅保存过任务回答而没有完整问题，因此这些记录标注“仅保存回答”，可查看但需新建会话继续。场景任务与研究运行仍在任务详情中查看。

平台重启不会恢复原来正在执行的任务；该任务标为已中断，已经保存的普通对话仍可查看和继续。

对话框里的“对话或场景任务”只在存在已激活的研究场景任务时显示。它用于运行已保存的场景任务，不是选择 Harness 的入口；普通对话会按需使用已接入且开放的 Unit。

## 服务、模型和权重怎样区分

| 手头的资源 | 在哪里配置 | 怎样选择 |
| --- | --- | --- |
| 已启动的本地或云端 OpenAI 兼容服务 | 服务连接 | OpenAI 兼容接口；再到模型角色应用到对话、分析或教师 |
| 原 Harness 的专用 HTTP API | 服务连接 | 原库专用 HTTP 接口；保留原客户端，不直接充当平台分析模型 |
| 本地模型目录或文件 | 权重资源 | 登记独立目录或单个文件，填写平台执行环境可见的完整路径；不要指向平台克隆的来源目录 |
| Git 仓库 URL 或本地源码目录 | Harness 接入 | 由分析器查找原功能、入口和依赖 |

“本地／云端”描述部署位置，“API”描述调用方式；接口格式应按服务实际提供的协议选择。仅有权重文件时，登记路径不会自动加载模型或启动推理服务。

登记权重的步骤：准备文件 → 填名称、目录／文件类型及完整路径 → 按原加载器要求声明必要文件 → 保存路径 → 检查资源 → 返回来源的“所需资源”选择。接线未通过、来源正在分析或已停用时不显示选择框，并给出下一步；接线已通过但尚无资源时，提示先添加资源。已有权重也不能绕过尚未通过的原参数映射。

原函数从配置字典读取服务地址或模型名时，分析器可用 `parameter_path` 声明原参数内的固定字符串键路径。检查器核对源码读取、单赋值别名及未遮蔽的词法闭包；运行时只解析经过核对的资源引用，其余配置值仍须有用户明确配置作为依据。动态键、字典变更、跨函数配置传递和 CLI 配置文件不会因此自动获得支持。

连接地址须符合原调用方式。有些原客户端会自行追加 `/v1`，此时 Harness 连接保存它所需的根地址；平台直接调用 OpenAI 兼容服务的连接通常包含 `/v1`。平台不会为原库自动增删路径后缀。部分原 SDK 还要求无认证服务使用非空占位符：明确的非密钥 `EMPTY` 可作为用户配置，真实凭据须使用服务的私有凭据引用。

## 仓库保存在哪里

默认启动配置下，Git URL 来源克隆到 `var/prototype/sources/repositories/<来源 ID>/`，分析使用的冻结源码文件保存在 `var/prototype/snapshots/`。如果启动时指定其他 home，则目录位于该状态目录下。删除来源时删除这些平台克隆。权重登记在独立目录，例如 `var/prototype/models/`；登记路径落在平台克隆里时，删除来源会连该权重登记和文件一起删除。同名的另一份独立目录权重不会被改指到旧克隆，也不会被这次删除带走。

填写本地目录时直接读取原目录，不再复制成 Git 副本，删除来源也不会删除这个目录。同一来源的普通分析使用已接入的目录；“源码更新”修订会重新冻结本地内容或重新拉取 URL，新的平台克隆记在来源上，删除来源时一并清理。页面在“来源与分析”和 Harness 配置卡片上显示当前本地源码目录；历史分析仍按各自冻结版本记录。
