# SeamPact

0.9.0：异构 Harness 自动接入、有限拆分与自适应调度的学术原型。首页提供普通对话及已保存场景任务；配置中维护 Harness 地址、模型、教师准则和学习器，调度页查看实际轨迹与结果。

核心链路是 **地址 → 目录解析 → API 工具分析 → 源码检查与原生绑定 → Unit 能力池 → 场景事件与合法候选 → RL 选择透明干预 → FIFO 许可 → 原 Harness 执行 → 实际结果反馈**。业务模型仍可申请其可见能力；没有可用 Unit 时仍可普通对话。

当前研究规格见[候选与两层评价](docs/Harness候选与两层评价方案.md)：以真实决策选择能力，分别检验拆分自由度、调度净收益和变化后的学习投入。共同能力卡与数值表示、PaperGraph 场景桥及视觉教师传图已有代码；合法细入口的自动导出、真实目标调用和研究收益须分别核实。接入必须由平台分析器处理原库；外部开发者不预写来源包装或切分答案，职责见[研究实验方案 0.0](docs/研究实验方案.md#00-接入预处理绑定拆分与调度的归因边界)。

## 启动

平台核心只需 Python 3.11 或以上；接入远程仓库还需 Git。本版有限原生宿主以用户确认的 Python 3.11、显式生命周期及无 frame 观察范围为依据，运行新构造规则请使用 Python 3.11。Harness 自身的依赖需要装在实际运行它的 Python 环境中。

Linux，在仓库根目录执行：

```bash
PYTHONPATH=src python -B -m seampact serve --home var/prototype --port 8880
```

Windows PowerShell，在仓库根目录一条命令启动（优先使用已有 `.venv-agentdojo`，否则使用当前 `python`）：

```powershell
.\start.cmd
```

打开 http://127.0.0.1:8880，按 Ctrl+C 停止。无需创建或激活新的虚拟环境，也不依赖 `py` launcher。更换端口可用 `.\start.cmd --port 8881`；启动脚本自动设置源码路径，并使用仓库内的 `var/prototype` 保存状态。

Windows PowerShell 手动启动：

```powershell
$env:PYTHONPATH = 'src'
python -B -m seampact serve --home var/prototype --port 8880
```

打开 http://127.0.0.1:8880。配置两个模型角色，保存后直接发送消息。对话模型支持本地或云端的 OpenAI 兼容接口；分析模型使用云端接口。接口地址填基础路径，如本地 `/v1`；平台追加 `/chat/completions`。

接入 Harness 后，在配置中点击“分析”。分析器可访问整仓，按确认的 RuleSet 提出入口、原生构造／初始化、资源绑定及 W／H／R 边界。引擎核对实际源码和支持规则，结果进入能力池。`READY` 表示静态绑定准备完成，原生初始化在真正调用时发生；缺依赖、参数或资源的 Unit 保留为 `MISSING`，显示具体原因。

“来源与分析”“能力池”“任务详情”可在独立页面查看，支持按来源筛选。列表实时更新时保留展开和滚动位置。来源卡片提供“摘除来源”：退出当前能力池、停止后续分析／调用，已进入执行的原调用可收尾；源码与分析历史保留。“重新接入”沿用已完成分析，建立新绑定，不重复调用分析模型。

## 当前实现范围

| 层 | 实际功能 |
|---|---|
| 前端 | 标准对话、模型与 Harness 配置、学习器／教师准则配置、研究运行与分项对照 |
| 分析器 | URL／目录接入，全目录源码工具，入口与构造事实，有限 B-CALL 原前缀／对象引用，W／H、R-INPLACE 与有限循环提取 |
| 调度器 | Double DQN、PPO、离散 SAC 共享候选评分；真实事件训练、参数热启动、冻结策略与条件重评；下层 FIFO；旧业务方案 Q 保留历史定位 |
| 模型适配 | 对话、分析、教师角色独立；文字准则与程序判据共用分项反馈，UNKNOWN 保留费用并排除不完整回报更新 |

方案中已有显式结果数据边和成功出口控制边：后项通过 `$result` 取得前项真实返回值，原生对象留在同一方案的本地 owner 内。引擎核对绑定与实际输入结构；业务语义兼容仍显示 `UNRESOLVED`。B-CALL 可执行受支持的原同步函数前缀，取得原工厂／构造器返回的真实对象；R-INPLACE 可保留外围分支、循环和异常结构，仅门控原调用位置。

0.8.0 已把能力池连接到运行组管理，API 可提出分组、引擎核对原对象／共享状态／控制依赖及远程条件。受支持的独立同步标量入口可导出原源码运行包、Dockerfile 和 K8S 单实例文件，登记运行进程后接到现有聊天和中央 RL。其他能力保留原本地执行并显示缺口。详见[运行组与 K8S](docs/运行组与K8S部署.md)。

动态 SDK 接线、生成器和未覆盖的构造形式仍明确报缺失。当前执行顺序保留；尚未实现合法并行、通用有状态远程执行、跨入口驻留共享粒度及完整 EXPORT／COMPOSE 证明。研究反馈使用实际任务／安全判据及实测成本；已有真实开发运行，尚无 RL 优于固定策略或跨来源泛化结论。操作与本机原始结果入口见[手动启动](docs/手动启动与演示.md)及[研究实验方案](docs/研究实验方案.md)。

MMCT、CRAG、NeMo、DiSP 已通过真实分析 API 完成整仓工具分析；运行事实与未满足条件见[0.7 规则兑现与实际运行](docs/0.7_规则兑现与实际运行.md)。分析完成、可绑定与实际执行分别记录。

## 当前研究方案

用户已确认严格使用原成果表：当前优先来源为 VPC3、MADL、REX-RAG、PaperGraphBench，MADL 优先考察且本轮真实接入尚未完成；QACD 暂缓，LLaVA-Critic 不进入正式能力池和实验，既有探索及成本保留。MADL 的鉴伪／定位不继承 QACD 的回答风险语义。按功能相对独立、可激活和可评价选择 Unit，原库入口与拆分由平台分析器处理，不预设两两配对或组合有效。模块级评价与完整 Agent 任务评价分别记录，由真实对照检验调度和组合收益。[候选、教师模板、Benchmark 与奖励方案](docs/Harness候选与两层评价方案.md)统一维护详细安排。

当前训练仍为终局聚合奖励；逐 Unit 局部奖励及新增外部 Benchmark 桥尚未实现。视觉教师实际传图已有代码，真实评价仍 NOT_RUN。原四来源未组成自动接入后已运行的调度池；人工包装检索的历史运行只作工程探索，方案更新不代表新增实验结果。

个人账号、服务器地址与环境探查、部署实录、个人学习讲义和脱敏前原件统一保存在 Git 忽略的 `.local-private/`；工程文档使用变量、项目相对路径或明确的示例值。具体规则见 [AGENT.md](AGENT.md)。本地目录不会随 clone 分发；旧提交中的内容需要单独处理。
