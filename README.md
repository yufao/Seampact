# SeamPact

0.14.8：异构 Harness 自动接入、有限拆分与自适应调度的学术原型。本版补齐有限参数传递、资源来源与初始化检查、用途声明和人工入口选择，并简化分析缺口提示。已完成本地核验，尚未部署远端；支持范围、六来源回查与剩余缺口见[0.14.8 更新说明](docs/0.14.8_接入支持与分析反馈.md)。按需驻留、混合任务及自动资源观测沿用[0.14.0 机制](docs/0.14_按需驻留与混合调度.md)。服务器使用统一的[安装与更新入口](docs/服务器部署.md)，[镜像构建和依赖复用](docs/镜像构建与依赖复用.md)统一维护。

核心链路是 **地址 → 目录解析 → API 工具分析 → 源码检查与原生绑定 → Unit 能力池 → 场景事件与合法候选 → RL 选择透明干预 → 合法许可（functional/1 用 FIFO；joint/1 允许学习就绪派发） → 原 Harness 执行 → 实际结果反馈**。业务模型仍可申请其可见能力；没有可用 Unit 时仍可普通对话。

当前研究规格见[候选与两层评价](docs/Harness候选与两层评价方案.md)：以真实决策选择能力，分别检验拆分自由度、调度净收益和变化后的学习投入。共同能力卡与数值表示、PaperGraph 场景桥及视觉教师传图已有代码；合法细入口的自动导出、真实目标调用和研究收益须分别核实。接入必须由平台分析器处理原库；外部开发者不预写来源包装或切分答案，职责见[研究实验方案 0.0](docs/研究实验方案.md#00-接入预处理绑定拆分与调度的归因边界)。

当前[联合调度规格](docs/部署前建设与调度动作方案.md#52-功能派发与生命周期联合模式本轮建设目标)包含合法就绪派发、准备及水平扩缩容；当前版本默认固定功能路径开展资源比较。已有真实本地 Unit 的窗口集成核验；真实来源混合训练、Linux／GPU／K8S 性能对照尚未完成，不由本地软件检查推断资源收益。

## 启动

平台进程及默认平台镜像使用 Python 3.11；接入远程仓库还需 Git。Harness 可单独选择 Python 3.10、3.11、3.12 或 3.13：源码核对在所选目标解释器中执行，原依赖安装与真实调用在匹配的运行组镜像中执行。目标解释器通过 Docker 准备，需要平台进程能够调用 Docker 及其 daemon；普通平台启动与原有 3.11 本地路径不要求 Docker。版本选择不会放宽显式生命周期、无 frame 观察及有限源码规则；新语法尚无对应规则时继续显示 `MISSING`。操作和真实运行边界见 [0.10 异构运行环境](docs/0.10_异构运行环境.md)。

Linux，在仓库根目录执行：

```bash
PYTHONPATH=src python -B -m seampact serve --home var/prototype --port 8880
```

Windows PowerShell，在仓库根目录一条命令启动（优先使用已有 `.venv-agentdojo`，否则使用当前 `python`）：

```powershell
.\start.cmd
```

打开 http://127.0.0.1:8880，按 Ctrl+C 停止。无需创建或激活新的虚拟环境，也不依赖 `py` launcher。更换端口可用 `.\start.cmd --port 8881`；启动脚本自动设置源码路径，并使用仓库内的 `var/prototype` 保存状态。

Windows PowerShell 手动启动：

```powershell
$env:PYTHONPATH = 'src'
python -B -m seampact serve --home var/prototype --port 8880
```

打开 http://127.0.0.1:8880。配置两个模型角色，保存后直接发送消息。对话和分析模型均支持本地或远程的 HTTP／HTTPS OpenAI 兼容接口；无鉴权服务需明确选择“无鉴权”，分析模型还须支持工具调用。接口地址填基础路径，如本地 `/v1`；平台追加 `/chat/completions`。地址由平台后端访问，容器内的 `localhost` 指向平台容器自身。

接入 Harness 后，在配置中点击“分析”。分析器可访问整仓，按确认的 RuleSet 提出入口、原生构造／初始化、资源绑定及 W／H／R 边界。引擎核对实际源码和支持规则，结果进入能力池。`READY` 表示静态绑定准备完成，原生初始化在真正调用时发生；缺依赖、参数或资源的 Unit 保留为 `MISSING`，显示具体原因。

需要独立环境时，在来源的“运行环境”中查看原库证据、选择 Python 与依赖安装方式，再“保存并准备目标解释器”。已有完整候选可“按此环境重新核对已有候选”，不重复调用分析模型；新增入口或边界仍交给分析器。通过核对后，在“运行组与部署”生成、构建、发布并启动对应镜像。更换环境不会删除命名服务、权重登记或历史结果；旧能力会等待重新核对，不能沿用旧 `READY`。

“来源与分析”“能力池”“任务详情”可在独立页面查看，支持按来源筛选。列表实时更新时保留展开和滚动位置。来源卡片提供“摘除来源”：退出当前能力池、停止后续分析／调用，已进入执行的原调用可收尾；源码与分析历史保留。“重新接入”沿用已完成分析，建立新绑定，不重复调用分析模型。

“取消本次分析”停止平台等待和后续处理，保留来源及已有能力；已发送的服务端请求可能继续推理。“删除来源记录”取消相关分析并从列表和能力池移除来源，同时删除平台克隆到本地的仓库，以及登记在这些仓库路径下的权重。放在独立目录的权重、你填写的原本地目录、冻结快照和已有任务依据保留。运行中的调用或研究占用须先结束。分析详情可查看逐轮模型请求、工具和安装耗时；相同提交后的即时完整核验不重复执行，源码或配置改变时仍重新核验。

已有完整分析需要改进时，在“来源与分析”的当前记录创建独立修订：可沿用冻结源码修复，或重新读取本地目录／拉取 URL 的新版本。编辑候选和填写重点后保存、完整重检，再选择是否调用当前分析模型局部修复；模型结果先留在草稿，明确安装后才替换当前能力池。已有资源登记和研究结果保留，普通“分析”仍是原完整分析路径。操作及范围见[0.11 分析修订与源码更新](docs/0.11_分析修订与源码更新.md)。

有效文档、证据状态与历史分工统一见[文档导航](docs/README.md)。

## 当前实现范围

| 层 | 实际功能 |
|---|---|
| 前端 | 标准对话、模型与 Harness 配置、学习器／教师准则配置、研究运行与分项对照 |
| 分析器 | URL／目录接入，冻结环境声明及目标解释器源码工具，入口与构造事实，有限 B-CALL 原前缀／对象引用，W／H、R-INPLACE 与有限循环提取 |
| 调度器 | Double DQN、PPO、离散 SAC 共享候选评分；真实事件训练、参数热启动、冻结策略与条件重评；functional/1 下层 FIFO、joint/1 合法派发与生命周期；旧业务方案 Q 保留历史定位 |
| 模型适配 | 对话、分析、教师角色独立；文字准则与程序判据共用分项反馈，UNKNOWN 保留费用并排除不完整回报更新 |

方案中已有显式结果数据边和成功出口控制边：后项通过 `$result` 取得前项真实返回值，原生对象留在同一方案的本地 owner 内。引擎核对绑定与实际输入结构；业务语义兼容仍显示 `UNRESOLVED`。B-CALL 可执行受支持的原同步函数前缀，取得原工厂／构造器返回的真实对象；R-INPLACE 可保留外围分支、循环和异常结构，仅门控原调用位置。

0.8.0 已把能力池连接到运行组管理，API 可提出分组、引擎核对原对象／共享状态／控制依赖及远程条件。0.9.0 工作区补齐部署前建设：原生组宿主在一个进程保留整组原构造与 owner，组外端口按 `group-port/1` 编码；运行组契约逐项允许启动、预热、停止接单、排空停止和副本；平台经 docker／kubectl／kind 构建、启动并按实例路由，训练以功能调度模式冻结放置与资源控制，并记录实例级成本与反馈。原对象端口未覆盖的成员保留本地执行。该阶段的历史运行范围见[运行组与 K8S](docs/运行组与K8S部署.md)。

0.10.0 增加按原库证据选择 Python 3.10–3.13 的源码核对与运行组环境；基础镜像、原依赖清单及原项目安装目录进入实际构建及 worker 身份。0.13.0 将可独立安装的依赖提前，生成可复用依赖镜像，并使用 BuildKit 包缓存。已有单来源的目标解释器与运行组镜像真实构建记录；跨库实际缓存命中、GPU 原目标调用和 K8S 执行仍须单独验证。环境准备、镜像构建、能力静态核对和原目标执行分别记录，不能互相替代。

动态 SDK 接线、生成器和未覆盖的构造形式仍明确报缺失。joint/1 已有根调用并发准入代码，原生整组宿主保留原执行上下文；任意有状态组复制、跨入口驻留共享粒度及完整 EXPORT／COMPOSE 证明仍未完成。研究反馈使用实际任务／安全判据及实测成本；已有真实开发运行，尚无 RL 优于固定策略或跨来源泛化结论。操作与本机原始结果入口见[手动启动](docs/手动启动与演示.md)及[研究实验方案](docs/研究实验方案.md)。

MMCT、CRAG、NeMo、DiSP 已通过真实分析 API 完成整仓工具分析；运行事实与未满足条件见[0.7 规则兑现与实际运行](docs/archive/0.7_规则兑现与实际运行.md)。分析完成、可绑定与实际执行分别记录。

## 当前研究方案

当前主实验为 10–15 个独立来源、四类防护工作：提示注入、文档支持性、视觉答案校准、图像真实性。原专题优先，允许外部补充；AnesSuite 等任务宿主与评价库不凑防护来源数。统一协议见[第 15 节](../ccfa-workfiles/experiments/harness-paper-design/plan.md#15-多来源防护效果保持与资源调度主实验2026-10-28)，实际运行与具体缺项见[原生运行考察](../ccfa-workfiles/experiments/harness-paper-design/native-feasibility.md)。原生诊断不计自动接入，静态 READY 不计完整目标成功。QACD 暂缓，LLaVA-Critic 仍不进入当前正式池；旧探索保留原归因。

功能模式默认终局聚合奖励，可选 event_module/1 局部反馈默认权重 0；joint/1 在任务完成时结算质量并累计时间成本，尚不接收该局部反馈协议。新增外部 Benchmark 桥尚未全部实现。视觉教师实际传图已有代码，真实评价仍 NOT_RUN。本版 REX／PaperGraph 已完成一题真实接续核验，PaperGraph 为交互源码适配；随后 11 个手动运行中 3 个完成、8 个因核验连接失败中断，三学习器更新次数均为 0。它们与历史检索实验分开记录，不作为无辅助自动接入或调度增益的结论。

远端使用 `bash deploy.sh install` 首次部署、`bash deploy.sh update` 更新，部署目录由 `--root` 指定；无仓库时先上传单独的 `deploy.sh` 并提供 `--repo`。脚本默认以工具镜像启动平台，通过本机 Docker socket 准备解释器和管理运行组容器，数据保存在镜像外，经 SSH 转发访问网页。已有部署首次指定原容器，由脚本保留原挂载与网络；容器已删除但旧状态还在时，使用 `install --reuse-data --data-dir <旧数据目录>` 备份并恢复启动。完整前提、备份与清理范围见服务器部署指南。

`src/seampact/` 是四层核心实现；`deploy/` 包含平台容器和 K8S 模板，运行组工件按能力池实际结果导出。代码与可共享的工程文档由 Git 管理，仓库地址使用当前远端配置。生成运行包、模型、数据、密钥、下载的第三方仓库和 `var/` 状态保留本地，按需 SFTP。旧 0.5 文档分类归档于本地忽略的 `docs/历史草案/0.5/`。

个人账号、服务器地址与环境探查、部署实录、个人学习讲义和脱敏前原件统一保存在 Git 忽略的 `.local-private/`；工程文档使用变量、项目相对路径或明确的示例值。具体规则见 [AGENTS.md](AGENTS.md)。本地目录不会随 clone 分发；旧提交中的内容需要单独处理。
